## 💡 为什么需要 EpoMail？

在互联网基础设施已经全面拥抱云计算与无服务器（Serverless）架构的今天，**电子邮件系统（Email Infrastructure）** 却依然停留在二十年前的沉重旧时代。

传统的自建企业与个人邮件系统往往面临以下严峻困境：

1. **运维成本极其高昂**：
   为了搭建一套可用、防垃圾的邮件系统，运维工程师通常需要手工配置 Postfix（MTA）、Dovecot（MDA/IMAP）、SpamAssassin/Rspamd（垃圾过滤）、ClamAV（防病毒扫描）以及 OpenDKIM/OpenDMARC 等近十种复杂开源组件，配置文件动辄数千行，极易出错。
2. **云服务商 25 端口封锁与 IP 黑名单信誉黑洞**：
   绝大多数现代云服务商（如 AWS、Azure、GCP、DigitalOcean、Vultr）默认封禁入站/出站 25 端口，且分配的公共 IPv4 地址大多早已被垃圾邮件滥发者污染，进入国际 RBL（Spamhaus、Barracuda 等）黑名单，导致发出的合法邮件频繁直接掉入垃圾箱甚至被拒信。
3. **高昂的常驻资源与固定月租开销**：
   传统邮件系统必须 7×24 小时常驻运行至少 1 台 2C4G 以上的 VPS 虚机，面对偶发性的邮件收发流量，大部分时间资源利用率不足 1%，且存在单点故障风险。
4. **陈旧过时的客户端交互体验**：
   传统的开源 Webmail（如 Roundcube、SquirrelMail、Horde）多诞生于 Web 1.0 时代，UI 界面臃肿陈旧，对现代移动端浏览器、触控手势以及暗色模式（Dark Mode）极度不友好。

## 🌟 EpoMail 的设计哲学：边缘云原生重构

**EpoMail (EpoCanvas Mail)** 的设计理念非常明确：**用现代 Serverless 边缘云原生基础设施，彻底革新传统的邮件系统！**

我们依托 **Cloudflare 全球分布式边缘网络**，将传统庞大笨重的邮件单体服务彻底解构为轻量级、无状态、高弹性的边缘无服务器服务：

```
                    ┌────────────────────────────────────────────────────────┐
                    │               全球边缘网络 (Cloudflare Edge)            │
                    │                                                        │
[入站邮件] ─────────▶  Email Routing ────▶ Worker Handler ────▶ Cloudflare D1 │
(SMTP Inbound)      │  (DDoS/垃圾清洗)      (Hono API / 业务)   (关系型元数据)   │
                    │                           │                            │
                    │                           ├─────────────▶ Cloudflare R2 │
                    │                           │               (对象存储附件) │
                    │                           │                            │
                    │                           ├─────────────▶ Cloudflare KV │
                    │                           │               (会话与分析缓存)│
                    │                           │                            │
                    │                           └─────────────▶ Workers AI   │
                    │                                           (智能验证码识别)│
                    │                                                        │
[出站邮件] ◀────────  Resend / CF Email ◀── 业务调度逻辑                      │
(SMTP Outbound)     │  (高信誉独立发信池)                                      │
                    └────────────────────────────────────────────────────────┘
```

### 1. 零服务器维护 (Zero-Server Maintenance)
不需要购买任何独立的 VPS 服务器，不需要安装 Linux 邮件软件包，更不需要熬夜处理系统补丁。所有后端逻辑均运行在 Cloudflare Workers 边缘计算节点上，毫秒级冷启动，全球 300+ 边缘城市就近接入。

### 2. 免费额度友好，极度节省成本
得益于 Cloudflare 的免费配额与按量计费策略，中小型团队与极客个人在日常使用场景下，**几乎零成本**即可长期稳定运行属于自己的专属全功能邮件服务系统。

### 3. 多域名、多账号与多角色号池
只需一个 EpoMail 实例，即可同时绑定管理多个独立域名（如 `yourname.com`、`company.io`、`project.org`）。系统原生支持 6 级 RBAC 角色权限体系，轻松满足主站长、域管理员、普通用户、只读访客等多租户协同诉求。

### 4. 极致现代化阅读交互
前端基于最新的 **Vue 3 + Vite + Element Plus** 技术栈开发，不仅支持完整暗色模式自适应切换与桌面/平板/手机全分辨率响应式适配，还深度集成了 **ECharts 增长数据大屏** 与 **Workers AI 智能验证码自动提取** 引擎。

## 📊 EpoMail 与传统邮件系统深度对比

| 评测维度 | 传统自建邮件系统 (Postfix/Dovecot) | 商业托管企业邮箱 (Google Workspace/365) | **EpoMail (开源边缘云原生)** |
| :--- | :--- | :--- | :--- |
| **部署与上线门槛** | 极高（需精通 Linux、DNS、网络防伪协议） | 极低（直接按人头订阅付费） | **低（提供一键部署脚本与图形化初始化）** |
| **服务器硬件成本** | 固定支出（每月 $10 - $50+ VPS 租金） | 按人头订阅（每人每月 $6 - $18+） | **极低（依托 Cloudflare 免费配额，接近 0 元）** |
| **公网 IP 信誉** | 极差（容易遭受 IP 段黑名单连带污染） | 极好（依赖商业巨头公共白名单池） | **极好（出站通过专业白名单信誉池 Resend/CF）** |
| **扩展性与容灾** | 差（单节点部署，需自行搭建主从备份） | 极好（多机房冗余） | **极好（全球 300+ 节点分布式边缘，天然容灾）** |
| **数据主权与隐私** | 100% 自主控制（但需自行负责容灾备份） | 数据托管在商业公司，存在审查/扫描风险 | **100% 自主掌控（D1/R2 私有账户归属，无商业广告扫描）** |
| **多域名支持** | 支持，但配置虚拟域（Virtual Domains）极其繁琐 | 需额外升级昂贵的高级多域订阅 | **原生开箱即用（支持无限域名绑定与灵活号池）** |
| **现代化前端体验** | 陈旧落后（多为 10 年前的 Web 界面） | 现代化商业体验 | **现代化响应式 SPA（Vue 3、暗色模式、移动端完美适配）** |
| **二次开发与 API** | 困难（需解析复杂的 Unix 本地 Maildir 文件） | 昂贵的 API 配额与复杂的 OAuth 申请 | **极简现代（原生 RESTful JSON API + Webhooks）** |

## 🎯 谁适合使用 EpoMail？

- **独立开发者与极客**：拥有多个独立域名，希望拥有属于自己的专属极客邮箱，用于接收注册验证码、账单、技术订阅与通知。
- **初创团队与微型企业**：希望为团队成员配备统一域名的企业邮箱（如 `admin@mybrand.com`、`support@mybrand.com`），同时不希望承担商业邮箱高昂的人头月费。
- **开源项目与社区运营者**：需要统一管理社区发信通知、邮件转发至 Telegram 团队协作群，并进行系统化日志审计。
- **隐私保护主义者**：注重通信数据主权，拒绝商业公司对邮件内容的隐蔽扫描与大模型训练挖掘，要求数据全部存放在自己控制的云基础设施中。
