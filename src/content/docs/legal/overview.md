## ⚖️ 法律地位与架构定位声明

EpoMail (EpoCanvas Mail) 是一套**开源、去中心化、基于边缘云原生（Cloudflare Workers）架构的邮件服务系统软件**。

为了确保全球用户、独立站长、企业集成商以及监管机构准确理解 EpoMail 的法律定位，特此发布本法律地位声明。本声明旨在清晰厘清**软件代码作者/贡献者（“开发方”）**与**独立部署和运营该软件的自然人/企业（“站长/运营方”）**之间的法律权责边界。

## 🏛️ 1. 软件提供方与自托管运营方的权责分界

在开源与分布式云计算语境下，EpoMail 严格遵循**“技术中立”与“控制权属于拥有者”**的国际通行法理：

```
┌────────────────────────────────────────────────────────┐
│             EpoMail 核心法律权责分界模型                │
└────────────────────────────────────────────────────────┘
          │                                    │
          ▼                                    ▼
【软件作者 / 贡献者团队】             【自托管站长 / 独立运营方】
• 仅编写、维护和发布开源代码          • 拥有并控制独立的 Cloudflare 账户
• 不持有用户自建实例的任何控制权      • 自行承担服务器资源与数据存储
• 零知识 (Zero-Knowledge) 原则        • 独立制定该站点的用户协议与管理规则
• 无法读取、拦截、解密任何通信        • 承担该站点日常运营的一切法律合规责任
• 不提供任何公共中心化通信托管服务    • 独立负责垃圾邮件治理与反滥用监管
```

### 软件提供方的免责声明
- **零访问权限 (Zero-Access)**：EpoMail 的核心开发人员与贡献者**绝不**拥有用户自建实例的任何管理员凭证、数据库读写权限或发信密钥。
- **无数据回传**：EpoMail 软件中不存在任何收集用户通信私密数据、邮件正文、收件人列表或访问凭证的隐蔽后门或遥测追踪代码。
- **技术中立性**：软件作者仅按开源通用标准发布软件构件，无法预知亦无法控制第三方站长利用本软件处理何种邮件内容。

### 自托管站长的独立主体责任
- 任何个人或企业下载、编译、部署 EpoMail 并向最终用户提供邮件通信服务，该部署实例即构成一个**完全独立的法律主体服务**。
- 自托管站长对该实例内的用户管理、内容合规、反垃圾邮件政策（Anti-SPAM）、数据隐私合规（如 GDPR/CCPA）承担完全且独立的法律责任。

## 🌐 3. 适用场景与合规性指引

根据部署架构的不同，EpoMail 的法律权责适用如下准则：

### 场景 A：个人/团队内部私有自托管 (Private Deployment)
- **法律性质**：个人通信或企业内部私有工具；
- **合规重点**：确保发信域名配置了合法的 SPF、DKIM、DMARC 防伪记录，遵守相关云服务商（Cloudflare、Resend）的《可接受使用政策》(AUP)，严禁用于外发任何未经请求的商业营销邮件。

### 场景 B：向公众开放注册的在线 Webmail (Public SaaS Instance)
- **法律性质**：面向公众的互联网信息服务提供商；
- **合规重点**：
  1. 必须根据当地法律法规完成必要的互联网信息服务备案或许可（如适用）；
  2. 必须在网站底部公开披露完整的《服务条款》(Terms of Service) 与《隐私权政策》(Privacy Policy)；
  3. 建立完备的用户实名/手机号/TOTP 认证体系，严厉打击网络钓鱼、诈骗与垃圾邮件滥发；
  4. 设立滥用投诉举报与合规下线快速通道（如 `abuse@yourdomain.com`）。
