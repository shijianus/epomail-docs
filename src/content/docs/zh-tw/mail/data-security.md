## 1. 全鏈路資料生命週期與邊緣處理模型

本服務將個人資料與通訊流之生命週期嚴格劃分為「蒐集、處理、利用、傳輸、保存、銷毀」六大階段。各階段均在 Cloudflare 邊緣運算與全球 Anycast 網路上以無狀態方式流轉，杜絕持久化殘留與越權讀取。

![EpoCanvas Mail 資料生命週期：蒐集（註冊與收發信）→ 處理（邊緣節點解析與加密）→ 利用（提供服務與安全防護）→ 傳輸（受託處理者與當事人觸發之功能）→ 保存（D1/KV/R2）→ 銷毀（7 日例行清理與實體刪除），各階段對應告知事項與處理標準](/images/mail/data-flow.svg)

*圖 1：個人資料於本服務之全鏈路生命週期。系統在各個環節均落實最小必要原則與強加密隔離，具體法律性質參見[隱私權政策](/zh-tw/mail/privacy-policy/)第 5 節。*

### 1.1 最小化蒐集與零遙測承諾

系統在蒐集環節實施極其苛刻的資料最小化（Data Minimization）控制。除使用者主動註冊所必需的帳號識別（使用者名稱、郵箱別名）及登入憑據外，系統絕不蒐集通訊錄、裝置陀螺儀、剪貼簿或跨站行為資料。我們莊嚴承諾：**EpoCanvas Mail 無論在託管實例還是開源程式碼中，均實施絕對的「零行為遙測」（Zero Telemetry）**。系統不內嵌任何商業分析 SDK、廣告轉化追蹤器或第三方監控腳本，使用者的每一次收發信與閱讀行為僅在本地信箱內生效。

### 1.2 邊緣瞬時執行與記憶體隔離

當郵件抵達或使用者發起請求時，業務邏輯直接在離使用者最近的 Cloudflare Workers 邊緣節點（V8 Isolate 沙箱）中瞬時執行。V8 沙箱在奈秒級內建立並在處理完成後立即物理銷毀，處理期間的解密明文僅暫存於易失性記憶體中，絕不寫入任何宿主機實體磁碟。這種無狀態瞬時執行機制從底層物理架構上消除了傳統伺服器中因跨請求記憶體殘留、常駐程序洩漏或多租戶側通道攻擊導致的潛在風險。

### 1.3 密碼學銷毀與徹底遺忘機制

為保障當事人的「被遺忘權」（Right to be Forgotten），系統建立了嚴格的生命週期清理機制。使用者移入垃圾桶的郵件在保留 7 日防誤刪緩衝期後，由邊緣排程任務（Cron Trigger）執行不可逆的實體覆寫清理；當使用者的總儲存用量超過 90% 預警線時，系統亦會對已刪除郵件逕行實體擦除以保障信箱健康。在使用者主動註銷帳號時，系統不僅立即抹除 D1 關聯式資料庫與 KV 快取中的全部關聯記錄，更會在底層執行加密金鑰覆寫粉碎，確保資料在物理層面達成永久且不可逆的徹底滅失。

### 2.1 憑證脫敏與 PBKDF2 / WebAuthn 儲存基準

系統對待使用者身分憑證採取業界最高強度的單向密碼學防護。傳統的密碼認證絕不儲存任何明文或簡單 MD5/SHA 雜湊，而是採用 PBKDF2 演算法結合高強度隨機鹽（Salt）進行 100,000 次金鑰拉伸疊代，即使資料庫快照遭遇非授權洩漏，亦能有效抵抗彩虹表與 GPU 平行離線窮舉破解。對於雙步驟驗證（TOTP），其種子金鑰在存入 D1 前經由實例級主金鑰進行 AES-256-GCM 對稱加密；而通行金鑰（Passkey）基於非對稱公鑰密碼學體系，伺服器端僅儲存由用戶端安全硬體導出的公鑰憑證，私鑰永不出使用者安全晶片（Secure Enclave），徹底杜絕伺服器端憑據失竊導致的身分冒充。

### 2.2 儲存分層與自備物件儲存架構

在附件與大型二進位檔案處理上，系統設計了彈性的儲存解耦層。系統支援按優先順序智慧解析物件儲存通道：優先使用使用者或企業管理員自備的 S3 相容儲存貯體（BYO-Storage），次選 Cloudflare R2 邊緣原生貯體，在輕量情境下平滑回退至 Cloudflare KV。使用者自備儲存擁有完全獨立的讀寫憑證與網路原則，實現資料資產的絕對掌控。所有檔案在輸出時均被強制附加 `Content-Disposition: attachment` 與 `X-Content-Type-Options: nosniff` 安全回應標頭，阻斷瀏覽器對可疑附件的惡意內嵌解析與跨站執行。

### 3.1 邊緣網路與反濫用閘道

作為第一道防線，Cloudflare Anycast 邊緣網路吸收並清洗全方位的分散式阻斷服務（DDoS）攻擊，並強制執行全站 TLS 1.3 傳輸加密與 HSTS 預先載入，徹底杜絕傳輸層中間人竊聽與降級劫持。邊緣閘道內嵌嚴格的 SSRF 防禦過濾器，任何企圖透過 Webhook、外部圖片代理或郵件擷取存取私有區域網路 IP（RFC 1918）或雲端廠商內部元數據介面（如 169.254.169.254）的惡意請求均在接入層被實體攔截並阻斷。

### 3.2 強身分驗證與無密碼通行金鑰

認證層摒棄傳統郵件服務僅依賴弱密碼的脆弱模式，深度整合 FIDO2 / WebAuthn 標準。使用者的通行金鑰與特定網域進行密碼學綁定，有效抵禦基於假冒網域的中間人釣魚攻擊。對於依賴密碼認證的情境，系統實施嚴格的頻控階梯防護：同一 IP 或帳號遭遇連續失敗嘗試時觸發指數退避與 12 小時鎖定機制，並在後台比對已知環境指紋庫（記錄最近 15 處常用裝置與網路 ASN），在發現異常環境登入時主動向安全管道投遞分級安全預警。

### 3.3 靜態資料加密與金鑰隔離

在持久化儲存層面，系統全面採用工業級 AES-256-GCM 演算法進行靜態資料加密（Encryption at Rest）。每封郵件在寫入 D1 資料庫之前，內文均由特定加密金鑰衍生生成獨立密文及認證標籤（Authentication Tag），有效防禦資料庫檔案脫機洩漏或未授權磁碟快照分析。加密金鑰由執行階段環境變數安全注入，與資料庫實現實體隔離部署，確保即使底層儲存服務遭未授權讀取，攻擊者缺乏環境金鑰亦無法還原任何郵件有效負載。

### 3.4 用戶端沙箱與不可變存證

在最終的使用者呈現介面上，EpoCanvas Mail 實施了激進的用戶端沙箱隔離。所有來自外部寄件者的 HTML 複雜排版郵件，均經由 DOMPurify 白名單機制嚴格剝離 `<script>`、`<style>`、`<iframe>`、`<form>` 及全部內聯事件屬性，並在自封閉的 Shadow DOM 沙箱內完成渲染，杜絕郵件偽造父級 UI、竊取 Session Cookie 或發起 XSS 腳本跨站攻擊。此外，官方技術文件採用 SHA-256 密碼學指紋與 Git Commit 雙向存證體系，確保官方規格與程式碼實作具備公開可檢驗的不可變性。

:::caution[加密之範圍與技術限制]
本服務所提供之「全部／隱私／加密」模式，係指伺服器端靜態加密（Server-side Encryption at Rest）。金鑰由實例伺服器之執行階段安全環境變數與使用者身分上下文衍生。此機制旨在防範資料庫勒索、脫機備份遭竊取或儲存快照洩漏之系統級風險，而非傳統端對端加密（E2EE）；掌握伺服器實例底層執行權限與環境變數之營運者在理論技術上具備解密能力。若使用者間通訊涉及國家安全、高度機密或要求營運者亦完全無法查閱之絕對保密情境，當事人應自行使用 GPG / PGP 等用戶端公鑰密碼學工具於本地完成內文加解密後再行投遞。
:::

## 6. 安全事件應變程序與主管機關受檢

為積極應對突發的網路安全事件與資料安全漏洞，EpoCanvas Mail 建立了標準化的安全應變與通報機制，確保在最短時間內控制風險並向相關方公開透明說明：

### 6.1 72 小時應變阻斷與通報流程

營運團隊在獲悉任何可能導致使用者個人資料被竊取、竄改、毀損或洩漏的安全事件時，將啟動四步應變標準作業程序（SOP）：
1. **即時阻斷與威脅隔離**：在發現威脅的數分鐘內，在邊緣閘道層緊急阻斷惡意 IP、強制註銷涉事工作階段權杖（JWT），並在必要時輪替全站加密主金鑰與服務金鑰；
2. **數位鑑識與影響評估**：留存完整的邊緣存取稽核軌跡，分析事件波及的帳號範圍、洩漏欄位及潛在危害程度；
3. **72 小時法定通報**：若安全事件達到法定重大標準，營運者將於確認事故後 72 小時內，透過站內公告及官方系統郵件通知受影響的當事人，並依法向所在地主管監管機關進行正式通報；
4. **根因補強與程式碼演進**：查明漏洞根本原因後，立即在上游開源程式碼庫中合併修復修補程式，發布安全公告（Security Advisory），協助全球自建節點營運者同步修復。
