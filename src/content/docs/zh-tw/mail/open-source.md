## 1. 授權條款

本專案原始碼依 MIT 授權條款（MIT License）發布，任何人可免費取得並：

1. 使用、複製、修改、合併、發布、散布、再授權及銷售本軟體的副本；
2. 前提是在軟體的所有副本或主要部分中保留原版權聲明與本授權聲明；
3. 軟體按「現狀」提供，不附任何明示或默示的擔保，包括適售性、特定用途適用性與不侵權的擔保；
4. 作者或版權持有人不對因軟體或軟體的使用產生的任何索賠、損害或其他責任負責。

## 2. 授權之外

- MIT 授權條款不授予商標或品牌使用權：EpoCanvas、Epomail 的名稱、標識、Logo 與視覺資產不隨原始碼開放而授權使用；
- 不得陳述或暗示獲得上游專案的背書或合作關係；
- 派生發行應自行承擔命名與標識的合規，並自行維護其與上游程式碼的差異說明。

## 3. 自部署者的法律地位

- 自部署之時點起，部署者即成為其實例使用者的資料控制者，上游開源作者不接觸實例資料（責任界定見[隱私權與條款總覽](/zh-tw/mail/overview/)第 2 節）；
- 部署者應依其所在地適用法律，對其使用者履行告知、當事人權利響應、安全維護與國際傳輸等義務；
- 本站法律文件（隱私權政策、服務條款、可接受使用政策、資料處理與安全維護、第三方處理者清單）可作為部署者面向其使用者的範本，採用時應依其實際配置修訂，責任主體隨之轉為部署者；
- 部署者配置的第三方服務（Cloudflare、Resend、Backblaze、Turso 等）由部署者自行建立契約關係，該等服務之條款對部署者及其使用者適用，與託管實例的[第三方處理者清單](/zh-tw/mail/sub-processors/)相互獨立。

## 4. 部署的技術門檻與安全責任

部署者應完成密鑰注入與初始化引導（步驟見[部署指南](/zh-tw/mail/deployment/)），並對實例的存取控制、密鑰保管與後續更新負責；上游專案發布的安全修復不自動及於未更新的部署實例。

## 5. 貢獻與回饋

- 缺陷報告與功能建議經 GitHub 儲存庫的 Issue 提交，程式碼貢獻以 Pull Request 進行；
- 貢獻者應確認其為所提交內容的權利人；貢獻一經併入儲存庫，即按 MIT 授權條款隨原始碼散布；
- 安全漏洞請勿以公開 Issue 揭露，應經[總覽](/zh-tw/mail/overview/)第 5 節的聯絡窗口私下報告。
