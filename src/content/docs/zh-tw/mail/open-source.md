## 1. 授權條款

原始碼依隨附的 MIT License 授權，本節為摘要，應連同原授權全文閱讀。

1. 可使用、複製、修改、合併、發布、散布、再授權及銷售軟體副本；專案的非營利定位不撤回 MIT 允許的商業使用。
2. 軟體副本或主要部分須保留原版權及授權聲明。
3. 授權含按現狀提供及不作擔保的條文，在適用法律允許的範圍內發生效力。
4. 授權中的責任排除不凌駕強制法律，也不自動免除作者另行營運託管服務、實際處理資料或自行承諾所生的責任。

## 3. 自部署者的法律地位

- 角色依每項處理的目的與方式判斷。部署者通常就其決定的處理擔任控管者，也可能與他方共同控管或代表他方處理；自建不代表唯一排他控管者，個人使用者也不一律是控管者。
- 適用法律不僅是部署者所在地法律。應評估 GDPR 的設立或域外適用條件、通訊保密及不可排除的消費者保護；非營利不豁免這些義務，具體角色見[總覽](/zh-tw/mail/overview/)第 2 節。
- 可參考本站文件撰寫告知，但須核實營運者身分、聯絡方式、資料來源、功能、保存及傳輸。組織委託處理應先確認受理與另訂必要 DPA；複製文件或簽署標籤不能取代合法依據及實際措施。
- 第三方關係依實際服務與契約建立；部分提供者可能就特定活動是獨立控管者。不得將全部第三方條款一律強加使用者；提供者與傳輸安排應自行核對，託管實例的[第三方處理者清單](/zh-tw/mail/sub-processors/)不是通用保證。

## 4. 部署的技術門檻與安全責任

請依[部署指南](/zh-tw/mail/deployment/)配置金鑰、權限與更新，評估備份、刪除、事件應變及必要的安全措施。上游修補不會自動更新所有部署；不得把測試環境視為可任意使用真實資料的授權。

單純發布程式碼不附 SLA、全年無休支援、永久託管或合規認證。實際營運者仍須依風險與適用法律履行安全及權利處理義務；加密與存取控制不能保證無資料洩漏，具體限制見[資料處理與安全維護](/zh-tw/mail/data-security/)。

## 5. 貢獻與回饋

- 缺陷及功能建議可用 [GitHub Issues](https://github.com/shijianus/epomail/issues)，程式碼可用 Pull Request；沒有逐件採納或時限承諾。
- 貢獻者須有權按儲存庫適用授權提交內容，保留必要的第三方聲明；單純貢獻不使其成為實例營運者或控管者。
- 未公開漏洞及個人資料請經[總覽](/zh-tw/mail/overview/)第 5 節私下聯絡；善意回報與合法研究不因批評專案而失去保障。
