# 官方郵件規範與防竄改驗證機制

**生效日期：2026 年 10 月 1 日｜版本：5.5**

本文檔依[隱私權與條款總覽](/mail/overview/)與[資料處理與安全維護](/mail/data-security/)，詳細規範 EpoCanvas Mail 之官方郵件簽發體系、安全操作通知規格、邊緣發件人防偽、不可變快照投遞、客戶端沙箱隔離，以及文檔密碼學防竄改驗證機制。本文檔旨在明確何謂「真正權威的官方規格說明」，並提供使用者與主管機關可驗證之技術存證標準。

本站法律與技術文件以本服務開放原始碼實作為準，旨在建立透明、嚴謹之非商業社群通訊規範。

## 1. 官方發件人防偽與身份認證體系

為徹底杜絕網路釣魚與發件人偽造風險，本服務建立邊緣特權隔離通道，將官方系統通訊與一般使用者收發信嚴格分離：

1. **唯一官方發信地址鎖定**：本服務所有系統歡迎郵件、全域營運公告與安全操作提醒，唯一且排他地由官方認證地址 `announcement@epocanvas.com` 簽發；
2. **邊緣層冒充阻斷機制**：Cloudflare Workers 邊緣網關與入站路由實施硬編碼過濾，任何外部寄件者、未授權連線或非特權內部 API 企圖以 `announcement@epocanvas.com` 名義寄送郵件，將於網關層立即阻斷並拋出 403 拒絕存取；
3. **認證標籤與官方藍標 (`isOfficial: 1`)**：僅由系統特權管道生成之郵件，方由邊緣節點注入不可偽造之 `isOfficial = 1` 屬性，前端閱讀窗格自動渲染專屬藍色官方盾牌認證標章及橫幅提示；
4. **生命週期與清理原則**：引導性質之系統郵件標記為重要待辦並於 7 日後自動物理清理；涉及重大安全事件之通知信件則永久封存於資料庫，不受常規 TTL 覆蓋。

## 2. 安全操作通知郵件體系（16 類事件）

本服務將使用者與系統關鍵異動納入 4 級安全防護階梯（L1 至 L4），建立覆蓋 16 種安全事件的即時通知矩陣。信件排版嚴格遵循去 AI 味之極簡工程設計，整合內聯向量盾牌、雙向操作指引卡片（本人操作備查 vs 非本人操作緊急處置）與深色安全管理按鈕：

| 等級 | 事件代碼 | 觸發時機與安全情境 | 注入元數據與參數 | 星標加註 |
| --- | --- | --- | --- | --- |
| L1 | NEW_DEVICE_LOGIN | 首次檢測到未識別的新設備或瀏覽器登入 | 時間、IP、地點、設備名稱、瀏覽器 | 否 |
| L1 | NEW_LOCATION_LOGIN | 跨城市或跨國別之新地理位置登入 | 時間、IP、國家與城市、網路服務商 | 否 |
| L1 | NEW_NETWORK_LOGIN | 新網路自治域 (ASN) 或新 ISP 接入點登入 | 時間、IP、ASN 編號、網路供應商名稱 | 否 |
| L2 | PASSWORD_CHANGED | 帳號登入密碼已成功變更 | 時間、IP、地點、設備與瀏覽器 | 否 |
| L2 | PAT_CREATED | 產生新的個人存取權杖 (Personal Access Token) | 權杖名稱、存取權限範圍、有效天數 | 否 |
| L2 | PAT_REVOKED | 個人存取權杖已被手動吊銷或過期作廢 | 權杖名稱、吊銷時點、操作設備 | 否 |
| L2 | OAUTH_AUTHORIZED | 授權第三方應用程式存取信箱資料 (OAuth 2.0) | 應用程式名稱、授權範圍、用戶端識別碼 | 否 |
| L2 | OAUTH_REVOKED | 撤銷特定第三方應用程式之存取權限 | 應用程式名稱、撤銷時點、客戶端資訊 | 否 |
| L3 | TOTP_ENABLED | 成功啟用 TOTP (RFC 6238) 雙重驗證防護 | 時間、IP、產生時點、備用碼狀態 | 是 |
| L3 | TOTP_DISABLED | 停用雙重驗證（降級為僅密碼單一驗證） | 時間、IP、操作設備、安全警示指引 | 是 |
| L3 | PASSKEY_ADDED | 綁定新的通行金鑰 (FIDO2 / WebAuthn) | 通行金鑰名稱、認證器類型、綁定時點 | 是 |
| L3 | PASSKEY_REMOVED | 移除已登記之通行金鑰憑證 | 通行金鑰名稱、移除時點、操作設備 | 是 |
| L3 | AUTO_FORWARD_CHANGED | 配置或變更郵件自動轉發目的地 | 轉發目標郵箱、過濾條件、啟用狀態 | 是 |
| L3 | STORAGE_PURGED | 自訂物件儲存 (BYO Storage) 配置被重設或清空 | 重設時點、操作 IP、預設儲存回退狀態 | 是 |
| L4 | ACCOUNT_LOCKED | 連續登入失敗達到閾值觸發 12 小時防爆破鎖定 | 失敗次數、鎖定時長、封鎖 IP、解鎖指引 | 是 |
| L4 | ACCOUNT_DELETED | 帳號已申請註銷或實體資料排程清除 | 申請時點、關聯別名數、資料銷毀期限 | 是 |

為防範警報風暴對使用者造成疲勞，系統於 KV 中維護已知環境指紋庫（記錄最新 15 筆設備、地點與網路），並對同類事件實施 1 小時靜默去重視窗。

## 3. 郵件不可變投遞與客戶端沙箱防竄改

官方郵件之通訊實施不可變傳輸與客戶端安全沙箱隔離，確保任何中間環節均無法竄改信件內容：

1. **不可變快照投遞 (Immutable Delivery)**：系統郵件於發送時完成渲染並固化寫入資料庫，不隨收件人日後切換個人語言而動態重譯，維護法律通訊之客觀唯一性；
2. **預置翻譯對稱回退**：多語言翻譯引擎預先編譯官方範本之標準譯文，比對一致時直調預置翻譯，一旦正文遭修改即優雅降級至 AI 全文翻譯；
3. **客戶端 Shadow DOM 物理隔離**：前端採用自封閉開放 Shadow DOM 渲染郵件內容，外層樣式與全域腳本絕對無法穿透；
4. **DOMPurify 白名單過濾**：強制清除 `<script>`、`<style>`、`<iframe>`、`<object>`、`<embed>`、`<form>` 標籤及所有內聯腳本事件，杜絕 XSS 與客戶端介面偽造。

## 4. 官方文檔防竄改與完整性校驗體系

本服務之官方文檔（`epomail-docs`）採用開源密碼學哈希存證體系，任何使用者均可離線或線上驗真文檔之原始性：

| 防護維度 | 技術實作機制 | 驗真依據與標準 | 防範攻擊場景 |
| --- | --- | --- | --- |
| 確定性指紋清單 | `public/tamper-proof.json` | SHA-256 內容雜湊值與位元組大小 | 鏡像站點內容篡改、文檔偷樑換柱 |
| 版本溯源錨點 | Git Commit 樹狀物件 | Git Commit SHA 與作者 PGP 簽名 | 未經授權之靜默更新與歷史篡改 |
| 客戶端即時驗真 | Web Crypto API 記憶體計算 | `crypto.subtle.digest('SHA-256')` | 傳輸中介人竄改、CDN 快取污染 |
| 離線終端校驗 | OpenSSL / sha256sum 工具鏈 | 原始 Markdown 本地哈希比對 | 離線審計、主管機關法規遵從檢查 |
| 官方權威源站 | `https://docs.epocanvas.com/epomail` | DNSSEC 驗證與嚴格 TLS 憑證 | 偽冒官方站點、釣魚文檔欺詐 |

:::tip[線上驗真操作指引]
本站每個文檔頁面底端均內嵌「🛡️ 官方防竄改與完整性校驗」即時面板。使用者點擊「🔍 即時驗證本文完整性」按鈕，瀏覽器將於本地記憶體完成 SHA-256 計算，並與官方清單核對。使用者亦可於終端機執行 `curl -sSL https://docs.epocanvas.com/epomail/tamper-proof.json | jq .` 取得官方存證資訊。
:::

## 5. 責任邊界與安全事件通報

1. **託管實例責任**：官方託管站點 `mail.epocanvas.com` 之安全郵件簽發、發件人鑑權與文檔防竄改由官方營運團隊負責維護；
2. **自行部署實例**：獨立部署者應依開原始碼自行配置 Cloudflare 資源，並依[資料處理與安全維護](/mail/data-security/)妥善保護密鑰，防止其專屬實例遭未授權存取；
3. **通報與支援窗口**：若發現任何官方郵件偽造、防竄改校驗失效或潛在漏洞，請立即聯繫：
   - 官方安全中心與發信通道：`announcement@epocanvas.com`
   - 隱私與資料保護視窗：`privacy@epocanvas.com`
