**生效日期：2026 年 10 月 5 日｜版本：5.16**

EpoCanvas Mail 的檢索分為兩套：面向使用者的郵件搜尋（頂欄搜尋框）與面向管理員的全庫檢索（管理區「全部郵件」）；設定頁另有獨立的設定項檢索。本頁逐項列出全部可用算子、旗標與規則條件，均與目前實作一致。分類規則與搜尋共用同一欄位語義，規則引擎之說明見第 7 節起。

![EpoCanvas Mail 搜尋：輸入 from:github 後列表僅顯示命中郵件並加亮關鍵詞](/images/mail/ui/ui-search.png)

*圖：郵件搜尋。算子可與自由關鍵詞組合，命中處即時加亮。*

## 1. 語法總則

- 多個條件以空格分隔，彼此為「且」關係，全部滿足方命中；
- 取值含空格時以雙引號閉合，如 `subject:"年度報告"`；
- 無算子的裸關鍵詞在主題、寄件人暱稱、寄件地址、收件地址與正文五個欄位間「或」匹配；
- 預設不區分大小寫、模糊子字串匹配；精確度與大小寫行為可經旗標改變（第 3 節）。

```text
from:github subject:"驗證碼" after:2026-10-01 exact:true
```

## 2. 欄位算子

十個欄位算子作用於對應欄位，值為子字串匹配（時間與大小除外）：

| 算子 | 取值 | 語義 |
| --- | --- | --- |
| `from:<值>` | 文字 | 寄件人地址或寄件人暱稱包含該值；`from:me` 等價 `is:sent` |
| `to:<值>` | 文字 | 收件人地址或收件人暱稱包含該值 |
| `subject:<值>` | 文字 | 僅匹配主題 |
| `subject_or_body:<值>` | 文字 | 主題或正文包含該值 |
| `body:<值>` | 文字 | 僅匹配正文純文字 |
| `larger:<位元組>` | 整數 | 郵件體積（正文與內容總長）不小於該位元組數 |
| `smaller:<位元組>` | 整數 | 郵件體積不大於該位元組數 |
| `before:<日期>` | YYYY-MM-DD | 收受時間早於該日 |
| `after:<日期>` | YYYY-MM-DD | 收受時間晚於該日 |
| `label:<名稱>` | 標籤名 | 命中掛有該標籤的郵件；標籤名含非 ASCII 字元時建議加雙引號 |

## 3. 範圍與旗標

旗標改變檢索範圍或呈現行為，解析後自關鍵詞中剝離：

| 旗標 | 行為 |
| --- | --- |
| `global:` | 放大至所有信箱檢索，不受目前視圖限制 |
| `is:sent` | 強制包含已送出郵件 |
| `is:spam` | 查詢域切換為垃圾郵件 |
| `is:trash` | 查詢域切換為垃圾桶 |
| `is:draft` | 前端轉跳草稿匣（草稿僅存本機） |
| `hl:off` | 關閉命中詞高亮 |
| `exact:true` | 全詞邊界精確匹配，避免子字串誤命中 |
| `case:true` | 開啟大小寫敏感 |

## 4. 高亮與摘錄

命中詞於列表與詳情以高亮呈現；摘錄窗向命中處平移以保留上下文。`exact:true` 時僅全詞命中加亮，`case:true` 時區分大小寫，`hl:off` 關閉全部高亮。高亮為瀏覽器原生渲染，不改變郵件內容。

## 5. 管理端 `$` 檢索

管理區「全部郵件」分區提供以 `$` 引導的進階語法，面向管理員的全庫審查：

| Token | 語義 |
| --- | --- |
| `$sender` | 按寄件人暱稱或地址檢索 |
| `$user` | 按郵件所屬使用者帳號檢索 |
| `$to` | 按收件帳號檢索 |
| `$subject` | 按主題檢索 |
| `$received`／`$sent`／`$deleted`／`$norecipient`／`$all` | 狀態過濾：已接收、已送出、已刪除、無收件人、全部 |

Token 支援英文大小寫變體與中文別名（如 `$發件人`、`$使用者`、`$收件人`、`$主題`）；值本身含 `$` 時以 `\$` 轉義。於郵件列表右鍵任一郵件，可直接以其寄件人、收件帳號或所屬使用者發起檢索。加密模式（Level 3）下管理端郵件列表恆為空，本節語法隨之不可用，見[運行模式](/zh-tw/mail/modes/)第 2 節。

## 6. 設定頁檢索

搜尋框在設定頁自動切換為設定項檢索：

| 輸入 | 行為 |
| --- | --- |
| 無前綴 | 僅在目前設定面板內檢索並加亮命中項，平滑捲動定位，零請求 |
| `all:` 或 `global:` | 跨全部設定頁檢索，彈出按頁面分组的下拉，點擊即跳轉定位 |
| `app:`、`oauth:`、`client:` | 檢索第三方應用管理中的 OAuth 應用 |

聯想補全隨輸入提供，Tab 可補全算子。

## 7. 分類規則條件

標籤分區的規則建構器以「條件 + 例外」兩步定義規則：條件全部命中且例外無一命中時執行動作。可用條件如下：

| 條件 | 語義 |
| --- | --- |
| `from`（寄件人為） | 寄件人地址或暱稱精確匹配，支援逗號分隔多值 |
| `to`（收件人為） | 收件人精確匹配，支援多值 |
| `sender_address_includes`（寄件地址包含） | 按寄件網域或地址片段匹配 |
| `recipient_address_includes`（收件地址包含） | 按收件網域或地址片段匹配 |
| `email_received_for_others`（他人同收） | 該地址出現在其他收件人位 |
| `subject_include`（主題包含） | 主題關鍵詞，支援多值 |
| `message_body_includes`（正文包含） | 正文關鍵詞，支援多值 |
| `subject_or_body_include`（主題或正文包含） | 二者任一命中 |
| `system_setting`（系統判定） | 引用系統級判定（如白名單命中） |

:::note
建構器中另提供大小（`at_least`／`at_most`）、日期（`before`／`after`）與郵件頭（`message_header_includes`）條件；目前引擎版本尚未實裝其判定，選擇後該條件不會命中，列此以免誤配。
:::

## 8. 動作與優先級

- 規則命中即按規則定義為郵件掛上對應標籤；
- `priority` 數值決定規則執行順序，數值小者優先；
- `stopProcessing` 開啟後，該規則命中即截斷後續規則；
- 規則於收信時自動執行，亦可於標籤頁手動執行。

## 9. 系統內建啟發式與站點治理

- 出廠預置社群、訂閱、推銷、工作四個標籤；其中訂閱與推銷由內建啟發式維護：無回覆前綴的寄件人、郵件行銷平台網域與退訂訊號歸入訂閱；折扣、限時等主題詞與行銷詞密度歸入推銷；
- 站點級治理由管理區「分類管理」配置：寄件人黑白名單、主題與內容關鍵詞、白名單模式、空寄件人攔截、非收件人攔截與可執行附件攔截；名單命中自動掛上對應標籤，硬攔截直接拒收並計數；
- 規則與名單的行為細節見[功能指南](/zh-tw/mail/features/)第 4 節。
