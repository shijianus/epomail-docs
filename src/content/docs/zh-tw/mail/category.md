**生效日期：2026 年 10 月 6 日｜版本：5.17**

分類管理是管理區的站點級治理介面（`#manage/admin/rules`，權限鍵 `setting:query`），在使用者個人規則之上疊加全站收信治理。個人標籤規則見[標籤與分類管理](/zh-tw/mail/labels/)；條件欄位語義見[搜尋與規則參考](/zh-tw/mail/search/)第 7 節。

<summary>圖解：分類管理——站點收信治理的四層防線</summary>

分類管理頁的四張治理卡：從收發總閘到 AI 識別再到名單與硬攔截，站點級收信治理的四層防線。

1. **郵件設定卡（收發開關）**：收信、寄信與自動重新整理的總開關，及無收件人郵件的處理開關；關閉收信後入站郵件直接拒收。
2. **AI 模型與 API 金鑰整合卡**：Workers AI 驗證碼提取及其規則、AI API Key／URL／模型配置——與系統設定 AI Hub 同源，此處控制的是入站識別行為（驗證碼徽標等）。
3. **基礎名單規則卡**：寄件人黑名單（可配置為標籤模式或直接攔截）、白名單模式（僅白名單內寄件人可送達）、主旨與內容關鍵詞黑名單、空寄件人攔截、非收件人攔截與可執行附件攔截。
4. **硬攔截規則卡**：直接拒收並累計攔截計數的終局手段；名單命中自動掛上對應標籤，攔截效果可回分析頁複核。

## 1. 收發與重新整理開關

收信功能、寄信功能與自動重新整理的總開關，以及無收件人郵件的處理開關；關閉收信後入站郵件直接拒收。

## 2. AI 識別

Workers AI 驗證碼提取及其規則配置、AI API Key／URL／模型——與[系統設定](/zh-tw/mail/system/)的 AI Hub 同源，此處控制的是入站識別行為（驗證碼徽標等）。

## 3. 名單與攔截

| 機制 | 說明 |
| --- | --- |
| 寄件人黑名單 | 命中即攔截，可配置為標籤模式或直接攔截 |
| 白名單模式 | 僅白名單內寄件人可送達，其餘按策略處理 |
| 硬攔截寄件人 | 直接拒收並累計攔截計數 |
| 主題與內容關鍵詞 | 命中黑名單關鍵詞的郵件攔截 |
| 空寄件人攔截 | 無寄件人名的郵件拒收 |
| 非收件人攔截 | 收件人不含本實例地址的郵件拒收 |
| 可執行附件攔截 | 攜帶可執行附件的郵件拒收 |

## 4. 與使用者側的分層

站點級名單由管理員維護、作用於全實例；使用者側規則僅作用於本人信箱，兩者命中均會自動掛上對應標籤。名單與關鍵詞的行為細節見[搜尋與規則參考](/zh-tw/mail/search/)第 9 節，濫用處置見[可接受使用政策](/zh-tw/mail/acceptable-use/)。

<details>
<summary>圖解：站點級治理的操作步驟</summary>

1. 進入管理區「分類管理」（需 `setting:query` 權限）。
2. 配置收信／寄信功能開關與自動重新整理、無收件人處理。
3. 配置 Workers AI 驗證碼識別及其 API 參數。
4. 按需啟用：寄件人黑名單、白名單模式、硬攔截寄件人、主題與內容關鍵詞、空寄件人攔截、非收件人攔截、可執行附件攔截。
5. 名單命中自動掛標，硬攔截直接拒收並累計攔截計數；攔截效果可回分析頁複核。

</details>
