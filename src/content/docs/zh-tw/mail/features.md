寫信彈層的四個標註分區，涵蓋一封信從排版到寄出的完整路徑：工具列決定樣式，收件人與主旨決定去向，寄送按鈕落地投遞。

- **格式化文字編輯**：段落、字號、粗體斜體底線刪除線、顏色、對齊、有序與無序清單、引用、分隔線、連結、圖片、表格、表情、翻譯與原始碼模式；
- **附件**：附件收發能力依帳號角色開啟；單一附件大小上限依實例設定（預設 25 MB，僅約束使用營運者公共儲存之使用者，自備儲存者不受限）；儲存配額依角色設定；
- **寄送範圍**：站內信箱直投（不產生對外傳輸）；寄往站外之郵件經營運者配置之通道（Resend／Mailjet 等）投遞，涉及之第三方見[第三方處理者清單](/zh-tw/mail/sub-processors/)；
- **寄送管理**：已傳送檢視可查；對外寄送量受帳號角色之每日寄信配額約束（見第 6 節）。

## 3. 搜尋語法

![EpoCanvas Mail 搜尋欄輸入 from:github 後的結果檢視：清單僅顯示命中之 GitHub 通知郵件，側欄計數保持同步](/images/mail/zh-tw/ui/search-guide.png)

*圖：搜尋。欄位算子可與自由關鍵字組合，命中清單即時更新。*

<details>
<summary>圖解：檢索——一次搜尋的兩個關鍵位置</summary>

搜尋的兩個標註分區示範一次完整檢索：在檢索框輸入算子或關鍵詞，命中清單即時篩選並加亮關鍵詞。

1. **頂欄檢索框**：郵件頁搜郵件、設定頁搜設定項；支援 `from:`／`to:`／`subject:`／`body:` 等十個欄位算子與 `is:`／`global:` 旗標，多個條件以空格相連為「且」關係，Tab 可補全算子。
2. **命中清單**：僅顯示滿足全部條件的郵件，命中詞以瀏覽器原生高亮標出（`hl:off` 可關閉）；點擊列進入詳情，摘錄窗自動平移到命中處以保留上下文。

</details>

| 算子 | 示例 | 說明 |
| --- | --- | --- |
| `from:` | `from:github` | 按寄件人過濾 |
| `to:` | `to:boss` | 按收件人過濾 |
| `subject:` | `subject:驗證碼` | 按主旨過濾 |
| `body:` / `subject_or_body:` | `body:發票` | 按內文／主旨或內文過濾 |
| `larger:` / `smaller:` | `larger:10M` | 按郵件體積過濾 |
| `before:` / `after:` | `after:2026-10-01` | 按日期過濾 |
| `label:` | `label:工作` | 按標籤過濾 |
| `global:` | `global:專案` | 跨信箱全站檢索 |
| `is:` | `is:sent`、`is:spam`、`is:trash` | 按狀態過濾 |

搜尋命中基於 CSS Highlights API 高亮；全站檢索與頁內尋找兩級並存。全部欄位算子、旗標與規則條件的完整參考見[搜尋與規則參考](/zh-tw/mail/search/)。

## 4. 標籤與分類規則引擎

- 預設預置四個標籤：**社群**（按常見公共信箱網域自動歸類）、**訂閱**、**推銷**、**工作**；標籤顏色與圖示可自訂；
- 規則條件可組合（寄件人地址包含、主旨關鍵字、系統設定等），支援例外與優先順序；收件時自動套用標籤，亦可手動進行；
- 全域治理工具：寄件人黑名單、主旨與內容關鍵字黑名單、白名單模式、空寄件人名攔截、非收件人攔截、可執行附件攔截與硬攔截拒收計數；
- 標籤統計（總數、未讀）於側欄即時呈現，分類結果可於分析頁複核。

## 5. 驗證碼自動提取

![EpoCanvas Mail 郵件詳情：Cloudflare 驗證碼郵件中的 6 位驗證碼以大字號呈現，清單與詳情均帶綠色驗證碼徽標](/images/mail/ui/ui-detail-verification.png)

*圖：僅在下列全域、實例告知與使用者選擇條件均滿足時，自動提取才可將完整主旨及最多 6,000 個 JavaScript 字元的正文傳至 Workers AI；主旨不計入正文上限。處理依據見[隱私權政策](/zh-tw/mail/privacy-policy/)第 6 節。*

<details>
<summary>圖解：驗證碼提取在詳情頁的呈現</summary>

郵件詳情中的驗證碼提取效果：6 位驗證碼以大字號呈現，列表與詳情均帶綠色徽標。

- **驗證碼大字區**：Workers AI 從主旨與正文前 6,000 字元中提取的驗證碼，直接以大字號呈現便於抄寫。
- **綠色徽標**：清單列與詳情頁同步出現的綠色標記，含義是「此郵件含已提取的驗證碼」，讓您不必逐封開啟即可從清單直接辨認。徽標只在提取成功時出現；未命中或已關閉驗證碼提取時不顯示，因此它的缺失不代表安全，只代表沒有可抄的碼。
- **邊界**：全域 `aiCode`、實例 `contentProcessing.verificationCodeEnabled`、有效 `noticeUrl` 與使用者 `privacyPreferences.aiVerificationCode === true` 須同時滿足才會發起自動提取；使用者偏好預設 `false`，可在資料設定關閉以停止後續請求。此選擇不代替完整告知、處理依據或供應者契約，見隱私權政策第 6 節。

</details>

## 6. 垃圾郵件治理

- 隔離與保存：每日排程按郵件建立時間判斷垃圾保存天數，預設 7 日後轉垃圾桶；垃圾桶也按建立時間比較固定 7 日門檻，可能同輪實體刪除，不是額外保留 7 日。檢舉垃圾／非垃圾按具體流程更新個人信任名單；
- 對外寄送限制：每日寄信配額按角色設定（一般使用者 5 封、LV.0 8 封、LV.1 10 封、管理員 100 封，站長不設上限），計數每日重置；配額濫用之處置見[可接受使用政策](/zh-tw/mail/acceptable-use/)第 6 節；
- 收費與行銷內容之傳輸責任歸寄件人；未經請求之大量商業郵件為禁止行為（見[可接受使用政策](/zh-tw/mail/acceptable-use/)第 3 節）。

## 7. 轉寄與推送

- **個人轉寄**：可將信箱郵件自動轉寄至其他地址，支援副本（CC）；`rules` 目前不提供，遇到該模式不轉寄，`alias` 清單為空也不傳送。`keepCopy` 固定為 `true` 保留原件，介面不可關閉；儲存啟用的 `rules` 或啟用轉寄且 `keepCopy: false` 會遭拒絕，須前後端配套升級；
- **全域轉寄**：管理員可配置系統級轉寄規則，受郵件模式約束（加密模式下關閉）；
- **Telegram 推送**：個人 `all` 通知全部郵件，`important` 按精確「重要」／`important` 標籤、實際星標或已有驗證碼篩選。`notifyCodeOnly` 是附已有驗證碼複製按鈕的單獨選擇，預設 `false`，不是郵件篩選或新提取；`includePreview` 預設 `false`，控制摘要與閱讀按鈕。相容 `privacy` 僅發通用通知，無主旨、寄件人、收件人、驗證碼、摘要或連結；其他個人模式也不附寄件人／收件人，系統通知獨立使用系統欄位。所有傳送路徑即使關閉預覽也核對即時使用者、信箱、郵件狀態與 D1 撤銷版本；閱讀／附件存取同樣檢查。停改個人通知或資料設定可撤舊連結，未來通知獨立，舊未限定用途／OSS v1 權杖須更新，聊天副本不能收回。須前後端配套升級，不證明線上已部署；見[通知與轉寄指南](/zh-tw/mail/notify/)；

## 8. AI 能力

| 能力 | 觸發方式 | 說明 |
| --- | --- | --- |
| 驗證碼提取 | 僅在第 5 節全部條件滿足後自動處理新信；使用者預設關閉 | Workers AI 邊緣推論，可在資料設定停止後續提取 |
| 全文翻譯 | 開啟列或換語言不傳送；每次外部翻譯須明確確認 | 全域 AI、`contentProcessing.translationEnabled` 與有效告知 URL 須啟用；請求帶有 `confirmed: true` 及與目前配置完全一致的 `noticeUrl`。缺少條件則停用；符合的官方預置譯文僅本機顯示。MyMemory／Google 公共備援及缺漏片段呼叫已從 `ai-service` 移除；`contentProcessing.publicTranslationFallbackEnabled` 恆為 `false`，儲存 `true` 遭拒，管理選項標為不可用。目前接收者見[第三方處理者清單](/zh-tw/mail/sub-processors/) |
| 圖片文字識別 | 已確認翻譯，且伺服器 `contentProcessing.ocrEnabled === true`、本次明確 `enableOcr: true` | 否則為 `false`，可僅翻譯文字，不沿用舊 OCR 偏好；可處理內嵌圖片或遠端圖片 URL，裝飾圖篩選仍為啟發式 |
| AI Hub | 管理員配置 | 接入 OpenAI 相容等多模型端點，0-Token 測速，模型按角色授權 |

營運者不自行將郵件作為模型訓練資料集；第三方的保存、訓練與再利用須依實際契約及設定確認。須同意的處理應可自由撤回且同樣容易；缺少可執行的選擇時須停用相應處理，不能僅以介面按鈕保證已符合（見[隱私權政策](/zh-tw/mail/privacy-policy/)第 6、9 節）。

## 9. 開放平台與資料自主

- **OAuth 2.0 / OIDC 認證中心**：可授權應用程式及撤銷授權；實際回傳可能包括信箱、名稱、頭像與角色欄位，未必按請求 scope 精簡。撤銷不收回已交付資料、已簽發的 ID token 或第三方工作階段，詳見第三方處理者清單；
- **接入指南**：管理端註冊應用、端點與整合程式碼詳見[開放平台與 API 接入](/zh-tw/mail/api/)；
- **資料匯出**：設定頁匯出部分個人資料、未標記刪除郵件的選定欄位及 `customLabels`，不含附件檔案、完整聯絡人、規則、安全設定或稽核資料；後端未套用時間範圍。匯出不含暫存的原始 MIME，單封 .eml 仍由現有欄位重建。原始郵件暫存採用 7 日應用層期限，重試可續期，成功不立即刪除；排程分批清理失敗可殘留，並非保證 TTL。D1 接收 claim 僅存中繼資料，不含原始正文。公開個人頁的三項統計隱藏設定也約束 API；已刪除或停用使用者回傳 404，但不會自動實體刪除靜態頭像。新註銷流程為停用帳號、撤銷存取並標記 `manual_review`，不是完整刪除。詳見[資料匯出與儲存](/zh-tw/mail/data/)；

## 10. 介面與行動裝置

- 六種介面語言（簡體中文、繁體中文、English、Français、Español、Nederlands），前後端字典六語言完全對稱；
- 明暗雙主題、300+ 離線向量圖示、響應式版面與 PWA 安裝；另提供 Android 行動應用程式（epomail）。Vue 已移除 Google Fonts 外連並使用系統字型，React 字型自託管；頭像、Turnstile 與其他外部資源仍可能發起請求，不能概括為零外部請求。

- **清單**：寄件人、主旨、摘要與驗證碼徽標的位置、字級與配色與中文版逐項一致——在地化只替換詞條，不改版式，因此截圖與操作指引可跨語言重用。日期、數字與計數同樣依介面語言格式化。
- **切換方式**：介面語言的切換點：一般設定的「語言」區六選一（簡體中文、繁體中文、English、Español、Français、Nederlands），改後即刻生效、無需重新登入。投遞與顯示分開——系統通知與歡迎郵件依每位收件人自己的語言設定產生，不隨寄件人的介面語言走。

</details>

375 寬度下的行動裝置收件匣：側欄收合為抽屜，清單保持完整可讀。

- **抽屜式側欄**：視窗寬度低於 1025 像素時，左欄自動收合為抽屜：點漢堡按鈕以遮罩形式喚出，選中任一檢視後自動收起，不遮擋閱讀區。桌面端與行動裝置共用同一套側欄結構，因此計數與標籤在兩種形態下完全一致。

- **清單**：與桌面端共用同一份虛擬捲動清單：長清單只渲染視窗內的可見列，首屏開啟速度不隨郵件總量成長。觸控目標依行動裝置可及性放大，但資訊密度與欄位構成與桌面一致，因此行動裝置截圖同樣可用於核對欄位。
