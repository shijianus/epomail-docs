**生效日期：2026 年 10 月 5 日｜版本：5.17**

EpoCanvas Mail 的設定分為兩個區域：側欄「設定」區為每個帳號可自行調整的個人設定，含個資、一般、安全、資料與標籤五個分區；「管理」區僅對具備管理權限的身分分組顯示，承載實例級配置。本頁逐區說明各項設定的作用與相互關係。多重帳號、郵件模式與登入方式等運行層面的行為見[運行模式](/zh-tw/mail/modes/)。

## 1. 個人設定分區

| 分區 | 內容 |
| --- | --- |
| 個資 | 頭像、暱稱、性別、生日等基本資料與聯絡資訊 |
| 一般 | 個人簡介、外觀色調、主題桌布、閱讀偏好、介面語言與翻譯目標語言 |
| 安全 | 使用者名稱與密碼、兩步驗證中心、註銷帳號 |
| 資料 | 資料匯出、通知與轉寄、儲存空間與個人雲端儲存 |
| 標籤 | 自訂標籤與分類規則管理 |

## 2. 個資：個人資料

![EpoCanvas Mail 個資頁：基本資訊卡含頭像上傳、個人暱稱、性別與生日；聯絡資訊卡顯示帶主信箱標記的電子郵件與新增電子信箱按鈕、電話號碼；下方為住家、公司與其他地址卡（介面為簡體中文）](/images/mail/zh-tw/ui/preferences-guide.png)

*圖：個資頁。主信箱帶「主信箱」標記，額外電子信箱可新增多個並隨時移除。*

<details>
<summary>圖解：個資頁——個人資料被拆成的四個維度</summary>

個資頁的四張卡片：從身分形象到聯絡方式再到地址簿，個人資料的四個維度分卡管理。

1. **基本資訊卡**：頭像上傳、個人暱稱、性別與生日；暱稱與頭像是否對外顯示，受管理員「公開個人主頁」開關約束。
2. **聯絡資訊卡**：登入主信箱帶「主信箱」標記且不可移除；可新增多個額外電子信箱並隨時移除，另可登記含區碼的電話號碼。
3. **地址卡**：住家、公司與其他三組地址分別儲存，各自獨立增刪與編輯。它們是純粹的個資留存欄位：不參與郵件投遞、不影響計費與身分分組；是否需要填寫、以及是否對外顯示，取決於營運者是否開啟「公開個人主頁」。
4. **關聯設定與安全卡**：個資頁通往其他設定頁的跳板：帳號安全（使用者名稱與密碼、兩步驗證）與第三方授權（已授權應用程式）兩處最常用的入口集中在此，避免在個資頁與安全頁之間反覆翻找；點擊即跳至對應分區，而非另開新頁。

</details>

基本資訊卡管理頭像、暱稱、性別與生日；聯絡資訊卡列出登入主信箱與自行新增的額外電子信箱，另可登記含國碼的電話號碼；地址卡分別保存住家、公司與其他地址。資料的公開範圍受管理員「公開個人主頁」開關約束。

## 3. 一般：外觀與語言

![EpoCanvas Mail 一般頁：個人簡介文字框，個性裝扮區提供暗色調、亮色調與跟隨系統三種外觀色調，全域主題桌布提供八種預設與自訂桌布，下方繼續個人背景等設定（介面為簡體中文）](/images/mail/zh-tw/ui/general-guide.png)

*圖：一般頁的外觀色調與主題桌布選擇，目前為跟隨系統與預設純淨桌布。*

<details>
<summary>圖解：常規頁——外觀與閱讀習慣的三張卡</summary>

一般頁的三張卡片：個人簡介、個性裝扮與偏好設定，涵蓋介面外觀與閱讀習慣的全部個人化。

1. **個人簡介卡**：一段展示於公開個人主頁的簡介文字；公開主頁是否開放由管理員「公開個人主頁」開關決定。
2. **個性裝扮卡**：外觀色調三態（暗色／亮色／跟隨系統，頂欄可快捷切換）與全域主題桌布（八種預設 + 自訂桌布或 URL）；另有個人背景（僅覆蓋信箱區）與介面密度。
3. **偏好卡**：閱讀偏好（收件匣類型、閱讀窗格位置、會話群組檢視）與語言（介面語言六選一、AI 翻譯目標語言 16 選一）；資料隱私區集中個人資訊與 AI 處理偏好入口。

</details>

- 外觀：暗色、亮色、跟隨系統三種色調；全域主題桌布預設八種，支援自訂桌布；另可單獨設定個人背景與介面密度；
- 閱讀偏好：收件匣類型、閱讀窗格位置與會話群組開關；
- 語言：系統語言六選一；翻譯目標語言獨立設定，共 16 種，決定 AI 全文翻譯的目標語言；圖片文字辨識翻譯可單獨關閉；
- 資料隱私區集中於個人資訊與 AI 處理偏好入口。

## 4. 安全：密碼與兩步驗證

安全頁可修改使用者名稱與密碼（顯示上次變更時間）。兩步驗證中心提供總開關與三種第二驗證方式的獨立配置：驗證器應用程式（TOTP）、備用復原碼（10 組一次性代碼）與通行金鑰（Passkey）。兩步驗證的登入行為與信任裝置規則見[運行模式](/zh-tw/mail/modes/)第 4 節。頁面底部提供註銷帳號入口，註銷後帳號資料依[隱私權政策](/zh-tw/mail/privacy-policy/)的刪除條款處理。

## 5. 資料：匯出、通知與儲存

![EpoCanvas Mail 資料頁：使用者資料與資料匯出卡含全量資料 JSON、郵件歷史歸檔（MBOX、JSON、CSV 與時間範圍）與通訊錄配置三類匯出；下方儲存空間卡顯示附件儲存用量儀表與個人物件儲存接入入口（介面為簡體中文）](/images/mail/zh-tw/ui/data-guide.png)

*圖：資料頁。資料匯出與儲存管理同頁呈現，附件儲存用量依身分分組配額計算。*

<details>
<summary>圖解：資料頁——個人資料自主的四個分區</summary>

資料頁的四張卡片：資料帶走的三種格式、一個轉寄區、一個儲存區與一個第三方授權區，個人資料自主的完整介面。

1. **使用者資料與資料匯出卡**：三類匯出並列：全量 JSON 備份、郵件歷史歸檔（MBOX／JSON／CSV + 時間範圍）與通訊錄配置；單封郵件另可在閱讀頁下載 .eml。
2. **郵件與訊息轉寄卡**：Telegram 訊息推送與自動轉寄的逐項配置；兩項功能是否對帳號開放由管理員「使用者資料控制」開關決定。
3. **儲存空間卡**：附件儲存用量儀表即時對照配額；可接入自備 Backblaze B2／S3 儲存桶，接入後新附件直存個人雲端、不受實例配額約束，解除接入即回落。
4. **第三方應用和服務卡**：使用者名下全部 OAuth 授權的應用清單：逐應用移除存取權限，或經詳情彈窗一鍵撤銷全部；撤銷即時生效，應用現有權杖立即失效。

</details>

| 匯出項 | 格式 | 範圍 |
| --- | --- | --- |
| 匯出全量資料 | JSON | 完整備份：帳號個資、歷史郵件、通訊錄、分類與標籤規則及安全設定 |
| 郵件歷史歸檔 | MBOX（通用）、JSON 或 CSV | 僅收發郵件，可限定時間範圍 |
| 通訊錄與配置 | JSON | 聯絡人名錄、自訂別名規則與系統個人化偏好 |

單封郵件可於閱讀頁直接下載為 .eml。「郵件與訊息轉寄」區提供 Telegram 訊息推送與自動轉寄：綁定私有機器人、推送偏好與觸發類型的逐步說明見[通知與轉寄指南](/zh-tw/mail/notify/)；兩項功能是否對使用者開放由管理員的「使用者資料控制」開關決定。儲存區顯示附件儲存用量儀表，並可接入個人物件儲存（Backblaze B2 或 S3 自備儲存桶），接入後附件直接保存於個人雲端，不受實例配額約束。

## 6. 標籤管理

標籤分區管理自訂標籤的顏色與圖示，並配置分類規則的條件、例外與優先級；出廠預置社群、訂閱、推銷與工作四個標籤。規則引擎的行為與搜尋語法見[功能指南](/zh-tw/mail/features/)第 3、4 節。

## 7. 管理控制台

管理區依身分分組的權限逐項顯示，介面路徑與身分分組綁定以防越權存取。九個管理分區如下：

| 分區 | 職責 |
| --- | --- |
| 分析頁 | 郵件量、分類與標籤的統計儀表板 |
| 使用者清單 | 帳號查詢、重設密碼、調整身分分組、重設兩步驗證、封禁與復原、清空使用者郵件 |
| 垃圾郵件／全部郵件 | 全站郵件審查分區；名稱與範圍隨郵件模式變化（Level 1 顯示全部郵件，Level 2 顯示垃圾郵件分區，Level 3 隱藏入口） |
| 權限控制 | 六種身分分組的配額與權限模板、預設分組與 AI 模型授權；參觀者與站長分組受保護不可刪除 |
| 註冊密鑰 | 邀請註冊碼的簽發與查驗 |
| 系統設定 | 實例級配置，見下方配置卡清單 |
| 應用管理 | OAuth 2.0／OIDC 第三方應用程式的接入憑證簽發與管理 |
| 分類管理 | 收信與寄信功能開關、AI 識別配置、黑白名單與硬攔截規則 |
| 操作報告 | 四類預警的研判、處置與申訴裁決 |

系統設定頁以配置卡組織實例級配置：

| 配置卡 | 內容 |
| --- | --- |
| 網站設定 | 開放註冊、公開個人主頁、郵件模式、兩步驗證、隱藏登入網域、註冊碼、新增信箱、多帳號快速切換、信箱前綴規則 |
| 個性化設定 | 網站標題、彈窗提示與動態／靜態介面 |
| 第三方認證與單一登入 | 第三方快捷登入總開關與各 Provider 密鑰配置（經特性開關控制顯示） |
| 儲存與核心資料庫 | 物件儲存（B2／S3，預設回退 R2／KV）、核心與第三方資料庫架構、單一附件上限與級聯刪除、KV 快取體檢 |
| 郵件推送 | Telegram 機器人、全域轉寄與規則轉寄（加密模式下鎖定關閉） |
| AI 智慧引擎與大模型接入 | AI 提供者（自訂 OpenAI 相容端點或 Cloudflare Workers AI）、啟用開關、每日配額與速率限制、模型授權 |
| 使用者資料控制 | 使用者的 Telegram 推送、郵件轉寄、API 與自備儲存開關及預設儲存配額 |
| Turnstile 人機驗證 | 人機驗證的站點密鑰與開關 |
| 網站公告 | 公告彈窗、公告郵件群發與歡迎郵件模板（多語言） |
| 操作報告 | 預警觸發的營運閾值 |
| 關於 | 版本資訊與更新檢查 |

操作報告頁以預警工單呈現全站風險事件，每條記錄帶類別、優先級、狀態與完整環境資訊（IP、地理、裝置與指紋）：

| 預警類別 | 觸發情形 | 常見處置 |
| --- | --- | --- |
| 稽核警告 | 被其他使用者檢舉或違規檢舉成立 | 核驗後研判放行或執行管控 |
| 風控警告 | 觸碰安全紅線或異常登入環境（如多地多 IP 併發登入） | 重點關注、約談或封禁 |
| 封禁警告 | 帳號已被系統自動封禁或管理員手動封禁 | 解除預警或維持 |
| 申訴警告 | 使用者就處置結果提交申訴 | 研判放行或駁回 |

![EpoCanvas Mail 操作報告頁：表格列出申訴警告、封禁警告、稽核警告與風控警告四類預警工單，各帶優先級、狀態標籤、活躍環境池資訊與研判放行、解除預警等處置按鈕（介面為簡體中文）](/images/mail/zh-tw/ui/audit-guide.png)

*圖：操作報告。四類預警統一清單研判，處置按鈕按預警類別分流；加密模式下記錄時間戳記被剝離。*

<details>
<summary>圖解：操作報告——一條預警工單的完整資訊鏈</summary>

操作報告頁的四欄表格：一條預警工單從「誰」到「為何觸發」再到「證據何在」的完整資訊鏈。

1. **使用者信箱欄**：這張工單所指的帳號：可能是被處置對象（風控／封鎖預警）、被檢舉方（稽核預警）或申訴人（申訴警告）。本頁只做研判，真正的處置動作——封鎖、復原、重設——在使用者清單頁執行，因此研判結論需與那一頁搭配使用。
2. **安全稽核等級欄**：風險分級（P0／P1 優先級與類別標籤）：稽核／風控／封禁／申訴四類預警各有常見處置分流。
3. **預警說明與觸發特徵欄**：該工單的觸發情形描述（如多地多 IP 併發登入、檢舉成立），是研判放行或駁回的判斷依據。
4. **活躍環境池欄**：純文字展示的完整環境資訊：IP、地理、裝置與指紋；加密模式（Level 3）下時間戳記被剝離，工單仍可研判。

</details>
