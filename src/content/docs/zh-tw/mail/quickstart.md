本頁給出兩條上路徑的最短操作序列：路徑 A 於託管實例註冊即用，從註冊到寄出第一封信約十分鐘；路徑 B 將整套服務部署於自己的網域與 Cloudflare 帳號，從複製倉庫到收發核驗約三十分鐘。兩條路徑運行同一套程式碼、使用同一套介面；本頁只列動作與結果，功能語義與設定細節經連結進入對應專頁，全部內容以開源實作為準。

## 1. 選擇路徑

| | 路徑 A：託管實例 | 路徑 B：自行部署 |
| --- | --- | --- |
| 適合 | 先試用產品，不自備基礎設施 | 已有網域與 Cloudflare 帳號，要資料完全自主 |
| 前置 | 一個瀏覽器 | 網域、Cloudflare 帳號、Node.js 與 pnpm；站外寄信另需投遞通道帳號 |
| 耗時 | 約 10 分鐘 | 約 30 分鐘 |
| 費用 | 目前不設付費功能 | 部署者自有 Cloudflare 用量 |
| 入口 | [mail.epocanvas.com](https://mail.epocanvas.com) | [部署指南](/zh-tw/mail/deployment/) |

## 2. 路徑 A：託管實例

1. **註冊帳號**：開啟 [mail.epocanvas.com](https://mail.epocanvas.com)，在登入頁切換到註冊表單，以「地址前綴 @ 實例網域」與密碼（6–30 位）提交。註冊是否需要註冊碼、是否附帶人機校驗由實例設定決定；需要註冊碼時向營運者索取，或經 `?code=` 參數直達註冊表單。註冊即時生效，無需郵件驗證。
2. **核對身分分組**：註冊後進入實例設定的預設分組；使用註冊碼註冊時，進入該碼綁定的分組。分組決定每日寄信配額、信箱數、儲存配額與附件權限，出廠播種值見[運行模式](/zh-tw/mail/modes/)第 3 節。
3. **收第一封信**：註冊成功後系統自動投遞歡迎郵件，登入即見。再用任一外部信箱向您的新地址寄一封含驗證碼的測試信：驗證碼經 Workers AI 自動擷取，以大字號與綠色徽標呈現於列表與詳情（見[功能指南](/zh-tw/mail/features/)第 5 節）。
4. **寄第一封信**：點側欄「寫信」彈出寫信層。收件人為站內地址時直投秒達；站外地址經營運者設定的投遞通道寄送。出站量受每日寄信配額約束，計數每日重置。
5. **開啟自動整理**：出廠預置社群、訂閱、推銷、工作四個標籤，並按啟發式自動歸類新郵件；自建規則、例外與優先級見[標籤與分類管理](/zh-tw/mail/labels/)。
6. **開啟兩步驟驗證**：於「設定 → 安全」三步綁定驗證器應用程式（TOTP），完成即顯示 10 組一次性復原碼，請離線留存；步驟見[帳號安全設定指南](/zh-tw/mail/security/)。
7. **綁定 Telegram 推送**（可選）：以自備機器人即時接收新郵件推送，附 7 日有效的站內閱讀連結；步驟見[通知與轉寄指南](/zh-tw/mail/notify/)。
8. **匯出備份**（可選）：於「設定 → 資料」一鍵匯出 JSON 完整副本；回收站郵件 7 日實體刪除，需留存的信件請先匯出（見[資料匯出與儲存](/zh-tw/mail/data/)）。

## 3. 路徑 B：自行部署

1. **核對前置條件**：一個網域、一個 Cloudflare 帳號、Node.js 與 pnpm 環境；站外寄信需 Resend 或 Mailjet 等投遞通道帳號。完整清單見[部署指南](/zh-tw/mail/deployment/)第 1 節。
2. **三步部署**：於終端依序執行（部署目標與自訂網域於 `wrangler.toml` 設定）：

```bash
git clone https://github.com/shijianus/epomail.git
cd epomail/mail-vue && pnpm install && npm run build
cd ../mail-worker && npx wrangler deploy
```

3. **初始化**：首次部署後存取 `/api/init/<jwt_secret>`，完成全部資料表建立、六個標準身分分組播種與主站長帳號初始化；引導鏈冪等，可安全重複。
4. **注入密鑰**：生產環境經 `npx wrangler secret put` 注入 `jwt_secret` 與 `totp_enc_key`；本地開發使用 `.dev.vars`（不入庫）。初始化路徑中的密鑰值須與工作階段簽署密鑰一致。
5. **接通收件**：於 Cloudflare 面板啟用網域 Email Routing，將目標地址路由至 Worker，入站郵件即收即解析。
6. **接通寄件**：於系統設定設定投遞通道；未設定前，站內信箱之間仍可直投。
7. **收發核驗**：註冊一個測試帳號並確認收到歡迎郵件；以測試帳號與主站長帳號站內互寄一封信；設定投遞通道後再外寄一封站外信件並確認送達。四項全部通過即部署完成。
8. **確認法律地位**：自部署之時點起，部署者即為其使用者的資料控制者，應向其使用者履行告知與安全維護義務；本站法律文件可作為基礎範本（見[開源與自行部署法律](/zh-tw/mail/open-source/)）。
