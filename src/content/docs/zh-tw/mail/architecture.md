本頁說明 EpoCanvas Mail 的技術實作：部署拓撲、資料加密、儲存鏈路、權限模型與郵件生命週期。全部技術事實以開源程式碼之實際實作為準，可自行審計核對；對個人之隱私影響與法定告知見[資料處理與安全維護](/zh-tw/mail/data-security/)與[隱私權政策](/zh-tw/mail/privacy-policy/)。

本站法律文件以繁體中文（臺灣）版本為正式版本，其餘語言版本為對照譯本，文義有疑義時以正式版本為準。

## 1. 部署拓撲

| 元件 | 實作 |
| --- | --- |
| 運算 | Cloudflare Workers（V8 Isolate 沙箱）處理請求；伺服器可在處理時取得明文，原始碼不能保證請求結束即銷毀沙箱或抹除全部明文 |
| 入站 | Cloudflare Email Routing 接收郵件，postal-mime 解析正文、標頭與附件 |
| 出站 | 三通道依序解析：Cloudflare Email Workers 綁定、Resend API、Mailjet；站內互發直接寫入資料庫 |
| 結構化儲存 | Cloudflare D1：支援使用者庫與郵件庫分離，亦可回落單庫；使用者庫承載帳號、角色與設定，郵件庫承載郵件、星標與附件中繼資料；線上實際繫結須另行核驗 |
| 鍵值儲存 | Workers KV：會話權杖、登入風控計數、TOTP 中間態、使用者資料與物件儲存兜底 |
| 邊緣推論 | Workers AI（驗證碼提取等，預設 llama-3.1-8b-instruct） |
| 定時任務 | 儲存庫設定為每日 UTC 16:00（臺灣時間次日 00:00）清空驗證計數、重置寄信計數、清理垃圾與未綁定 OAuth 身分、更新分析快取；每 5 分鐘處理通知與物件刪除佇列。程式另有 30 分鐘分支，但該設定未註冊它 |
| 人機驗證 | Cloudflare Turnstile（HTTP API 校驗，註冊與新增信箱） |

## 3. 資料加密體系

- **三模式靜態加密**：全部模式不加密郵件欄位；隱私模式依垃圾、回收站及無主狀態選擇加密；加密模式對選定欄位加密。欄位範圍為 `subject/content/text/code`，並非全部資料；見[資料處理與安全維護](/zh-tw/mail/data-security/)；
- **郵件加密**：AES-256-GCM 使用隨機 12 位元組初始化向量，HKDF-SHA256 按使用者衍生密鑰；來源依序為 `email_enc_key`、`totp_enc_key`、`jwt_secret`，全部缺失則報錯，不回落內建預設密鑰；
- **憑證保護**：新密碼預設以 PBKDF2-HMAC-SHA256 210,000 次迭代及隨機鹽雜湊，迭代數可設定，舊雜湊在登入時升級；已啟用 TOTP 密鑰以 AES-256-GCM 加密，復原碼同時保存 SHA-256 雜湊與加密原碼副本，通行金鑰保存公鑰及憑證資料。臨時認證資料與其他憑證的保存例外見[資料處理與安全維護](/zh-tw/mail/data-security/)；
- **邊界**：以上為伺服器端靜態加密，非端對端加密；附件不在加密範圍內。

## 4. 附件儲存鏈

附件二進位依序解析儲存：使用者自備 S3 → 營運者設定的 S3 → Cloudflare R2 → 缺省 KV。中繼資料存於 D1；下載使用簽署連結與防禦性標頭。實體刪除郵件時先清除附件索引並登記物件刪除佇列，再檢查剩餘引用；失敗重試達到 10 次後停止，不能保證全部物件同步刪除。外部副本見[第三方處理者清單](/zh-tw/mail/sub-processors/)。

## 5. 會話與角色權限

JWT（HS256）預設有效期為 30 天；KV 保存會話允許清單及移除部分敏感欄位的使用者快照。程式在加入新會話前判斷數量大於 10，通常可保留 11 個，並非嚴格 10 個上限；KV 期限可因活動續寫或部分操作縮短。登出移除目前會話，註銷刪除該帳號會話記錄；權限採用 RBAC，播種六個標準角色：

| 角色 | 每日發信 | 儲存配額 | 附件 | 附加能力 |
| --- | --- | --- | --- | --- |
| 參觀者 | 禁止 | 0 | 否 | 唯讀沙箱 |
| 普通使用者 | 5 封 | 5 MB | 否 | 基礎收發 |
| 普通使用者 LV.0 | 8 封 | 10 MB | 否 | 部落格等級連動升級 |
| 普通使用者 LV.1 | 10 封 | 25 MB | 是 | 基礎收發與附件 |
| 管理員 | 100 封 | 500 MB | 是 | 使用者管理、全郵件管理（受郵件模式約束） |
| 站長 | 不限 | 1024 MB | 是 | 全部權限 |

受保護路由核驗 JWT、KV 會話及相應角色權限；部分公開端點另有驗證流程。註銷刪除一般會話記錄，不等於同步清除全部授權、資料或第三方副本。

## 6. 郵件生命週期

| 環節 | 行為 |
| --- | --- |
| 刪除 | 一般刪除標記 `is_del=1`；每日任務依 `email.create_time` 超過 7 天清理垃圾桶，不是移入後再保留 7 天；明確要求徹底刪除或配額條件可直接觸發實體刪除 |
| 垃圾隔離 | `spamRetentionDays` 預設 7 天，依郵件建立時間轉入垃圾桶；隨後同輪可能滿足垃圾桶實體刪除條件 |
| 配額清理 | 使用者執行刪除時，現有容量用量嚴格超過配額 90%，所選郵件直接實體刪除；沒有達到 90% 即背景自動清倉的任務 |
| 官方郵件 | 讀取郵件列表時，依 `welcomeExpireDays`（預設 7 天）及建立時間將指定官方寄件地址的過期郵件標刪；後續實體清理另由垃圾桶任務處理 |
| 級聯刪除 | 一般郵件徹底刪除與垃圾桶清理會清理附件索引和星標，並登記物件刪除重試；不同管理員批次路徑的涵蓋範圍不完全相同 |
| 帳號註銷 | 僅標記使用者資料列為已刪除並移除會話；信箱、郵件及個人資料不會一併標刪，沒有註銷後 90 天自動實體刪除任務，見[隱私權政策](/zh-tw/mail/privacy-policy/) |

## 7. 應用安全設計

- **防越權路由**：郵件 URL 一律使用 HMAC-SHA256 簽名的 20 位隨機 Hash，綁定使用者與租戶，不暴露自增 ID，杜絕枚舉與 BOLA／IDOR；
- **XSS 三重防禦**：DOMPurify 允許清單消毒、body style 注入過濾、附件輸出 MIME 允許清單加嚴格 CSP 與 `nosniff`；
- **SSRF 阻斷**：出站請求經公共位址校驗，回環、RFC 1918 與雲中繼資料位址一律拒絕；
- **登入防護**：失敗計數以輸入的登入識別為鍵，達到 5 次拒絕登入，每次失敗寫入 12 小時 TTL；不是所有別名共享的原子帳號鎖。另有 Turnstile 與 TOTP／Passkey 驗證；
- **官方郵件完整性**：官方發信身分鎖定、不可變快照投遞與文件防竄改校驗，見[防竄改與官方規範](/zh-tw/mail/tamper-proof/)。

## 8. 可觀測與品質保障

- 儲存庫啟用 Cloudflare observability；應用另在 D1／KV 保存身分操作、檢舉、裁決及登入環境資料。多數稽核記錄無自動到期任務；平臺日誌實際保存期須核驗，見[隱私權政策](/zh-tw/mail/privacy-policy/)；
- 自動化測試、稽核與巡檢腳本逾百個：Playwright 全真棧瀏覽器迴歸、公網端對端斷言、全倉靜態掃描與六語言 i18n 三件套（詳見[專案介紹](/zh-tw/mail/project/)第 7 節）。
