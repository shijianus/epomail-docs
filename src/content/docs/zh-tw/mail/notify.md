本頁逐步說明「設定 → 資料」頁「郵件與訊息轉寄」區的兩項能力：Telegram 訊息推送與自動轉寄。兩項功能是否對帳號開放由管理員「使用者資料控制」卡決定；關閉時對應區塊不顯示。資料匯出與儲存亦在同一頁，見[設定指南](/zh-tw/mail/settings/)第 5 節。

1. **資料 JSON 匯出卡**：下載部分帳號欄位、未標記刪除的郵件欄位及自訂標籤；不含附件檔案、完整安全設定或所有個人資料。
2. **郵件歷史歸檔卡**：瀏覽器將同一後端回應轉換為 MBOX、JSON 或 CSV；後端不套用所選時間範圍，也不包含完整原始 MIME 或附件檔案。
3. **通訊錄與配置卡**：匯出傳回的個人欄位子集與自訂標籤；不能作為完整通訊錄、別名規則或全部偏好的備份。
4. **郵件與訊息轉寄標題區**：Telegram 通知與自動轉寄的入口；個人通知可選全部或重要郵件，預覽與驗證碼複製另行選用。閱讀及附件連結每次存取仍須核對目前狀態與撤銷版本，具體欄位與轉寄限制見下文。

## 1. Telegram 訊息推送

推送使用您自備的私有 Telegram 機器人，新郵件即時直達您的會話：

1. 向 @BotFather 申請一個私有機器人，取得 Bot Token（形如 `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`）；
2. 取得您與該機器人的 Chat ID（向機器人發送任意訊息後經 getUpdates 查詢，群組為負數、頻道形如 `-100123456789`）；
3. 在「Telegram 訊息推送」項點設定，填入 Bot Token 與 Chat ID；在群組話題內接收時可另填 Topic ID；
4. 個人通知選擇 `all`（全部）或 `important`（重要）。重要郵件僅依精確標籤 `重要`／`important`、實際星標或已有驗證碼判定，不依主旨含字判斷；`notifyCodeOnly` 預設 `false`，僅控制附加驗證碼快速複製按鈕；只有已有且不超過 256 字元的提取驗證碼才會新增按鈕，不是「只推送含驗證碼郵件」篩選；
5. 點「發送測試訊息」核對目標對話，再確認所傳欄位與閱讀連結後開啟推播。

個人通知的 `includePreview` 預設 `false`；在 `all`／`important` 模式中，即使關閉預覽，通知仍採用郵件主旨（無主旨時為通用標題，最多 200 字元）；明確設為 `true` 才另外附摘要（最多 400 字元）及配置可用時的閱讀連結。`privacy` 模式無論其他選項為何僅使用通用標題，不含主旨、寄件人、收件人、驗證碼或連結。系統通知依管理員設定的系統欄位獨立處理，不由個人預覽開關代為關閉。機器人 Token 與 Chat ID 會交給實例後端，不只留在裝置上。自動 AI 驗證碼辨識另須個人選用且服務已設定，預設關閉，與通知篩選及驗證碼複製選項不同。

本輪本機實作對 Telegram 郵件閱讀及附件請求逐次核對連結有效期、所屬使用者、信箱、郵件狀態及撤銷版本；個人預覽已關閉亦會阻擋舊連結存取，分享頁不載入遠端內容。個人通知停用或相關設定改變會撤銷舊連結；「設定 → 資料」的「撤銷現有閱讀連結」可撤銷本帳號全部既有個人及系統通知連結，未來通知仍可獨立產生新連結。一般登出不會撤銷這些連結，帳號停用後的存取則被狀態核驗阻擋。撤銷不刪除 Telegram 聊天中已有的正文或下載副本。這些機制不證明所有線上部署已更新，所涉第三方見[第三方處理者清單](/zh-tw/mail/sub-processors/)。

## 2. 自動轉寄

| 配置項 | 說明 |
| --- | --- |
| 啟用自動轉寄 | 總開關；開啟後出現下方配置 |
| 轉寄目的地信箱 | 一個或多個目標地址，多個以英文逗號分隔 |
| 觸發類型 | 全部郵件，或按收件信箱字面前綴比對，例如 `billing`；`*` 不代表萬用字元，別名前綴清單為空時不轉寄 |
| 主題標頭 | 可選在轉寄郵件主題新增 `[Fwd]` 標頭，便於在目標信箱中識別 |

:::note
個人「智慧規則過濾轉寄」（`rules`）目前不可用：執行時不轉寄，不退回全轉；儲存啟用的 `rules` 設定會被拒絕。保存的 `keepCopy` 會規範化為 `true`；僅在轉寄啟用時提交 `keepCopy=false` 會被拒絕，停用的設定也會寫入 `true`。轉寄不自動刪除原件。以上為目前本機原始碼行為，實際測試仍在複驗，不代表線上部署已完成。
:::

## 3. 投遞路徑與防回圈

轉寄優先經平台原生通道，失敗時可改經系統投遞通道並按設定新增 `[Fwd]`；該備援呼叫僅帶主旨及正文等欄位，不帶一般附件，不能保證目標取得完整原郵件。與收件人或原寄件人相同的目標會略過；這不是消除全部多跳回圈的保證。前置系統規則也可能直接結束入站流程，略過個人推播及轉寄。規則語意見[搜尋與規則參考](/zh-tw/mail/search/)第 7 節。
