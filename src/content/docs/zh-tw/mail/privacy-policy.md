## 4. 儲存與存取的實際範圍

### 4.1 帳號與安全資料

新寫入的密碼驗證採用加鹽 PBKDF2-HMAC-SHA256，預設 210,000 次迭代且可配置；歷史 SHA-256 或較低參數記錄可在驗證時升級，不能保證所有存量已完成遷移。TOTP 密鑰加密保存；復原碼有驗證用雜湊，另保存以密鑰加密、可於重新驗證後顯示的原碼副本；通行金鑰保存公開憑證資料。停用 TOTP 時，如仍有有效通行金鑰，帳號仍維持多因素驗證啟用。這些措施降低風險，並非保證密碼永不可被猜解。TOTP 設定流程會將加密後的設定密鑰寫入 D1 的 `auth_security_operation`，有效期為 300 秒。多因素登入待完成流程也保存在該 D1 資料表；其 payload 不含輸入密碼，完成第二步時只更新 payload，不會延長原有截止時間。到期只會阻止流程繼續使用，不等於紀錄已實體刪除；排程清理仍可能稍後處理。個人欄位、登入來源、操作紀錄與權限設定亦可能存於實例資料庫或 KV。

### 4.2 郵件與附件

郵件資料主要由 Cloudflare D1 與配置的物件儲存處理；附件按使用者或營運者配置使用 S3 相容儲存、R2 或 KV。目前原始碼另將完整原始 MIME 以伺服器密鑰作 AES-256-GCM 加密後保存至所屬使用者選定的物件儲存；D1 claim 記錄雜湊、收件人、Message-ID、使用者、原文物件鍵及到期時間。應用設定 7 日到期，重試可續期，COMPLETE 不立即刪除；排程每次分批最多 100 筆，先刪物件再刪 claim，失敗保留待重試。這不是儲存 TTL、附件刪除佇列或 7 日內必然清除保證。伺服器密鑰加密不是端對端加密，實際實例仍須升級及配置；原始 MIME 不在自助匯出內，單封 .eml 不等於該原始檔。外部備份及實際儲存地區須另核實。

服務不提供端對端加密。「加密」與「隱私」模式依程式及設定對部分正文、主旨作伺服器端靜態加密；附件與路由中繼資料不自動納入該保護，掌握伺服器及密鑰者在技術上可能解密。在隱私模式中，將原受保護的郵件移入垃圾桶，會將主旨、正文及提取的驗證碼解密保存，並可能進入管理可見範圍；復原後再按該模式加密。移入垃圾桶不是對營運者進一步保密的方法，加密模式也不自動阻止個人配置的通知或轉寄。

### 4.3 瀏覽器、日誌與外部請求

瀏覽器可在 localStorage 保存多帳號工作階段權杖登記表（`epo_sessions`）、語言、介面偏好及目前開啟郵件的完整物件；各分頁目前身分／登出標記存於 sessionStorage。撰寫郵件時的最近收件人紀錄另以使用者 ID 或電子郵件為鍵，存於 localStorage 的 `epomail_recipient_records:*`，一般登出不會刪除這些紀錄。本機草稿與其附件物件另存於以主信箱命名的 IndexedDB，未見應用層加密；伺服器匯出不包含這些本機資料。

一般登出撤銷目前工作階段並清除目前郵件、目前帳號的收件人記憶體快取及該帳號工作階段，但不會刪除以使用者 ID 或電子郵件為鍵、存於 localStorage 的 `epomail_recipient_records:*`；本機草稿與其他帳號亦予保留。資料設定另提供須明確確認的裝置清除，範圍包括本站全部本機帳號、草稿、附件、收件人紀錄、可信狀態與快取；清除被阻擋或失敗時回報結果，不應視為已清完。刪除草稿時，其紀錄與附件在同一 IndexedDB 交易中聯刪。這些機制須實例升級；裝置清除不等於伺服器全量刪除，一般登出也不撤銷全部閱讀連結。

登入安全機制亦處理 IP 衍生的國家／城市、網路 ASN 及裝置資訊。已知環境清單最多保留最近 15 筆並使用 180 日滑動 TTL，持續使用可能使期限續延；IP 多帳號關聯項目使用 7,200 秒 TTL。可信裝置憑證可保存 60 日，前 30 日可能用於免除部分多因素驗證。這些與帳號欄位或稽核日誌的保存並非同一週期。

Cookie 規則也可能適用於 localStorage 等終端儲存。維持您要求的登入、必要驗證與安全機制，僅在符合所在地法律的嚴格必要例外時免事先同意；任何非必要追蹤或終端存取須另行評估，不能以「未使用 Cookie」免除要求。

升級後的 HTML 閱讀預設阻擋遠端圖片、遠端 CSS 與主動內容；一般閱讀可在提示後僅為目前郵件允許圖片，寄件方仍可能收到 IP、User-Agent、時間及開啟紀錄，此選擇不是圖片代理。列印維持預設阻擋，Telegram 分享閱讀不允許遠端資源。Google Fonts 外連已從程式移除；Turnstile、外部頭像等配置資源仍可能產生第三方請求。實際效果須核對實例升級與配置，完整資料流見[第三方處理者清單](/zh-tw/mail/sub-processors/)。

### 4.4 管理與除錯存取

管理介面依郵件模式、角色及權限限制可見範圍；這不是營運者在技術上絕對不能接觸資料的保證。人工存取限處理具體支援、安全事故、濫用檢舉、合法請求或其他有依據且必要的事項，採最小權限並保留適當紀錄。禁止以學習、測試或好奇為由隨意閱讀真實郵件，亦不得將其貼入公開 Issue 或除錯服務。

公開個人頁面預設關閉；開啟後可公開主信箱、個人欄位、角色、加入時間及獲准的統計。升級後的後端分別執行統計、趨勢與來源三個公開選項；使用者或信箱帳號停用、刪除時，公開端點回傳 404。軟刪除不會同時實體刪除原靜態頭像 URL 下的檔案；既有頭像位址或其他副本仍須分別處理。營運者須核對實際匿名回應，不以介面隱藏代替後端控制。

### 4.5 敏感與第三人的資料

郵件可能包含健康、種族、宗教、政治意見、工會、基因、用於唯一識別個人的生物辨識、性生活或性傾向等特殊類別資料；刑事定罪與犯罪資料另受特別限制。僅稱「被動儲存」或取得帳號使用者的一般同意，不會自動滿足相關額外法律要件，也不能代替郵件所涉其他人的有效同意。目前不以承接受監管的敏感資料處理為服務目的；未確認合法依據及保障前，不應上傳此類真實資料。意外收到時，營運者仍須限制存取、評估合法處理及刪除，不能僅以用途禁止免除責任。

學習及測試優先使用合成資料，或經評估不能以合理可能使用的手段重新識別個人的匿名資料。僅替換姓名、遮蓋地址、雜湊帳號或分開保存對照表，仍可能屬於可關聯的假名化個人資料；郵件脈絡、附件和第三人的資訊亦須評估。合成郵件內容不會使真實測試帳號、IP、登入及第三方請求紀錄自動匿名。

## 6. AI 與選用內容處理

已核對的程式包含收件時的驗證碼提取，以及您操作後的翻譯、圖片文字辨識。實際資料可能包括主旨、正文片段、圖片及其中的身分或敏感內容，不能保證文本中沒有個人資料。OpenAI 相容協定只描述介面，不表示接收者必然為 OpenAI。

自動驗證碼提取、翻譯與 OCR 的伺服器許可門檻預設均為 false；目前程式不提供公共翻譯備援。自動提取還要求全站 `aiCode`、使用者 `aiVerificationCode` 明確為 true 及所需告知確認，缺少條件不執行；允許後可在新信抵達時向 Workers AI 傳送完整主旨及最多 6,000 個 JavaScript 字元的正文，主旨不計入上限。逐使用者選擇可關閉，但不是每封信都須按按鈕。實例須升級並落實配置；技術開關或確認不單獨證明 GDPR 的合法依據或完整同意要求已滿足。

開啟翻譯面板或切換語言不傳送內容，須主動確認並提供與目前告知對應的 URL，伺服器門檻通過後才可處理。翻譯可使用配置模型或 Workers AI；MyMemory／Google 公共翻譯備援已從所有路徑移除，目前無法使用；後端拒絕儲存啟用值 true，介面選項停用。舊實例須升級，不能只依賴原開關。OCR 省略參數時為 false，只有本次明確選擇並通過伺服器許可才處理圖片；可傳送內嵌圖片位元組或遠端圖片 URL 到配置接收者，辨識結果再進入翻譯。

真實接收實體、契約、保存及跨境保障仍須依實例揭露並核實；確認目前告知不證明這些事項已完成，也不授權未揭露接收者或模型訓練。未具備依據或保障時應停用相關外傳。升級後的個人 Telegram 按 `all`（全部）或 `important`（重要）篩選，重要依據真實「重要／important」標籤、星標或既有驗證碼。`notifyCodeOnly` 預設 `false`，僅在非 `privacy` 模式且已有不超過 256 字元的提取驗證碼時附加複製按鈕，不是只推送驗證碼郵件。`includePreview` 預設 `false`；在 `all`／`important` 模式中，通知標題仍採用郵件主旨（無主旨時使用通用標題），最多 200 字元，即使關閉預覽也保留；明確設為 `true` 後才另外附最多 400 字元摘要及配置可用時的閱讀連結；`privacy` 模式只發通用標題，不含主旨、寄件人、收件人、驗證碼或連結。閱讀及附件每次校驗狀態與版本，關閉預覽也不能繞過。轉寄規則無法使用時停止轉寄，不退為全部；保存的 `keepCopy` 會規範化為 `true`，啟用轉寄時提交 `false` 會被拒絕，停用時也寫入 `true`，保留原件。細節見[通知與轉寄指南](/zh-tw/mail/notify/)，實例仍須升級並核對實際效果。

營運者不將郵件作為自行訓練模型的資料集；第三方的保存、訓練與再利用限制須以實際契約及配置確認，不憑本政策代其作保。AI 結果可能有誤，驗證碼、翻譯與辨識輸出應由您核對；本服務不以此提供具法律效果的專業判斷。在適用範圍內應清楚標示 AI 功能及輸出，依實際角色與用途履行必要透明告知；一般翻譯或辨識不因使用 AI 就當然屬高風險系統，亦不因此取得合規認證。

## 7. 接收者與國際傳輸

依實際配置，接收者包括 Cloudflare、外寄投遞服務、您或營運者指定的儲存與資料庫、身分源、AI／翻譯服務、通知平臺、經授權應用及收件人的郵件服務商。各方是否為受託處理者或獨立控管者依其實際用途及契約判斷，不能全數列為僅按指示處理。

Cloudflare 全球網路或非歐盟供應者的使用不保證資料僅在歐洲經濟區內處理。GDPR 限制的跨境傳輸，須先確認實際地區與合法機制，例如對應範圍的充分性決定，或已有效訂立的標準契約條款、傳輸影響評估及必要補充措施。SOC 2、ISO 認證、TLS 或服務商宣稱提供 SCC，都不單獨構成該次傳輸已合法的證明。例外或明示同意不應用作反覆、結構性傳輸的通常替代方案。

可向第 14 節窗口索取與您資料相關的接收者、地區及保障摘要，並在依法可提供且經必要遮蔽後取得保障文件。對有權機關的請求，營運者核實權限與法律依據、限制揭露範圍，並於法律允許且不損及合法目的時通知受影響者。

## 8. 保存、停用與刪除

| 資料類別 | 實際機制及保存標準 |
| --- | --- |
| 帳號、個人設定與正常郵件 | 為提供服務而保存至刪除、帳號清理或合法必要性消失；停用不等同實體清除 |
| 本機草稿、目前郵件與收件人歷史 | 一般登出撤銷目前工作階段並清除目前郵件及記憶體收件人快取，但不刪除 `epomail_recipient_records:*` 或其他帳號；草稿與附件保留並在刪除草稿時同一交易聯刪；裝置清除與收件人紀錄、草稿附件聯刪見第 4.3 節，伺服器匯出不涵蓋這些本機資料 |
| 垃圾郵件與垃圾桶 | 每日處理以郵件 `create_time` 起算；垃圾保存預設 7 日後轉垃圾桶，垃圾桶門檻固定 7 日，因此可在同輪符合實體刪除條件；不是移入後再保證 7 日緩衝 |
| 過期系統郵件與配額清理 | 部分官方郵件在讀取列表時依過期天數（預設 7 日）標記刪除，再由排程處理；執行刪除時用量已超過配額 90% 的郵件可直接實體刪除 |
| 帳號註銷／停用 | 升級後的註銷先在 D1 停用全部關聯信箱，再撤銷工作階段、PAT、可信裝置、待驗證狀態與 OAuth 授權；入站在 AI 處理前阻擋。刪除使用者紀錄前已接入原始 MIME 清理，失敗保留定位資訊供重試；`manual_review` 仍表示須人工複核原文、claim 及其他殘留，不是全量刪除；`cleanup_failed` 表示清理失敗且有可查狀態，不承諾 90 日全清 |
| 安全、登入、稽核及權利請求紀錄 | 僅保存特定目的所必要的期間；沒有通用自動到期的項目，營運者須另訂並落實最短必要保存與定期複核 |
| 附件、原始郵件、備份及外部副本 | 附件自備儲存定位資訊保留至其刪除佇列 pending／failed 項處理完；缺原配置時回報失敗，不改用預設儲存桶刪除。原始 MIME 使用第 4.2 節的獨立到期清理，不屬於附件佇列。Telegram 閱讀及附件每次校驗使用者／信箱／郵件狀態與版本；資料設定可撤銷全部閱讀連結，停用或變更個人通知會撤舊連結，但不刪除聊天或已下載副本 |
| 法定保存或具體爭議 | 有實際法律依據時僅保留所需資料、限制其他使用並記錄理由及期限，期滿清除 |
| 計畫性停運 | 在合理可行時先通知並提供資料取回期間，再終止資源及處理殘留副本；突發中斷可能限制取回能力 |

沒有一項固定的 90 日寬限可排除法定「不再必要即刪除」或第 9 節的請求期限。若備份只能按週期覆寫，應隔離不再使用、告知週期，並於復原時重新套用刪除；未確認的備份週期不能描述為即時或徹底不可復原。寄件人、收件人或獨立服務商已持有的副本，通常無法由本服務單方面刪除；依法應通知接收者更正、刪除或限制時仍須辦理。

## 9. 當事人權利與處理期限

依適用法律及其要件，您可請求知情、查閱及複本、更正、刪除、限制處理、反對基於合法利益的處理、撤回同意，以及在符合條件時取得機器可讀資料或請求可攜。撤回不影響撤回前合法的處理；反對直接行銷時應停止該用途。您亦可就具有重大影響的自動決定請求適用的保障與人工介入。

撤回應與給予同意同樣容易。可透過相應功能的實際退出管道或 `privacy@epocanvas.com` 提出；如該管道無法及時停止後續處理，或比啟用明顯更困難，營運者應先改善機制或停用依賴該同意的處理。撤回選用功能的同意不應迫使您註銷無關的基本服務。GDPR 可攜權限於以同意或契約為依據、以自動化方式處理且由您提供的資料；技術可行時可請求直接傳給另一資料控管者。可攜範圍依資料來源、處理依據及方式判斷，通訊中同時涉及他人的資料不因此一概排除，但提供或移轉不得不利影響其他人的權利與自由，亦不授予您存取他人帳號或無關郵件的權利。對合法利益處理提出異議後，除可證明優先的重大合法理由或為法律請求所必要外，應停止相應處理。

自助匯出是其中一個途徑，匯出檔不等於所有資料的完整副本：個人欄位為選定子集，不包含附件檔案、垃圾桶郵件、完整路由欄位、原始 MIME、所有別名及安全／管理稽核紀錄。取得未包含且依法可請求的資料，可聯絡 `privacy@epocanvas.com`；營運者亦須保護通訊對象及其他人的權利，必要時遮蔽而非一概拒絕。

GDPR 適用時，應無不當遲延處理請求，最遲於收到請求後一個月內告知所採取的行動；僅確認收件不算完成。因複雜程度或請求數量而有必要時，可依法再延長最多兩個月，但須在第一個月內說明延長及理由；不採取行動時亦應在期限內告知理由、申訴與司法救濟途徑。其他適用法律定有較短期限者，依其規定。

一般請求免費。僅在適用法律允許且能證明請求明顯無根據或過度時，始得收合理費用或拒絕並說明。身分有合理疑義時僅要求必要的補充核驗，不一律索取證件，也不以未註冊或無法登入排除權利。

您可直接向有管轄權的資料保護機關申訴及尋求司法救濟；GDPR 適用時，包括您慣常居所、工作地或涉嫌侵害地的主管機關。毋須先取得營運者同意或先用完內部申訴。歐盟機關聯絡資料可見 [EDPB 成員清單](https://www.edpb.europa.eu/about-edpb/about-edpb/members_en)。

## 10. 安全與事故應變

營運者應依資料性質、風險、技術現況及合理實施成本採取適當的存取控制、憑證保護、加密、更新與事故處理措施；安全功能的存在不構成零風險或特定認證的保證。個人維護模式不要求本政策以外的 24 小時支援，但不延長法定通報期限。

事故須立即評估、控制並留存紀錄。GDPR 適用時，除不太可能對個人權利自由造成風險外，控管者應無不當遲延且在可行情況下於知悉後 72 小時內向有管轄權的監管機關通報；遲報須說明，資訊可依法分階段提供。對當事人可能造成高度風險時，除符合法定例外，應無不當遲延直接告知，不一律以公開事故細節代替通知。受託處理者應無不當遲延通知控管者。其他適用通訊法另有通報對象、門檻或較短期限者，從其規定。

## 12. 法律適用與比例原則

本站現有文件以臺灣為託管服務的法律背景，但本次未由可核實的營運者資料確認其實際所在國家及地址；選擇臺灣法或使用繁體中文不能證明所在地。對外處理真實個人資料前須補齊第 2 節身分資料，並確認實際適用的資料保護及通訊法律。臺灣法規義務應按官方資料庫所載已生效規定與施行注記判斷；法規修正公布不等於已施行。

營運地不是唯一判斷依據。在歐盟設立機構相關活動中處理資料，或在境外向身在歐盟的人提供服務、監測其境內行為而符合法定條件時，GDPR 亦可能適用；單純網站可從歐盟連線，不當然構成向當地提供服務。免費、公益、個人作者或「測試中」不會自動排除適用；對外開放信箱亦不能一概援用純粹個人或家庭活動例外。

是否應任命歐盟代表、資料保護長或進行影響評估，須分別判斷：

- 境外營運者因向歐盟境內人士提供服務或監測而適用 GDPR 時，代表例外須同時滿足處理偶發、不含大規模特殊類別或刑事資料處理，以及依性質、情境、範圍與目的不太可能造成風險；持續信箱服務通常不能僅憑人數少援用。
- 資料保護長在核心活動涉及大規模、經常且系統性監測，或大規模特殊類別／刑事資料等法定情形下須指定；一般隱私聯絡人不自動具有該職務。
- 可能對個人權利自由造成高度風險的擬議處理，應先作資料保護影響評估；不能僅憑「測試」略過，也不要求每個合成郵件實驗都進行同一規模的評估。
- 不足 250 人的處理紀錄例外受非偶發、風險及特殊類別／刑事資料等限制。持續郵件處理仍須判斷紀錄義務；簡明管理紀錄可按實際角色涵蓋法定欄位，無須購買專用系統。

措施可配合規模與風險，不因發布原始碼而當然須成立公司、取得 ISO 認證、購買保險或承諾企業級支援。是否屬於受規管的通訊服務，仍須按實際功能、向歐盟提供服務的情況及相關成員國規則另行判斷；免費或「測試」不當然排除通訊保密義務。
