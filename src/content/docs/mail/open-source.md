本页说明 EpoCanvas Mail 专案开源授权的范围与自行部署的法律地位。本页不构成任何实例的用户契约：托管实例用户适用[服务条款](/mail/terms-of-service/)与[隐私政策](/mail/privacy-policy/)；自部署实例的用户适用部署者自行公布的条款。

![EpoCanvas Mail 责任边界：上游开源项目提供源代码，实例由其运营者独立运作并承担数据控制者责任](/images/mail/self-host-responsibilities.svg)

*图：软件、运营者与用户三方之责任边界。上游开源作者不运营任何电子邮件服务，亦不为任何实例之行为负责。*

## 1. 授权条款

本专案源代码依 MIT 授权条款（MIT License）发布，任何人可免费取得并：

1. 使用、复制、修改、合并、发布、分发、再授权及销售本软件的副本；
2. 前提是在软件的所有副本或主要部分中保留原版权声明与本许可声明；
3. 软件按「现状」提供，不附任何明示或默示的担保，包括适销性、特定用途适用性与不侵权的担保；
4. 作者或版权持有人不对因软件或软件的使用产生的任何索赔、损害或其他责任负责。

## 2. 授权之外

- MIT 授权条款不授予商标或品牌使用权：EpoCanvas、Epomail 的名称、标识、Logo 与视觉资产不随源代码开放而授权使用；
- 不得陈述或暗示获得上游项目的背书或合作关系；
- 派生发行应自行承担命名与标识的合规，并自行维护其与上游代码的差异说明。

## 3. 自部署者的法律地位

- 自部署之时点起，部署者即成为其实例用户的数据控制者，上游开源作者不接触实例资料（责任界定见[隐私权与条款总览](/mail/overview/)第 2 节）；
- 部署者应依其所在地适用法律，对其用户履行告知、当事人权利响应、安全维护与国际传输等义务；
- 本站法律文档（隐私政策、服务条款、可接受使用政策、数据处理与安全维护、第三方处理者清单）可作为部署者面向其用户的范本，采用时应依其实际配置修订，责任主体随之转为部署者；
- 部署者配置的第三方服务（Cloudflare、Resend、Backblaze、Turso 等）由部署者自行建立契约关系，该等服务之条款对部署者及其用户适用，与托管实例的[第三方处理者清单](/mail/sub-processors/)相互独立。

## 4. 部署的技术门槛与安全责任

部署者应完成密钥注入与初始化引导（步骤见[部署指南](/mail/deployment/)），并对实例的访问控制、密钥保管与后续更新负责；上游项目发布的安全修复不自动及于未更新的部署实例。

## 5. 贡献与回馈

- 缺陷报告与功能建议经 GitHub 仓库的 Issue 提交，代码贡献以 Pull Request 进行；
- 贡献者应确认其为所提交内容的权利人；贡献一经并入仓库，即按 MIT 授权条款随源代码分发；
- 安全漏洞请勿以公开 Issue 披露，应经[总览](/mail/overview/)第 5 节的联络窗口私下报告。
