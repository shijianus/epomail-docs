# 官方邮件规范与防篡改验证机制

**生效日期：2026 年 10 月 1 日｜版本：5.5**

本文档依[隐私权与条款总览](/mail/overview/)与[数据处理与安全维护](/mail/data-security/)，详细规范 EpoCanvas Mail 之官方邮件签发体系、安全操作通知规格、边缘发件人防伪、不可变快照投递、客户端沙箱隔离，以及文档密码学防篡改验证机制。本文档旨在明确何谓「真正权威的官方规格说明」，并提供用户与主管机关可验证之技术存证标准。

本站法律与技术文档以本服务开源实现为准，旨在建立透明、严谨之非商业社区通讯规范。

## 1. 官方发件人防伪与身份认证体系

为彻底杜绝网络钓鱼与发件人伪造风险，本服务建立边缘特权隔离通道，将官方系统通讯与一般用户收发信严格分离：

1. **唯一官方发信地址锁定**：本服务所有系统欢迎邮件、全域运营公告与安全操作提醒，唯一且排他地由官方认证地址 `announcement@epocanvas.com` 签发；
2. **边缘层冒充阻断机制**：Cloudflare Workers 边缘网关与入站路由实施硬编码过滤，任何外部寄件者、未授权连接或非特权内部 API 企图以 `announcement@epocanvas.com` 名义寄送邮件，将于网关层立即阻断并抛出 403 拒绝访问；
3. **认证标签与官方蓝标 (`isOfficial: 1`)**：仅由系统特权管道生成之邮件，方由边缘节点注入不可伪造之 `isOfficial = 1` 属性，前端阅读窗格自动渲染专属蓝色官方盾牌认证标识及横幅提示；
4. **生命周期与清理原则**：引导性质之系统邮件标记为重要待办并于 7 日后自动物理清理；涉及重大安全事件之通知信件则永久封存归档于数据库，不受常规 TTL 覆盖。

## 2. 安全操作通知邮件体系（16 类事件）

本服务将用户与系统关键异动纳入 4 级安全防护阶梯（L1 至 L4），建立覆盖 16 种安全事件的实时通知矩阵。信件排版严格遵循去 AI 味之极简工程设计，整合内联矢量盾牌、双向操作指引卡片（本人操作备查 vs 非本人操作紧急处置）与深色安全管理按钮：

| 等级 | 事件代码 | 触发时机与安全情境 | 注入元数据与参数 | 星标加注 |
| --- | --- | --- | --- | --- |
| L1 | NEW_DEVICE_LOGIN | 首次检测到未识别的新设备或浏览器登录 | 时间、IP、地点、设备名称、浏览器 | 否 |
| L1 | NEW_LOCATION_LOGIN | 跨城市或跨国别之新地理位置登录 | 时间、IP、国家与城市、网络服务商 | 否 |
| L1 | NEW_NETWORK_LOGIN | 新网络自治域 (ASN) 或新 ISP 接入点登录 | 时间、IP、ASN 编号、网络提供商名称 | 否 |
| L2 | PASSWORD_CHANGED | 账号登录密码已成功变更 | 时间、IP、地点、设备与浏览器 | 否 |
| L2 | PAT_CREATED | 生成新的个人访问令牌 (Personal Access Token) | 令牌名称、访问权限范围、有效天数 | 否 |
| L2 | PAT_REVOKED | 个人访问令牌已被手动吊销或过期作废 | 令牌名称、吊销时点、操作设备 | 否 |
| L2 | OAUTH_AUTHORIZED | 授权第三方应用访问邮箱数据 (OAuth 2.0) | 应用名称、授权范围、客户端标识符 | 否 |
| L2 | OAUTH_REVOKED | 撤销特定第三方应用之访问权限 | 应用名称、撤销时点、客户端信息 | 否 |
| L3 | TOTP_ENABLED | 成功启用 TOTP (RFC 6238) 双重验证防护 | 时间、IP、生成时点、备用码状态 | 是 |
| L3 | TOTP_DISABLED | 停用双重验证（降级为仅密码单一验证） | 时间、IP、操作设备、安全警示指引 | 是 |
| L3 | PASSKEY_ADDED | 绑定新的通行密钥 (FIDO2 / WebAuthn) | 通行密钥名称、认证器类型、绑定时点 | 是 |
| L3 | PASSKEY_REMOVED | 移除已登记之通行密钥凭证 | 通行密钥名称、移除时点、操作设备 | 是 |
| L3 | AUTO_FORWARD_CHANGED | 配置或变更邮件自动转发目的地 | 转发目标邮箱、过滤条件、启用状态 | 是 |
| L3 | STORAGE_PURGED | 自定义对象存储 (BYO Storage) 配置被重置或清空 | 重置时点、操作 IP、默认存储回退状态 | 是 |
| L4 | ACCOUNT_LOCKED | 连续登录失败达到阈值触发 12 小时防爆破锁定 | 失败次数、锁定时间、封锁 IP、解锁指引 | 是 |
| L4 | ACCOUNT_DELETED | 账号已申请注销或实体数据排程清除 | 申请时点、关联别名数、数据销毁期限 | 是 |

为防范警报风暴对用户造成疲劳，系统于 KV 中维护已知环境指纹库（记录最新 15 条设备、地点与网络），并对同类事件实施 1 小时静默去重视窗。

## 3. 邮件不可变投递与客户端沙箱防篡改

官方邮件之通讯实施不可变传输与客户端安全沙箱隔离，确保任何中间环节均无法篡改信件内容：

1. **不可变快照投递 (Immutable Delivery)**：系统邮件于发送时完成渲染并固化写入数据库，不随收件人日后切换个人语言而动态重译，维护法律通讯之客观唯一性；
2. **预置翻译对称回退**：多语言翻译引擎预先编译官方模板之标准译文，比对一致时直调预置翻译，一旦正文遭修改即优雅降级至 AI 全文翻译；
3. **客户端 Shadow DOM 物理隔离**：前端采用自封闭开放 Shadow DOM 渲染邮件内容，外层样式与全局脚本绝对无法穿透；
4. **DOMPurify 白名单过滤**：强制清除 `<script>`、`<style>`、`<iframe>`、`<object>`、`<embed>`、`<form>` 标签及所有内联脚本事件，杜绝 XSS 与客户端界面伪造。

## 4. 官方文档防篡改与完整性校验体系

本服务之官方文档（`epomail-docs`）采用开源密码学哈希存证体系，任何用户均可离线或线上验真文档之原始性：

| 防护维度 | 技术落实机制 | 验真依据与标准 | 防范攻击场景 |
| --- | --- | --- | --- |
| 确定性指纹清单 | `public/tamper-proof.json` | SHA-256 内容哈希值与字节大小 | 镜像站点内容篡改、文档偷梁换柱 |
| 版本溯源锚点 | Git Commit 树状对象 | Git Commit SHA 与作者 PGP 签名 | 未经授权之静默更新与历史篡改 |
| 客户端实时验真 | Web Crypto API 内存计算 | `crypto.subtle.digest('SHA-256')` | 传输中间人篡改、CDN 缓存污染 |
| 离线终端校验 | OpenSSL / sha256sum 工具链 | 原始 Markdown 本地哈希比对 | 离线审计、主管机关法规遵从检查 |
| 官方权威源站 | `https://docs.epocanvas.com/epomail` | DNSSEC 验证与严格 TLS 证书 | 伪冒官方站点、钓鱼文档欺诈 |

:::tip[线上验真操作指引]
本站每个文档页面底端均内嵌「🛡️ 官方防篡改与完整性校验」实时面板。用户点击「🔍 实时验证本文完整性」按钮，浏览器将于本地内存完成 SHA-256 计算，并与官方清单核对。用户亦可于终端执行 `curl -sSL https://docs.epocanvas.com/epomail/tamper-proof.json | jq .` 获取官方存证信息。
:::
