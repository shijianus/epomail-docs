## 1. 系统发信身份与显示标记

识别系统通讯时，应区分应用显示规则与身份认证：

1. 欢迎邮件与全域公告通常由系统使用内置地址 `announcement@epocanvas.com` 生成；这不表示其他安全或管理通知不存在，也不表示显示该地址的邮件必定真实。
2. `isOfficial` 为应用显示标记：发件人为 `announcement@epocanvas.com`、`admin@epocanvas.com`，或带「官方」标签时，可显示标识与横幅。该标记不是数字签名，也不是对发件人身份的独立认证。
3. 部分系统邮件于读取列表时，按配置的过期天数（默认 7 日）懒标记删除，再由每日计划任务清理；并非到期立即彻底删除。实际期限与清理限制见[数据处理与安全维护](/mail/data-security/)第 1.5 节。

## 2. 系统邮件与通知目录

系统通讯包括下列类型；具体是否发送与发送方式取决于实现、配置及事件，不限于欢迎邮件与公告：

| 类型 | 触发时机 | 说明 |
| --- | --- | --- |
| 欢迎邮件 | 新信箱开通 | 可使用内置六语言模板；保存与清理依第 1 节 |
| 全域公告 | 管理员发布系统公告 | 可使用内置六语言模板或经修改的内容；保存与清理依第 1 节 |
| 安全通知 | 登录或安全事件、依法须通知的事故 | 可因事件与适用规则发出，不因其涉及账户安全而当然属于伪造邮件 |
| 管理裁决与申诉通知 | 管理处置、裁决或申诉复核 | 可告知处置与复核结果；有关记录的保存规则见数据安全文件 |

不能仅凭发件地址、显示标记或邮件中的链接判断真伪。请从已知可信的服务入口核对通知；有疑义时使用第 6 节窗口，不在可疑链接中提交凭证。

## 3. 投递快照与模板翻译

1. 模板邮件在发送时替换变量并保存正文快照，切换界面语言本身不会重写已保存的正文。该行为不等于存储不可改写，也不提供数字签名或身份认证。
2. 使用「翻译」时，命中可用的目标语言模板可在本地呈现；无法识别模板、模板缺失或正文改动等未命中情形进入一般翻译流程，可能按配置经模型、Workers AI 或公共翻译备援处理。不能概括承诺官方邮件绝不外传；接收者、处理链及所需保障见[隐私政策](/mail/privacy-policy/)第 6、7 节。

## 4. 客户端渲染限制

邮件正文的渲染采用样式封装与内容清洗，两者都不是独立的身份或安全认证：

1. Shadow DOM 提供 DOM 与样式作用域封装，减少邮件与页面样式互相干扰；它不是脚本安全边界，不能阻止页面脚本访问或操作内容，也不是独立来源的沙箱。
2. DOMPurify 按配置移除危险标签与内联事件处理器，降低内容注入风险。清洗效果依版本、配置与后续处理决定，不能保证阻断所有脚本注入、界面伪造或远程资源请求。

## 5. 发布清单一致性检查

`tamper-proof.json` 是发布清单的既有文件名，不表示清单已签名或不可篡改。在线面板只比较当前站点两次返回的本页清单条目，不对页面正文计算哈希。

| 检查途径 | 机制 | 范围与限制 |
| --- | --- | --- |
| 发布清单 | `tamper-proof.json` | 构建时记录工作树源文件经 CRLF 转 LF 后的 SHA-256、字节数及当时的 Git HEAD；提交号不证明工作树没有未提交修改 |
| 本页面板 | 「发布清单一致性检查」 | 仅在本页概述与图示后、第 1 节前显示；比较初次与再次读取的本页条目 SHA-256 及完整 `gitCommit` |
| 手动源文件核对 | Node／`sha256sum`／OpenSSL | 另行核对清单与源文件的来源及版本，按相同换行规则计算本地 Markdown 哈希；面板不执行此项操作 |
| 请求来源 | 当前站点的同源清单地址 | 只读取该站清单，不请求 GitHub 作独立核验；HTTPS 本身不证明发布者身份或文档法律效力 |

成功仅表示两次清单中本页条目哈希与 `gitCommit` 相同，不验证页面正文、发布者身份、数字签名或法律合规。清单与脚本同由该站提供，若两者一起被替换仍可能显示一致，不能作为独立信任依据。

:::tip[如何检查清单一致性]
在本页面板点击「检查清单一致性」。初次有效读取只建立比对基准，不显示成功；再次读取后哈希或提交号不同显示「验证失败」，发布更新也可能造成差异。网络或 HTTP 错误、无效 JSON／结构、缺少本页条目、不合法的 64 位十六进制 SHA-256 或完整 Git 提交号均显示「无法验证」，不会按成功处理。初取失败后重新读取成功也只建立基准，须再次检查；手动源文件核对说明可在面板内另行展开。
:::
