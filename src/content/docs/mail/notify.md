「资料」页的三个导出卡与「邮件与消息转发」标题区：上面管数据带走的格式，下面管新邮件进来的实时触达。

1. **资料 JSON 导出卡**：下载部分账号字段、未标记删除的邮件字段及自定义标签；不含附件文件、完整安全设置或所有个人资料。
2. **邮件历史归档卡**：浏览器将同一后端响应转换为 MBOX、JSON 或 CSV；后端不应用所选时间范围，也不包含完整原始 MIME 或附件文件。
3. **通讯录与配置卡**：导出返回的个人字段子集与自定义标签；不能作为完整通讯录、别名规则或全部偏好的备份。
4. **邮件与消息转发标题区**：Telegram 通知与自动转寄的入口；个人通知可选全部或重要邮件，预览与验证码复制另行选用。阅读及附件链接每次访问仍须核对当前状态与撤销版本，具体字段与转寄限制见下文。

## 1. Telegram 消息推送

推送使用您自备的私有 Telegram 机器人，新邮件实时直达您的会话：

1. 向 @BotFather 申请一个私有机器人，取得 Bot Token（形如 `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`）；
2. 获取您与该机器人的 Chat ID（向机器人发送任意消息后经 getUpdates 查询，群组为负数、频道形如 `-100123456789`）；
3. 在「Telegram 消息推送」项点设置，填入 Bot Token 与 Chat ID；在群组话题内接收时可另填 Topic ID；
4. 个人通知选择 `all`（全部）或 `important`（重要）。重要邮件只按精确标签 `重要`／`important`、实际星标或已有验证码判定，不按主题含字判断；`notifyCodeOnly` 默认 `false`，仅控制附加验证码快捷复制按钮；只有已有且不超过 256 字符的提取验证码才会添加按钮，不是「只推送含验证码邮件」筛选；
5. 点「发送测试消息」核对目标会话，再确认所传字段与阅读链接后开启推送。

个人通知的 `includePreview` 默认 `false`；在 `all`／`important` 模式中，即使关闭预览，通知仍使用邮件主题（无主题时为通用标题，最多 200 字符）；明确设为 `true` 才另外附摘要（最多 400 字符）及配置可用时的阅读链接。`privacy` 模式无论其他选项为何仅使用通用标题，不含主题、发件人、收件人、验证码或链接。系统通知按管理员配置的系统字段独立处理，不由个人预览开关代为关闭。机器人 Token 与 Chat ID 会交给实例后端，不只留在设备上。自动 AI 验证码识别另须个人选用且服务已配置，默认关闭，与通知筛选及验证码复制选项不同。

本轮本地实现对 Telegram 邮件阅读及附件请求逐次核对链接有效期、所属用户、信箱、邮件状态及撤销版本；个人预览已关闭也会阻止旧链接访问，分享页不加载远程内容。个人通知停用或相关配置改变会撤销旧链接；「设置 → 资料」的「撤销现有阅读链接」可撤销本账号全部既有个人及系统通知链接，未来通知仍可独立生成新链接。普通退出不会撤销这些链接，账号停用后的访问则被状态核验阻止。撤销不删除 Telegram 聊天中已有的正文或下载副本。这些机制不证明所有线上部署已更新，所涉第三方见[第三方处理者清单](/mail/sub-processors/)。

## 2. 自动转发

| 配置项 | 说明 |
| --- | --- |
| 启用自动转发 | 总开关；开启后出现下方配置 |
| 转发目的地邮箱 | 一个或多个目标地址，多个以英文逗号分隔 |
| 触发类型 | 全部邮件，或按收件信箱字面前缀匹配，例如 `billing`；`*` 不代表通配符，别名前缀列表为空时不转寄 |
| 主题标头 | 可选在转发邮件主题添加 `[Fwd]` 标头，便于在目标邮箱中识别 |

:::note
个人「智能规则过滤转发」（`rules`）当前不可用：运行时不转寄，不回退成全转；保存启用的 `rules` 配置会被拒绝。保存的 `keepCopy` 会规范化为 `true`；仅在转寄启用时提交 `keepCopy=false` 会被拒绝，停用的配置也会写入 `true`。转寄不自动删除原件。以上是当前本地源码行为，实际测试仍在复验，不代表线上部署已完成。
:::

## 3. 投递路径与防回环

转寄优先经平台原生通道，失败时可改经系统投递通道并按设置添加 `[Fwd]`；该备援调用只带主题及正文等字段，不带普通附件，不能保证目标取得完整原邮件。与收件人或原发件人相同的目标会跳过；这不是消除全部多跳回环的保证。前置系统规则也可能直接结束入站流程，跳过个人推送及转寄。规则语义见[搜索与规则参考](/mail/search/)第 7 节。
