本页说明托管实例 [mail.epocanvas.com](https://mail.epocanvas.com) 的服务与支持。这是个人维护、非营利的学习与测试 side project；自行部署的条件由其实际运营者另行说明，角色及责任见[开源与自行部署法律](/mail/open-source/)与[总览](/mail/overview/)。注册前请阅读服务条款，不接受者请勿建立账号。

繁体中文（台湾）版为本站正式版本，其余语言为对照译本；此安排不限制适用法律要求的清楚告知、对消费者有利的解释或不得排除的权利。更新日期记录文本修订，不代表新条件自动生效。

## 1. 服务内容

| 项目 | 说明 |
| --- | --- |
| 账号与注册 | 依实例开放情况及配额注册，供年满 16 岁且具备必要缔约能力者使用 |
| 邮件收发 | 经配置的收信路由、站内投递及站外通道处理；收件结果亦受对方服务影响 |
| 存储 | 按账号配额存储；选用个人对象存储时，依配置传送相关数据 |
| 整理与自动化 | 邮件检视、标签、规则、搜索及可配置的验证码提取 |
| AI 能力 | 翻译、文字辨识及其他已启用功能的数据范围与触发条件见隐私政策 |
| 通知与转发 | 可配置 Telegram 及邮件转发；涉及外部接收者与相应数据传送 |
| 用户端 | Web、可安装 PWA 及 Android 应用，依已发布版本提供 |
| 语言 | 六语言界面与本地化通知，实际覆盖依版本 |

功能操作见[功能指南](/mail/features/)与[界面与路由总览](/mail/interface/)；个人数据处理应连同[隐私政策](/mail/privacy-policy/)阅读。

## 2. 服务边界

| 事项 | 边界 |
| --- | --- |
| 可用性 | 无 SLA、固定可用率、投递时限或全年无休值班；上游中断的责任仍依事实与法律判断 |
| 保存期限 | 垃圾桶、调度、备份与合法保存各有范围；删除不等于所有副本立即清除，详见隐私与安全文件 |
| 配额 | 发送、信箱数与存储依实例公布设置及合理变更程序 |
| 费用 | 托管实例目前免费；非营利不排除数据保护与消费者义务 |
| 功能变动 | 不保证永久托管或特定功能持续；重大不利变更与可预见停运应在合理可行时预先通知并提供合理取回期间 |
| 附件限制 | 依实例、存储及投递提供者限制；BYOS 不使其他技术或法律限制失效 |

本项目以欧盟数据保护原则为参照，按实际风险尽合理努力维护与改善，并通过[隐私政策](/mail/privacy-policy/)第 1 节说明已知风险及可采取的措施。此定位不包含全面合规认证、企业级可用性或无事故保证；法定权利及不可排除责任不因风险告知而改变。

服务适合能够容忍中断、内容丢失及功能调整的学习与一般通信测试，不适合作为紧急通信、法定保存、医疗决策、唯一账号恢复信箱或重要数据的唯一备份。请优先使用合成内容，另留必要副本，并按实际需要选择功能。具体保存、导出与加密边界见隐私政策及[数据处理与安全维护](/mail/data-security/)；行为规则见[可接受使用政策](/mail/acceptable-use/)。

## 4. 支持管道

| 管道 | 适用事项 |
| --- | --- |
| 产品内联络 | 站内消息或 `admin@epocanvas.com`，供一般支持与申诉 |
| 隐私与数据保护 | `privacy@epocanvas.com`，供权利行使与数据保护申诉 |
| GitHub Issues | 缺陷与功能建议：[源代码存储库](https://github.com/shijianus/epomail/issues) |
| Telegram | `t.me/epomail` 社区交流，不适合提交私人数据或凭证 |

一般支持非即时，未承诺答复或修复期限。GDPR 适用时，数据保护请求应无不当迟延并于收到后 1 个月内答复；符合法律规定的复杂度或数量条件时，可延长最多 2 个月，并在首月内通知原因；其他适用法律要求更短期间者从其规定。详见隐私政策；一般支持调度不能延后法定期限。

## 5. 申诉与恢复

- 无法登录时，可用登录页提供的恢复或申诉入口，或联络 `admin@epocanvas.com`；仅要求比例相当的核验，恢复依实际验证及技术可行性决定。
- 对警告、停用或终止可提出申诉；紧急隔离不剥夺事后复核与外部救济。处置依[可接受使用政策](/mail/acceptable-use/)第 6、7 节。
- 可使用界面目前提供的导出及单封邮件下载；自助导出不代表涵盖全部个人数据、附件或外部副本。需要补充访问、可移植或删除者，请依[隐私政策](/mail/privacy-policy/)及[数据处理与安全维护](/mail/data-security/)提出请求。

## 6. 自部署实例的支持边界

单纯发布源代码不产生对所有部署的托管、支持或可用性承诺。实际运营者应依其服务关系与适用法律向使用者提供告知及救济；作者若另行运营，同样承担相应义务。

本站文件可作撰写参考，不能取代实际角色、配置及法律适用的评估，也不构成认证。需要组织委托处理者，须先确认是否受理，并另订必要的数据处理协议。
