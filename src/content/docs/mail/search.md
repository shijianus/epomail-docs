**生效日期：2026 年 10 月 5 日｜版本：5.13**

EpoCanvas Mail 的检索分为两套：面向用户的邮件搜索（顶栏搜索框）与面向管理员的全库检索（管理区「全部邮件」）；设置页另有独立的配置项检索。本页逐项列出全部可用算子、旗标与规则条件，均与当前实现一致。分类规则与搜索共用同一字段语义，规则引擎之说明见第 7 节起。

![EpoCanvas Mail 搜索：输入 from:github 后列表仅显示命中邮件并加亮关键词](/images/mail/ui/ui-search.png)

*图：邮件搜索。算子可与自由关键词组合，命中处即时加亮。*

## 1. 语法总则

- 多个条件以空格分隔，彼此为「且」关系，全部满足方命中；
- 取值含空格时以双引号闭合，如 `subject:"年度报告"`；
- 无算子的裸关键词在主题、发件人昵称、发件地址、收件地址与正文五个字段间「或」匹配；
- 默认不区分大小写、模糊子串匹配；精确度与大小写行为可经旗标改变（第 3 节）。

```text
from:github subject:"验证码" after:2026-10-01 exact:true
```

## 2. 字段算子

十个字段算子作用于对应字段，值为子串匹配（时间与大小除外）：

| 算子 | 取值 | 语义 |
| --- | --- | --- |
| `from:<值>` | 文本 | 发件人地址或发件人昵称包含该值；`from:me` 等价 `is:sent` |
| `to:<值>` | 文本 | 收件人地址或收件人昵称包含该值 |
| `subject:<值>` | 文本 | 仅匹配主题 |
| `subject_or_body:<值>` | 文本 | 主题或正文包含该值 |
| `body:<值>` | 文本 | 仅匹配正文纯文本 |
| `larger:<字节>` | 整数 | 邮件体积（正文与内容总长）不小于该字节数 |
| `smaller:<字节>` | 整数 | 邮件体积不大于该字节数 |
| `before:<日期>` | YYYY-MM-DD | 收受时间早于该日 |
| `after:<日期>` | YYYY-MM-DD | 收受时间晚于该日 |
| `label:<名称>` | 标签名 | 命中挂有该标签的邮件；标签名含非 ASCII 字符时建议加双引号 |

## 3. 范围与旗标

旗标改变检索范围或呈现行为，解析后自关键词中剥离：

| 旗标 | 行为 |
| --- | --- |
| `global:` | 放大至所有信箱检索，不受当前视图限制 |
| `is:sent` | 强制包含已发送邮件 |
| `is:spam` | 查询域切换为垃圾邮件 |
| `is:trash` | 查询域切换为回收站 |
| `is:draft` | 前端转跳草稿箱（草稿仅存本设备） |
| `hl:off` | 关闭命中词高亮 |
| `exact:true` | 全词边界精确匹配，避免子串误命中 |
| `case:true` | 开启大小写敏感 |

## 4. 高亮与摘录

命中词于列表与详情以高亮呈现；摘录窗向命中处平移以保留上下文。`exact:true` 时仅全词命中加亮，`case:true` 时区分大小写，`hl:off` 关闭全部高亮。高亮为浏览器原生渲染，不改变邮件内容。

## 5. 管理端 `$` 检索

管理区「全部邮件」分区提供以 `$` 引导的高级语法，面向管理员的全库审查：

| Token | 语义 |
| --- | --- |
| `$sender` | 按发件人昵称或地址检索 |
| `$user` | 按邮件所属用户帐号检索 |
| `$to` | 按收件帐号检索 |
| `$subject` | 按主题检索 |
| `$received`／`$sent`／`$deleted`／`$norecipient`／`$all` | 状态过滤：已接收、已发送、已删除、无收件人、全部 |

Token 支持英文大小写变体与中文别名（如 `$发件人`、`$用户`、`$收件人`、`$主题`）；值本身含 `$` 时以 `\$` 转义。于邮件列表右键任一邮件，可直接以其发件人、收件帐号或所属用户发起检索。加密模式（Level 3）下管理端邮件列表恒为空，本节语法随之不可用，见[运行模式](/mail/modes/)第 2 节。

## 6. 设置页检索

搜索框在设置页自动切换为配置项检索：

| 输入 | 行为 |
| --- | --- |
| 无前缀 | 仅在当前设置面板内检索并加亮命中项，平滑滚动定位，零请求 |
| `all:` 或 `global:` | 跨全部设置页检索，弹出按页面分组的下拉，点击即跳转定位 |
| `app:`、`oauth:`、`client:` | 检索第三方应用管理中的 OAuth 应用 |

联想补全随输入提供，Tab 可补全算子。

## 7. 分类规则条件

标签分区的规则构建器以「条件 + 例外」两步定义规则：条件全部命中且例外无一命中时执行动作。可用条件如下：

| 条件 | 语义 |
| --- | --- |
| `from`（发件人为） | 发件人地址或昵称精确匹配，支持逗号分隔多值 |
| `to`（收件人为） | 收件人精确匹配，支持多值 |
| `sender_address_includes`（发件地址包含） | 按发件域名或地址片段匹配 |
| `recipient_address_includes`（收件地址包含） | 按收件域名或地址片段匹配 |
| `email_received_for_others`（他人同收） | 该地址出现在其他收件人位 |
| `subject_include`（主题包含） | 主题关键词，支持多值 |
| `message_body_includes`（正文包含） | 正文关键词，支持多值 |
| `subject_or_body_include`（主题或正文包含） | 二者任一命中 |
| `system_setting`（系统判定） | 引用系统级判定（如白名单命中） |

:::note
构建器中另提供大小（`at_least`／`at_most`）、日期（`before`／`after`）与邮件头（`message_header_includes`）条件；当前引擎版本尚未实装其判定，选择后该条件不会命中，列此以免误配。
:::

## 8. 动作与优先级

- 规则命中即按规则定义为邮件打上对应标签；
- `priority` 数值决定规则执行顺序，数值小者优先；
- `stopProcessing` 开启后，该规则命中即截断后续规则；
- 规则于收信时自动执行，亦可于标签页手动执行。

## 9. 系统内置启发式与站点治理

- 出厂预置社群、订阅、推销、工作四个标签；其中订阅与推销由内置启发式维护：无回复前缀的发件人、邮件营销平台域名与退订信号归入订阅；折扣、限时等主题词与营销词密度归入推销；
- 站点级治理由管理区「分类管理」配置：发件人黑白名单、主题与内容关键词、白名单模式、空发件人拦截、非收件人拦截与可执行附件拦截；名单命中自动打上对应标签，硬拦截直接拒收并计数；
- 规则与名单的行为细节见[功能指南](/mail/features/)第 4 节。
