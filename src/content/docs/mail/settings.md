**更新日期：2026 年 11 月 2 日｜版本：5.25**

EpoCanvas Mail 的设置分为两个区域：侧栏「设置」区为每个帐号可自行调整的个人设置，含个资、常规、安全、资料与标签五个分区；「管理」区仅对具备管理权限的身份分组显示，承载实例级配置。本页逐区说明各项设置的作用与相互关系。多账户、邮件模式与登录方式等运行层面的行为见[运行模式](/mail/modes/)。

## 1. 个人设置分区

| 分区 | 内容 |
| --- | --- |
| 个资 | 头像、昵称、性别、生日等基本资料与联系信息 |
| 常规 | 个人简介、外观色调、主题壁纸、阅读偏好、界面语言与翻译目标语言 |
| 安全 | 用户名与密码、两步验证中心、注销帐号 |
| 资料 | 数据导出、通知与转发、存储空间与个人云存储 |
| 标签 | 自定义标签与分类规则管理 |

## 2. 个资：个人资料

![EpoCanvas Mail 个资页：基本信息卡含头像上传、个人昵称、性别与生日；联系信息卡显示带主邮箱标记的电子邮件与添加电子邮箱按钮、电话号码；下方为住家、公司与其他地址卡](/images/mail/ui/preferences-guide.png)

*图：个资页。主邮箱带「主邮箱」标记，额外电子邮箱可添加多个并随时移除。*

<details>
<summary>图解：个资页——个人资料被拆成的四个维度</summary>

个资页的四张卡片：从身份形象到联系方式再到地址簿，个人资料的四个维度分卡管理。

1. **基本信息卡**：头像上传、个人昵称、性别与生日；昵称与头像是否对外展示，受管理员「公开个人主页」开关约束。
2. **联系信息卡**：登录主邮箱带「主邮箱」标记且不可移除；可添加多个额外电子邮箱并随时移除，另可登记含区号的电话号码。
3. **地址卡**：住家、公司与其他三组地址分别保存，各自独立增删与编辑。它们是纯粹的个资留存字段：不参与邮件投递、不影响计费与身份分组；是否需要填写、以及是否对外展示，取决于营运者是否开启「公开个人主页」。
4. **关联设置与安全卡**：个资页通往其他设置页的跳板：帐号安全（用户名与密码、两步验证）与第三方授权（已授权应用）两处最常用的入口集中在此，避免在个资页与安全页之间反复翻找；点击即跳至对应分区，而非另开新页。

</details>

基本信息卡管理头像、昵称、性别与生日；联系信息卡列出登录主邮箱与自行添加的额外电子邮箱，另可登记含区号的电话号码；地址卡分别保存住家、公司与其他地址。资料的公开范围受管理员「公开个人主页」开关约束。

## 3. 常规：外观与语言

![EpoCanvas Mail 常规页：个人简介文本框，个性装扮区提供暗色调、亮色调与跟随系统三种外观色调，全局主题壁纸提供八种预设与自定义壁纸，下方继续个人背景等设置](/images/mail/ui/general-guide.png)

*图：常规页的外观色调与主题壁纸选择，当前为跟随系统与默认纯净壁纸。*

<details>
<summary>图解：常规页——外观与阅读习惯的三张卡</summary>

常规页的三张卡片：个人简介、个性装扮与偏好设置，覆盖界面外观与阅读习惯的全部个性化。

1. **个人简介卡**：一段展示于公开个人主页的简介文本；公开主页是否开放由管理员「公开个人主页」开关决定。
2. **个性装扮卡**：外观色调三态（暗色/亮色/跟随系统，顶栏可快捷切换）与全局主题壁纸（八种预设 + 自定义壁纸或 URL）；另有个人背景（仅覆盖信箱区）与界面密度。
3. **偏好卡**：阅读偏好（收件箱类型、阅读窗格位置、会话视图）与语言（界面语言六选一、AI 翻译目标语言 16 选一）；数据隐私区集中个人信息与 AI 处理偏好入口。

</details>

- 外观：暗色、亮色、跟随系统三种色调；全局主题壁纸预设八种，支持自定义壁纸；另可单独设置个人背景与界面密度；
- 阅读偏好：收件箱类型、阅读窗格位置与会话视图开关；
- 语言：系统语言六选一；翻译目标语言独立设置，共 16 种，决定 AI 全文翻译的目标语言；图片文字识别翻译可单独关闭；
- 数据隐私区集中于个人信息与 AI 处理偏好入口。

## 4. 安全：密码与两步验证

安全页可修改用户名与密码（显示上次变更时间）。两步验证中心提供总开关与三种第二验证方式的独立配置：身份验证器应用（TOTP）、备用恢复码（10 组一次性代码）与通行密钥（Passkey）。关闭 TOTP 会移除 TOTP 密钥；若仍有有效通行密钥，帐号仍维持两步验证启用，通行密钥不会随之删除。两步验证的登录行为与信任设备规则见[运行模式](/mail/modes/)第 4 节。页面底部提供注销帐号入口，注销后帐号资料依[隐私政策](/mail/privacy-policy/)的删除条款处理。

## 5. 资料：导出、通知与存储

![EpoCanvas Mail 资料页：个人资料、邮件归档与配置导出的界面入口；各导出均有字段限制，时间范围选项不代表后端已应用；下方为附件用量及对象存储入口](/images/mail/ui/data-guide.png)

*图：资料页。数据导出与存储管理同页呈现，附件存储用量按身份分组配额计算。*

<details>
<summary>图解：资料页——个人数据自主的四个分区</summary>

资料页的四张卡片：数据带走的三个格式、一个转发区、一个存储区与一个第三方授权区，个人数据自主的完整界面。

1. **用户资料与数据导出卡**：JSON、邮件归档及配置导出均取同一后端响应，只包含选定字段；时间范围未生效，不是完整备份。单封 .eml 亦由现有字段重建。
2. **邮件与消息转发卡**：Telegram 与转寄设置；是否开放受管理员控制；个人规则转发（`rules`）当前不可用，运行时不转寄且不回退为全部；Telegram 的通知范围、预览及验证码复制控制按配置执行，详见通知与转发指南。
3. **存储空间卡**：附件用量与配额；个人 Backblaze B2／S3 可承接新附件，其他限制仍适用。解除接入不迁移或删除旧对象，也不保证旧附件继续可读。
4. **第三方应用和服务卡**：查看及撤销 OAuth 授权；服务端可拒绝后续相关请求，但不能收回已交付资料、已签发 ID token 或第三方会话。

</details>

| 导出项 | 格式 | 范围 |
| --- | --- | --- |
| 汇出全量数据（界面名称） | JSON | 部分个人资料、未标记删除邮件的选定字段及 `customLabels`；不含附件文件、完整联系人／规则、安全设置及审计 |
| 邮件历史归档 | MBOX、JSON 或 CSV | 浏览器转换同一响应的邮件字段；后端未应用时间范围，不含垃圾桶邮件及完整原始 MIME |
| 通讯录与配置 | JSON | 返回的个人字段子集、`customLabels` 与导出时间；不是完整通讯录、别名或全部偏好备份 |

单封 .eml 由现有字段重建；完整导出边界见[数据导出与存储](/mail/data/)。「邮件与消息转发」区的绑定、筛选及链接撤销限制见[通知与转发指南](/mail/notify/)。个人 Backblaze B2／S3 可使新附件走个人存储并绕过附件保存路径的系统配额检查，但其他邮件、发送及服务商限制仍适用，解除接入不会迁移或删除旧对象。

## 6. 标签管理

标签分区管理自定义标签的颜色与图标，并配置分类规则的条件、例外与优先级；出厂预置社群、订阅、推销与工作四个标签。规则引擎的行为与搜索语法见[功能指南](/mail/features/)第 3、4 节。

## 7. 管理控制台

管理区按身份分组的权限逐项显示，界面路径与身份分组绑定以防越权访问。九个管理分区如下：

| 分区 | 职责 |
| --- | --- |
| 分析页 | 邮件量、分类与标签的统计仪表盘 |
| 用户列表 | 帐号查询、重置密码、调整身份分组、重置两步验证、封禁与恢复、清空用户邮件 |
| 垃圾邮件／全部邮件 | 全站邮件审查分区；名称与范围随邮件模式变化（Level 1 显示全部邮件，Level 2 显示垃圾邮件分区，Level 3 隐藏入口） |
| 权限控制 | 六种身份分组的配额与权限模板、默认分组与 AI 模型授权；参观者与站长分组受保护不可删除 |
| 注册密钥 | 邀请注册码的签发与查验 |
| 系统设置 | 实例级配置，见下方配置卡清单 |
| 应用管理 | OAuth 2.0／OIDC 第三方应用的接入凭证签发与管理 |
| 分类管理 | 收信与发信功能开关、AI 识别配置、黑白名单与硬拦截规则 |
| 操作报告 | 四大板块风险工单的研判、处置、证据抽屉与申诉裁决 |

<span id="operator-notice"></span>

系统设置中的「运营与隐私」卡须填写可识别的运营者名称、实际国家／地区、联系邮箱、条款版本与有效的服务条款／隐私告知链接；联系地址及接收者、保存说明按实际情形补充。缺少必填资料会阻止新注册，既有登录与初始化不受此门槛影响。注册时用户主动勾选未预选的条款接受框；服务器记录账号、版本、时间、语言及条款链接，不把隐私告知当作一揽子同意。

<span id="optional-processing"></span>

验证码、翻译与 OCR 的可选内容处理默认关闭，启用须配置资料去向说明；自动验证码还需用户在资料页明确选择，翻译须逐次确认当前说明，OCR 须另作本次选择。公共翻译备援当前不可用。资料页另提供撤销现有 Telegram 阅读链接及明确确认后的本机资料清理；注销显示访问关闭与待核验的删除状态，不代表所有副本已删除。须配套升级前后端，真实身份、契约、接收者与保存执行不能由配置代为证明。

系统设置页以配置卡组织实例级配置：

| 配置卡 | 内容 |
| --- | --- |
| 网站设置 | 开放注册、公开个人主页、邮件模式、两步验证、隐藏登录域名、注册码、添加邮箱、多账户快速切换、邮箱前缀规则 |
| 个性化设置 | 网站标题、弹窗提示与动态／静态界面 |
| 第三方认证与单点登录 | 第三方快捷登录总开关与各 Provider 密钥配置（经特性开关控制显示） |
| 存储与核心数据库 | 对象存储（B2／S3，缺省回退 R2／KV）、核心与第三方数据库架构、单附件上限与级联删除、KV 缓存体检 |
| 邮件推送 | Telegram 机器人、全局转发与规则转发（加密模式下锁定关闭） |
| AI 智能引擎与大模型接入 | AI 提供商（自定义 OpenAI 兼容端点或 Cloudflare Workers AI）、启用开关、每日配额与速率限制、模型授权 |
| 用户资料控制 | 用户的 Telegram 推送、邮件转发、API 与自带存储开关及默认存储配额 |
| Turnstile 人机验证 | 人机验证的站点密钥与开关 |
| 网站公告 | 公告弹窗、公告邮件群发与欢迎邮件模板（多语言） |
| 操作报告 | 预警触发的运营阈值 |
| 关于 | 版本信息与更新检查 |

操作报告页以四大板块呈现全站风险事件：滥用威胁、申诉审计、风险管理、操作记录，各自汇总一类工单并提供差异化工单表：

| 板块 | 收录工单 | 常见研判 |
| --- | --- | --- |
| 滥用威胁 | 一人多号、严重举报等 LV3+ 威胁帐号 | 查验证据后解封、封禁或延期 |
| 申诉审计 | 用户就处置判决提交的申诉 | 逐单表单复核后研判放行或驳回 |
| 风险管理 | 垃圾邮件、异地跳 IP 等例行风控 | 按违规等级分级研判与归档 |
| 操作记录 | 已终局的处置与归档更新 | 回溯全程台账与申诉次数 |

![EpoCanvas Mail 操作报告页：页顶四张板块卡与差异化工单表，工具栏含批量延期、刷新、重置、导出数据、清理历史与文档外链](/images/mail/ui/audit-guide.png)

*图：操作报告。四大板块各自汇总一类工单；加密模式下记录时间戳被脱敏擦除。*

<details>
<summary>图解：操作报告——四大板块的工单台</summary>

操作报告页的四个标注分区：四张板块卡决定研判取向，工单表逐条处置。

1. **滥用威胁卡**：LV3+ 威胁帐号的集中台账，实时汇总「待审 N／已封禁 N」，点击进入威胁板块的精简处置视图。
2. **申诉审计卡**：申诉工单数与逐单表单复核入口，研判放行即恢复帐号发信能力。
3. **风险管理卡**：例行风控工单按违规等级、报警原因与截止期限研判。
4. **操作记录卡**：终局处置台账，含更新次数、最后更新与申诉次数；完整的证据抽屉、批量处置与 CSV 导出说明见[操作报告](/mail/audit/)。

</details>
