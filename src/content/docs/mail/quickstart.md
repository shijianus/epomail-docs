本页给出两条上手路径的最短操作序列：路径 A 于托管实例注册即用，从注册到发出第一封信约十分钟；路径 B 将整套服务部署于自己的域名与 Cloudflare 帐号，从克隆仓库到收发核验约三十分钟。两条路径运行同一套代码、使用同一套界面；本页只列动作与结果，功能语义与配置细节经链接进入对应专页，全部内容以开源实现为准。

本站法律文档以繁体中文（台湾）版本为正式版本，其余语言版本为对照译本，文义有疑义时以正式版本为准。

## 1. 选择路径

| | 路径 A：托管实例 | 路径 B：自行部署 |
| --- | --- | --- |
| 适合 | 先试用产品，不自备基础设施 | 已有域名与 Cloudflare 帐号，要资料完全自主 |
| 前置 | 一个浏览器 | 域名、Cloudflare 帐号、Node.js 与 pnpm；站外发信另需投递通道帐号 |
| 耗时 | 约 10 分钟 | 约 30 分钟 |
| 费用 | 当前不设付费功能 | 部署者自有 Cloudflare 用量 |
| 入口 | [mail.epocanvas.com](https://mail.epocanvas.com) | [部署指南](/mail/deployment/) |

## 2. 路径 A：托管实例

1. **注册帐号**：打开 [mail.epocanvas.com](https://mail.epocanvas.com)，在登录页切换到注册表单，以「地址前缀 @ 实例域名」与密码（6–30 位）提交。注册是否需要邀请码、是否附带人机校验由实例配置决定；需要邀请码时向运营者索取，或经 `?code=` 参数直达注册表单。注册即时生效，无需邮件验证。
2. **核对身份分组**：注册后进入实例设定的默认分组；使用邀请码注册时，进入该码绑定的分组。分组决定每日发信配额、信箱数、存储配额与附件权限，出厂播种值见[运行模式](/mail/modes/)第 3 节。
3. **收第一封信**：注册成功后系统自动投递欢迎邮件，登录即见。再用任一外部邮箱向您的新地址发一封含验证码的测试信：验证码经 Workers AI 自动提取，以大字号与绿色徽标呈现于列表与详情（见[功能指南](/mail/features/)第 5 节）。
4. **发第一封信**：点侧栏「写信」弹出写信层。收件人为站内地址时直投秒达；站外地址经营运者配置的投递通道发送。出站量受每日发信配额约束，计数每日重置。
5. **开启自动整理**：出厂预置社群、订阅、推销、工作四个标签，并按启发式自动归类新邮件；自建规则、例外与优先级见[标签与分类管理](/mail/labels/)。
6. **开启两步验证**：于「设置 → 安全」三步绑定验证器应用（TOTP），完成即展示 10 组一次性恢复码，请离线留存；步骤见[帐号安全设置指南](/mail/security/)。
7. **绑定 Telegram 推送**（可选）：以自备机器人实时接收新邮件推送，附 7 日有效的站内阅读链接；步骤见[通知与转发指南](/mail/notify/)。
8. **导出资料**（可选）：于「设置 → 资料」下载选定个人资料及未删邮件字段的 JSON；不含附件文件、完整原始 MIME 或全部安全设置。垃圾桶按邮件创建时间超过 7 天清理，请在删除前另存所需附件；见[数据导出与存储](/mail/data/)、[隐私政策](/mail/privacy-policy/)、[数据处理与安全维护](/mail/data-security/)及[第三方处理者清单](/mail/sub-processors/)。

## 3. 路径 B：自行部署

1. **核对前置条件**：一个域名、一个 Cloudflare 帐号、Node.js 与 pnpm 环境；站外发信需 Resend 或 Mailjet 等投递通道帐号。完整清单见[部署指南](/mail/deployment/)第 1 节。
2. **三步部署**：于终端依次执行（部署目标与自定义域名于 `wrangler.toml` 配置）：

```bash
git clone https://github.com/shijianus/epomail.git
cd epomail/mail-vue && pnpm install && npm run build
cd ../mail-worker && npx wrangler deploy
```

3. **初始化**：首次部署后访问 `/api/init/<jwt_secret>`，完成全部数据表建立、六个标准身份分组播种与主站长帐号初始化；引导链幂等，可安全重复。
4. **注入密钥**：生产环境经 `npx wrangler secret put` 注入 `jwt_secret` 与 `totp_enc_key`；本地开发使用 `.dev.vars`（不入库）。初始化路径中的密钥值须与会话签名密钥一致。
5. **接通收件**：于 Cloudflare 面板启用域名 Email Routing，将目标地址路由至 Worker，入站邮件即收即解析。
6. **接通发件**：于系统设置配置投递通道；未配置前，站内信箱之间仍可直投。
7. **收发核验**：注册一个测试帐号并确认收到欢迎邮件；以测试帐号与主站长帐号站内互发一封信；配置投递通道后再外发一封站外信件并确认送达。四项全部通过即部署完成。
8. **确认法律地位**：自部署之时点起，部署者即为其用户的数据控制者，应向其用户履行告知与安全维护义务；本站法律文档可作为基础范本（见[开源与自行部署法律](/mail/open-source/)）。
