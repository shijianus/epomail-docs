本页说明托管实例注册（路径 A）与自行部署（路径 B）。下列时间仅是功能上手的估算，不含法律与安全准备。本页所述新注册与资料控制流程，须配套升级 Worker、React 登录界面和 Vue 设置界面并完成配置；不表示任何线上实例已升级或通过验证。其他功能与配置细节见各专页。

本站法律文档以繁体中文（台湾）版本为正式版本，其余语言版本为对照译本，文义有疑义时以正式版本为准。

## 1. 选择路径

| | 路径 A：托管实例 | 路径 B：自行部署 |
| --- | --- | --- |
| 适合 | 先试用产品，不自备基础设施 | 已有域名与 Cloudflare 帐号，要资料完全自主 |
| 前置 | 一个浏览器 | 域名、Cloudflare 帐号、Node.js 与 pnpm；站外发信另需投递通道帐号 |
| 耗时 | 约 10 分钟 | 约 30 分钟 |
| 费用 | 当前不设付费功能 | 部署者自有 Cloudflare 用量 |
| 入口 | [mail.epocanvas.com](https://mail.epocanvas.com) | [部署指南](/mail/deployment/) |

## 2. 路径 A：托管实例

1. **注册帐号**：打开 [mail.epocanvas.com](https://mail.epocanvas.com)，在登录页切换到注册表单，阅读实例显示的运营者资料、当前条款版本与[服务条款](/mail/terms-of-service/)，勾选未预选的「我接受服务条款」复选框后，提交「地址前缀 @ 实例域名」与密码（6–30 位）。[隐私政策](/mail/privacy-policy/)在此提供资料处理告知，不以一个复选框取得概括隐私同意；若必要法律告知或条款版本资料不完整，新注册会关闭。此门槛只影响新注册；既有登录与管理员初始化路径仍可使用。注册是否需要邀请码、是否附带人机校验由实例配置决定；需要邀请码时向运营者索取，或经 `?code=` 参数直达注册表单。注册即时生效，无需邮件验证。
2. **核对身份分组**：注册后进入实例设定的默认分组；使用邀请码注册时，进入该码绑定的分组。分组决定每日发信配额、信箱数、存储配额与附件权限，出厂播种值见[运行模式](/mail/modes/)第 3 节。
3. **收第一封信**：注册成功后查看欢迎邮件，并以您控制的外部邮箱发送合成测试内容，确认收件。验证码提取不是默认启用：须实例开启 `verificationCodeEnabled` 并提供当前处理告知，且您主动开启默认关闭的个人偏好。翻译逐次确认当前告知；图片 OCR 另需本次明确选择与服务器开关，公共翻译回退默认关闭。见[设置指南](/mail/settings/#optional-processing)。
4. **发第一封信**：点侧栏「写信」弹出写信层。收件人为站内地址时直投秒达；站外地址经营运者配置的投递通道发送。出站量受每日发信配额约束，计数每日重置。
5. **开启自动整理**：出厂预置社群、订阅、推销、工作四个标签，并按启发式自动归类新邮件；自建规则、例外与优先级见[标签与分类管理](/mail/labels/)。
6. **开启两步验证**：于「设置 → 安全」三步绑定验证器应用（TOTP），完成即展示 10 组一次性恢复码，请离线留存；步骤见[帐号安全设置指南](/mail/security/)。
7. **绑定 Telegram 推送**（可选）：以自备机器人实时接收新邮件推送，附 7 日有效的站内阅读链接；步骤见[通知与转发指南](/mail/notify/)。
8. **导出资料**（可选）：于「设置 → 资料」下载选定个人资料及未删邮件字段的 JSON；不含附件文件、完整原始 MIME 或全部安全设置。垃圾桶按邮件创建时间超过 7 天清理，请在删除前另存所需附件；见[数据导出与存储](/mail/data/)、[隐私政策](/mail/privacy-policy/)、[数据处理与安全维护](/mail/data-security/)及[第三方处理者清单](/mail/sub-processors/)。

## 3. 路径 B：自行部署

1. **核对前置条件**：一个域名、一个 Cloudflare 帐号、Node.js 与 pnpm 环境；站外发信需 Resend 或 Mailjet 等投递通道帐号。完整清单见[部署指南](/mail/deployment/)第 1 节。冷启动前先完成 `temp_login_ui` 的 React 构建，再完成 `mail-vue` 的 Vue 构建；`mail-vue` 的构建脚本会将登录面复制到 Worker 静态资源。
2. **部署**：在终端依次构建前端并部署 Worker（部署目标与自定义域名于 `wrangler.toml` 配置）：

```bash
git clone https://github.com/shijianus/epomail.git
cd epomail
pnpm --dir mail-worker install --frozen-lockfile
node scripts/build-prod.mjs
```

3. **注入密钥并部署**：由仓库根目录执行 `pnpm --dir mail-worker exec wrangler secret put jwt_secret` 与 `pnpm --dir mail-worker exec wrangler secret put totp_enc_key`，另建议以相同方式设置独立的 `init_secret`；完成后执行 `pnpm --dir mail-worker exec wrangler deploy`。密钥经交互提示输入，不写入 URL、版本控制文件或公开示例。
4. **初始化与配置告知**：通过 HTTPS 向 `/api/init` 发送 `POST`，在 `x-init-secret` 标头提供 `init_secret`（未另设时回退为 `jwt_secret`），建立数据表、播种标准分组并初始化站长。若响应含初始密码，私下保存并立即变更。登录管理界面后完成[运营者告知设置](/mail/settings/#operator-notice)，再开放注册；缺少必填资料不阻挡站长初始化或既有登录。
5. **接通收件**：于 Cloudflare 面板启用域名 Email Routing，将目标地址路由至 Worker，入站邮件即收即解析。
6. **接通发件**：于系统设置配置投递通道；未配置前，站内信箱之间仍可直投。
7. **收发核验**：在隔离测试环境使用专门建立的帐号与合成数据，检查注册接受条款、欢迎邮件、站内互寄及站外收发；不可公开生产凭证。这些只是功能烟雾测试，不代表安全、隐私、删除或法律准备全部完成，也不是可直接向真实用户开放的证明。
8. **确认法律地位**：按实际决定处理目的与方式的情况评估角色，不因自行部署就当然成为唯一控制者。公布真实身份、所在地、联络资料与依法所需地址，核对接收者、有效契约、跨境安排与保存期限；范本或已填设置不能证明这些事实。见[开源与自行部署法律](/mail/open-source/)。
