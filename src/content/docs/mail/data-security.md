## 1. 安全功能与已知限制

### 1.1 传输与通信保密

网站及 API 应使用正确配置的 HTTPS/TLS。对外投递、收件方系统、外部对象存储及用户自行转寄的整段路径，不能仅凭浏览器连接使用 TLS 就保证全部端到端加密。升级后的 HTML 阅读默认阻止远程图片、远程 CSS 与主动内容；普通阅读可经提示仅允许当前邮件图片，仍有 IP 与打开追踪风险。打印保持默认拦截，Telegram 分享不允许远程资源。Google Fonts 外链已移除，Turnstile、外部头像仍可能请求第三方；见[第三方处理者清单](/mail/sub-processors/)。

### 1.2 边缘处理与调试

业务逻辑使用 Cloudflare Workers，持久状态由数据库与存储服务保存。邮件解析、翻译、投递及备援可能在内存中接触明文；沙箱可重复使用，不能保证每次请求结束即销毁实体内存，亦不能以无自建服务器推论平台无日志或快照。

日志应遮蔽凭证、邮件正文与不必要识别资料。测试优先采用合成内容与隔离资源；不得为重现错误而把真实邮件、密钥或数据库副本上传公开存储库或未获准的 AI／诊断服务。

### 1.3 静态加密

邮件模式可对主题及正文应用 AES-256-GCM 服务器端静态加密；适用范围依模式与记录状态决定。完整原始 MIME 另按第 1.5 节以服务器密钥 AES-256-GCM 加密；附件与元数据不自动取得同样保护。运营者持有密钥及服务器权限，技术上可解密；管理界面的模式限制不等于端到端保密。在隐私模式下，移入垃圾桶可将邮件主题、正文与验证码解密保存并纳入管理可见范围，恢复后再按模式加密；加密模式关闭的系统级通知／转寄不涵盖所有个人配置的外传。

实例应使用独立且妥善保管的密钥，完成初始化并验证实际加密状态，规划轮换与访问权限。源代码有加密函数，并不证明每条历史数据、备份或第三方副本均已加密。

### 1.4 凭证与会话

本次核对版本新写入密码采用 PBKDF2-HMAC-SHA256，每位用户随机盐，默认 210,000 次迭代；可配置参数且仍接受历史 SHA-256 或较低参数并于验证时升级。TOTP 密钥使用 AES-256-GCM；恢复码有哈希及可重新验证后显示的加密原码副本，通行密钥存公开凭证数据。哈希不是不可猜解保证，后续仍应按风险及技术现状评估参数。

TOTP 设置流程将加密后的设置密钥写入 D1 的 `auth_security_operation`，有效期为 300 秒；多因素登录的待完成流程也保存在该 D1 表中，其 payload 不含输入密码。完成第二步只更新 payload，不会续期原有截止时间；到期会阻止后续使用，但不等于记录已物理删除，计划清理可能稍后处理。若停用 TOTP 时仍有有效通行密钥，`totpEnabled` 仍保持开启。登录环境清单最多 15 条、180 日滑动 TTL；IP 多账号关联 TTL 为 7,200 秒，可信设备凭证可保存 60 日且前 30 日可免除部分多因素验证。

登录失败限制与会话撤销均有实现；JWT 默认有效期 30 日。会话列表的容量判断有边界差异，不能宣称程序严格保证最多 10 个同时会话。凭证保存于浏览器 localStorage 时，仍须防范共用设备与脚本访问风险。

### 1.5 数据处理矩阵

| 类别 | 保存位置与内容 | 现有清理机制 | 运营者须落实的限制 |
| --- | --- | --- | --- |
| 账号与验证 | D1 账号、个人字段、验证及设置数据；KV 会话 | 注销先停用全部关联信箱，撤销会话、PAT、可信设备、待验证状态及 OAuth 授权，入站在 AI 前拦截 | `manual_review` 不等于全清；失败以 `cleanup_failed` 留存可查状态，静态头像与残留副本另核对 |
| 正常邮件 | D1 主题、正文、元数据及标签 | 用户操作、配额及管理清理 | 正常数据不得无目的无期限保留；备份与历史副本另作处理 |
| 垃圾／回收站 | 邮件数据及相连对象 | 每日分支依 `create_time` 比较 7 日门槛；垃圾转回收站后可于同轮符合删除条件 | 不是移入回收站后固定 7 日缓冲；须确认计划任务成功与失败重试 |
| 系统邮件 | 欢迎／公告内容及过期字段 | 部分官方邮件于读取列表时按过期天数（默认 7 日）标记删除，再由每日分支清理 | 并非独立到时立即清除；实例须告知其实际期限并核对成功 |
| 附件与原始邮件 | 附件使用 S3、R2、KV；完整原始 MIME 以服务器密钥 AES-256-GCM 加密至所属用户选定的对象存储，D1 claim 记录哈希、收件人、Message-ID、用户、原文键及到期时间 | 原始 MIME 应用到期设为 7 日，重试可续期；COMPLETE 不立即删，排程每次最多 100 条，先删对象再删 claim，失败保留重试 | 不属附件删除队列，不是存储 TTL 或 7 日内全清保证；服务器密钥非端到端加密，实例须升级配置，注销时原始 MIME 清理仍须核验 |
| 登录与安全事件 | IP、User-Agent、设备、操作者、事件及必要处置数据 | 账号字段及各日志机制不同；未见通用自动到期 | 订定字段最小化、访问权限与可执行的保存期限 |
| 审计、申诉及裁决 | 审计事件、风险／工单状态、申诉、通知与授权审计数据 | 有条件的手动清除一般旧事件；没有全类别默认 TTL | 见下段的保留条件；逐类设置期限及删除程序 |
| 导出与本地副本 | 用户下载的 JSON、单封 .eml；`localStorage` 的 `epo_sessions` 会话令牌登记表、当前邮件与 `epomail_recipient_records:*` 收件人记录；`sessionStorage` 的标签页身份标记；IndexedDB 草稿及附件 | 普通登出撤销当前会话并清除当前邮件及内存收件人缓存，但不删除 `epomail_recipient_records:*` 或其他账号；草稿与附件保留并在删除草稿时同一事务联删 | 数据设置的设备清除须明确确认，范围包括本站全部本地账号、草稿、附件、收件人记录、可信状态与缓存；阻塞或失败会回报；不等于服务器全量删除 |

本地草稿数据库以主邮箱命名，包含收件人、主题、正文、发件设置及另表保存的附件对象，未见应用层加密。`epo_sessions` 会话令牌登记表、当前邮件及 `epomail_recipient_records:*` 收件人记录使用同源持久存储；各标签页身份标记使用 sessionStorage，多账号的界面路径不等于浏览器存储或设备访问隔离。PWA 有自动注册的 Service Worker，但本次核对未配置邮件的离线缓存，也未见浏览器 Web Push 订阅实现；本地持久化不能据此忽略。

每日清理分支设置于 UTC 16:00（台湾次日 00:00），另有每五分钟的计划任务；有计划任务设置不等于每项清理均每五分钟执行。用户执行删除时，若当时用量已超过配额 90%，所选邮件可直接实体删除，不是仅由后台任务清除既有回收站。

审计清除端点只接受特定范围：超过 180 日、属一般审计、正常风险且状态已结案／过期／驳回，并须排除有效封禁引用。这是技术上的清除条件，并非法定最低保存期；其他事件、申诉、裁决、通知及授权记录没有因此自动到期。运营者须补足合法保存规则及可执行清理，不能把「有清除按钮」描述为所有日志已按期删除。

## 2. 运营与开源责任

### 2.1 托管测试实例

个人维护的测试实例以尽合理努力降低风险为维护原则：结合资料敏感性、处理范围、技术现状与合理实施成本，优先处理可能造成较大损害的缺陷，并明确说明当前措施及限制。必要流程可采用与风险相当的人工核对、记录及清理，不无条件承诺企业级备份、专职值班或特定修复时限。遇到尚不能妥善控制的风险，应减少资料、限制功能或暂停相关处理；已知限制及用户可采取的措施见[隐私政策](/mail/privacy-policy/)第 1 节。法定安全要求、权利请求与通报期限仍依适用法律办理。

### 2.2 源代码作者与部署者

只提供源代码而不决定特定实例处理目的或方式者，不因此承担该实例的运营义务。同一作者若另行运营托管实例，应就该运营负责；实际共同决定或受托处理的角色也须依事实判断，不能以文件先行排除。

### 2.3 规模相当的治理

小型实例可采用一份简明电子台账，记录目的与依据、数据及当事人类别、接收者、地区与传输保障、保存／删除和安全措施；依法须保存处理记录时，应具备法定字段并可向有管辖权的机关提供，不能仅凭不足 250 人免除。权利请求可用私密工单记录接收日、期限、核验、处理范围及完成情况；定期人工复核与清理可以适用，但须确实执行并留下必要记录。

欧盟代表、数据保护官与影响评估须各按法定条件判断，见隐私政策第 12 节；隐私信箱不自动成为这些法定职务。无须仅因开源或非营利测试而成立公司、雇用专职团队、购买保险或取得 ISO 认证，也不能以缺少预算延长法定期限。测试资源即使仅存合成邮件，也应核对真实账号、访问日志及外部请求的处理。

### 2.4 对外开放前的确认

运营者身分与地址、实际第三方与所在地、合法处理依据、日志及备份保存、完整删除与请求跟踪仍须落实。代码在缺少运营者名称、国家、联系邮箱、条款版本及条款／隐私 URL 时关闭新注册，现有登录仍可用；注册的条款选框不预选，接受记录包含版本、时间、语言及 URL，不额外收 IP 作为接受证据。隐私政策是另行告知，不是概括处理同意；字段齐全或勾选不证明主体、契约或合规已核实。未具依据或保障的流须停用，见[隐私政策](/mail/privacy-policy/)第 2、8 节与[第三方处理者清单](/mail/sub-processors/)第 7 节。

## 3. 权利、删除与事故

### 3.1 导出与补充请求

自助 JSON 导出包含部分个人资料、未标记删除的邮件映射与自定义标签，不含所有收件字段、附件二进制内容、原始邮件、全部信箱别名或管理审计数据。单封 .eml 不等于保存的完整原始 MIME，亦不保证等同数据库全部个人资料。机器可读导出不会单独完成所有查阅与可携义务。

未包含但依法可请求的数据，由人工渠道核实并补充；不得以功能没有提供为由拒绝。回复期限、核验、费用与申诉依[隐私政策](/mail/privacy-policy/)第 9 节。

### 3.2 删除程序

升级后的注销先在 D1 停用用户全部关联信箱，再撤销会话、PAT、可信设备、待验证状态与 OAuth 授权；入站在 AI 处理前拒绝。公开端点对停用或删除的用户／信箱返回 404；Telegram 阅读及附件每次检查用户、信箱、邮件的状态及版本。停用或更改个人通知会撤销旧阅读链接，数据设置另可明确撤销全部链接；这不删除聊天消息或已下载副本。删除用户记录前已接入原始 MIME 清理，失败保留定位信息供重试。注销返回 `manual_review` 仍须人工核对原文、claim 及其他残留，不是全量清除；清理失败以 `cleanup_failed` 留存可查状态，不承诺 90 日全清。原静态头像 URL 的文件不会随软删除实体删除。

普通登出仅撤销当前会话并清除当前邮件、收件人缓存及当前账号会话，保留草稿、其他账号及不属于本次撤销的凭证，不是全会话或全阅读链接撤销。共用设备可在数据设置明确确认清除本站全部本地账号、草稿附件、可信状态与缓存；被阻塞或失败会报告，不得忽略结果。设备清除与服务器注销、全量删除须分别核对。

附件自备外部存储的删除保留原后端定位与必要配置，直至其删除队列中的 pending／failed 项处理完成，再安全移除设置。原始 MIME 的独立到期清理见第 1.5 节，不使用附件队列。缺少原配置时标记失败，不转用默认存储桶删除；运营者须核对重试及每个对象的结果，不能把已排队当作已删除。

删除请求应建立可跟踪记录，逐一核对账号、别名、邮件、对象、验证与授权、审计及备份系统；依法须保存者记录依据、隔离用途并告知可提供的理由及期限。未确认完成前不向用户发出「全部彻底删除」的回复。请求处理不得因内部尚未自动化而超过法定期限。

### 3.3 最小化与用户选择

代码的自动提取、翻译、OCR 服务器门槛默认 false；当前不提供公共翻译备援。自动提取还须 `aiCode`、用户 `aiVerificationCode` 明确 true 与告知确认。打开翻译面板或换语言不发送内容，须确认当前告知 URL；OCR 缺省 false，仅本次选择与服务器许可均通过才处理。MyMemory／Google 公共备援已从全部路径移除，后台拒绝启用值 true、界面选项禁用；旧实例须升级，不能只依赖原开关。实际接收实体、契约、保存及跨境保障仍须披露；确认不是 GDPR 全套证明。公开资料后端分别执行统计／趋势／来源选项并对停用、删除用户／信箱回 404，但原静态头像不随软删除清除。升级后的个人 Telegram 强制执行通知范围、预览及验证码复制控制：`all`／`important` 模式即使关闭预览，通知标题仍采用主题（无主题时用通用标题，最多 200 字符）；`notifyCodeOnly` 仅在非 `privacy` 模式且已有不超过 256 字符验证码时添加复制按钮；`includePreview` 明确为 true 才附最多 400 字符摘要及配置可用时的阅读链接；`privacy` 模式仅发通用提示。阅读及附件每次校验状态与版本，含预览关闭情形。转寄规则不可用时停止，不回退全部；保存的 `keepCopy` 规范化为 true，启用转寄时的 false 会被拒绝，停用配置也写入 true，原件保留。具体字段与选择见[通知与转发指南](/mail/notify/)，这些代码机制不代表生产环境验证完成。

### 3.4 事故应变

发现事故后应控制影响、保全必要证据、判断涉及数据与风险并记录决策。GDPR 的监管通报以风险条件为前提，在可行情况下于知悉后 72 小时内办理；高度风险时依法无不当迟延通知当事人。完整规则见[隐私政策](/mail/privacy-policy/)第 10 节，不能一律以公开漏洞公告代替个别通知。

安全问题可私下寄至 `announcement@epocanvas.com`，隐私与权利请求寄至 `privacy@epocanvas.com`；公开修补说明应避免包含可识别用户的事件细节或尚可利用的凭证。
