## 1. 服务内置之安全功能

官方托管实例对资料之保护分为传输、边缘处理、静态存储与凭证四层。各层措施均实现于开源代码，可自行审计核对。

*图：传输、边缘、静态存储与凭证四层防护；底层为用户之自主控制（自助导出、删除与两步验证）。*

### 1.1 传输加密

您经由浏览器或移动应用访问本服务时，全部连接经 HTTPS/TLS 加密传输，通信内容于公共网络中对中间节点保持密文状态。站点静态资源经内容分发网络分发并附带缓存与安全响应标头。

### 1.2 边缘无状态处理

业务逻辑运行于 Cloudflare Workers（V8 Isolate 沙箱）：处理过程中解密之邮件明文仅存于该次请求之内存；请求结束，沙箱随之释放，宿主机物理磁盘不留存明文。本服务无自建持久服务器，亦无常驻后台进程。

### 1.3 静态存储加密

邮件主题与正文之加密视实例采用之邮件模式而定：「加密模式」下全部邮件之主题与正文均以 AES-256-GCM（含认证标签）加密存储；「隐私模式」下除垃圾与回收站邮件外均加密；「全部模式」下不作加密。每条记录使用随机初始化向量；加密密钥自实例级主密钥环境变量（`jwt_secret`／`totp_enc_key`）经 HKDF-SHA256 派生，并按用户加盐，主密钥不写入数据库、不随代码提交。若实例未配置主密钥环境变量，加密将退化为代码内置之缺省密钥，部署者应经初始化门禁完成配置以避免之。附件不在加密范围内。

:::caution[加密之范围与限制]
上述加密为服务器端静态加密（encryption at rest），防范数据库文件失窃、快照外泄等基础设施级风险，并非端对端加密：掌握实例服务器与主密钥之运营者在技术上具备解密能力。管理员之可及范围依邮件模式而定：「全部模式」下管理员得读取全部邮件；「隐私模式」下仅限垃圾、已删除与无主邮件；「加密模式」下管理界面不回传用户邮件内容。需要任何第三方（含运营者）均无法查阅之保密强度者，应自行以 GPG/OpenPGP 等客户端工具于本地加密正文后再行投递。
:::

### 1.4 凭证保护

- **密码**：以 PBKDF2-HMAC-SHA256 执行 100,000 次迭代哈希，每用户使用独立随机盐，不以明文或可逆形式存储；
- **两步验证**：TOTP 密钥以 AES-256-GCM 加密存储；备用恢复码仅存 SHA-256 哈希值；
- **通行密钥（Passkey/WebAuthn）**：服务器仅存储公钥与凭证标识，私钥留存于您设备之认证器，不经网络传输。

### 1.5 数据处理矩阵

本服务所涉数据类别、收集字段、处理目的、存储介质与留存周期如下：

| 资料类别 | 收集字段 | 处理目的 | 存储介质与防护 | 留存周期 |
| --- | --- | --- | --- | --- |
| 帐号凭证 | 电子邮件地址、用户名、密码哈希与随机盐、TOTP 密钥（加密存储）、备用码哈希、通行密钥公钥 | 注册、登录验证、两步验证 | Cloudflare D1；PBKDF2（100,000 次迭代）、TOTP 静态加密 | 帐号存续期间；注销后会话即时失效，实体删除后不可复原 |
| 通信资料 | 发件人与收件人、抄送/密送、主题、时间戳、已读状态、标签、邮件正文 | 邮件收发、会话组织、关键词检索 | Cloudflare D1（元数据）；主题与正文按邮件模式加密 | 由您控制；回收站保留 7 日后实体删除 |
| 网络与设备资料 | 注册 IP、最近登录 IP、操作系统、浏览器与设备类型 | 安全审计、异常登录识别 | Cloudflare D1；仅管理员审计可查询，不用于商业画像 | 至帐号实体删除为止 |
| 边缘环境信息 | 请求时之边缘国家/地区码（`cf-ipcountry`） | 界面预选（如电话区号默认值） | 不入库；仅随响应回传至浏览器 | 不保存，随响应结束销毁 |
| 会话与授权 | JWT 会话令牌、角色权限 | 边缘 API 鉴权 | Cloudflare KV 允许清单；同帐号上限 10 个活跃会话 | 有效期 30 日；登出即时移除失效 |
| 附件资产 | 原始文件名、MIME 类型、文件体积、二进制内容 | 附件传输、预览与下载 | 实例自有对象存储（依序解析：自备 S3 兼容存储、R2 绑定，缺省 KV）；下载附带防御性标头 | 随所属邮件删除级联移除 |

## 2. 双轨运营之责任边界

EpoCanvas Mail 兼具官方托管服务与开源专案双重属性。数据控制者之界定与三方责任划分详见[隐私权与条款总览](/mail/overview/)第 2 节，本节就托管实例定位与开源分发规则作补充。

*图：同一开源代码库之两条运营轨道。托管实例由运营团队担任数据控制者；自建实例之部署者为唯一数据控制者；上游作者不运营服务、不掌握资料。*

### 2.1 官方托管实例之定位

托管实例 mail.epocanvas.com 由运营团队以非商业方式运营：不植入广告，不出售或出租用户资料，不承诺企业级服务水平协议（SLA）。服务可用性依赖 Cloudflare 及投递通道等上游服务；重要通信请您自行定期导出备份（见第 3 节）。

### 2.2 行为边界

使用托管实例应遵守[可接受使用政策](/mail/acceptable-use/)之全部规定，包括禁止滥发垃圾邮件、钓鱼与恶意软件散布、批量注册与资源滥用。违反者，运营者得依该政策所定之执行阶梯处置，直至实体删除。

### 2.3 开源代码之分发与二次开发

源代码依 MIT 授权条款公开，任何个人或组织均得查阅、审计、修改与自建部署。分发或二次开发时应遵守：

1. 完整保留原作者版权声明与 MIT 许可证全文；
2. 不得于域名、界面或宣传材料中暗示该实例由官方团队运营或经官方认证；
3. 面向公众提供邮件注册服务者，应自行公示运营主体、服务条款与隐私政策。本站文档得作为其告知范本，但不构成官方背书。

### 2.4 自建实例之独立责任

第三方以开源代码自建实例者，自部署时点起即为该实例用户唯一且排他之数据控制者，应依其所在地适用法律自行履行告知、安全维护与受监督等义务。上游开源作者与贡献者不运营任何实例，不接触自建实例之资料，亦不对任何实例之运营行为、安全事故或法律争议承担连带责任。

## 3. 您对资料之控制

您对自身资料享有查询、复制、更正、停止处理与删除之权利。本章说明各项权利经何种功能落实；权利内容之完整定义见[隐私政策](/mail/privacy-policy/)第 9 节。

</div>

*图：资料控制之三种途径：自助导出（JSON）、删除（回收站缓冲后实体删除）与权利行使（30 日内答复）。*

### 3.1 查询、导出与更正

- **界面自助**：您得随时于信箱界面查阅个人资料、登录记录与全部邮件；
- **数据导出**：「设置 → 数据导出」生成 JSON 格式之完整副本（含个人资料与未删除邮件全文）；单封邮件亦得下载为 .eml 文件；
- **人工请求**：更正、停止处理等需人工处理之请求，运营者于受理后 30 日内答复并处理，联络窗口为 `privacy@epocanvas.com`。

### 3.2 删除

- **邮件删除**：删除之邮件先入回收站，7 日后由系统定时任务实体删除（含附件与索引），不可复原；信箱用量逾配额 90% 时，您执行之删除径行实体删除以释放空间；
- **帐号注销**：您得于设置中自助注销。注销后会话即时失效，邮件与资料进入软删除状态；除法令要求留存外，管理员于注销后 90 日内执行实体删除。实体删除后，帐号资料、邮件、附件与授权记录自数据库与对象存储移除，不可复原；
- **法定权利之对应**：欧洲经济区用户依《通用数据保护条例》享有之查阅、复制、删除等权利，及美国加州居民依 CCPA/CPRA 享有之知情、删除与不歧视权利，均经前述自助功能与人工请求管道落实；位于其他法域者，依其所在地适用法律行使同类权利。

### 3.3 出售与追踪之排除

- 运营者不出售、不出租、不交易您的个人资料与通讯内容；
- 资料不为跨上下文行为广告、用户画像或商业模型训练之目的而利用；
- 您行使隐私权利，不致服务功能、质量或可用性受到差别对待。

### 3.4 安全事件应变

若发生个人资料被窃取、泄漏、窜改或灭失之安全事故，运营者将依下列程序处理：

1. **即时处置**：强制下线相关会话、隔离涉事内容，必要时暂停部分服务以阻止损害扩大；
2. **法定通报**：于知悉事故后 72 小时内向主管机关通报（适用法律定有不同时限者，从其规定并尽速为之），并以站内公告或系统邮件通知受影响之当事人；
3. **修复公示**：查明原因后于开源代码库发布修复与安全公告，供自建运营者同步修补。

发现安全隐患或漏洞者，请通过下列窗口联络：

- **安全与官方通讯**：`announcement@epocanvas.com`
- **隐私与数据保护**：`privacy@epocanvas.com`
