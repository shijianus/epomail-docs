# 数据处理与安全维护

**生效日期：2026 年 9 月 29 日｜版本：4.1**

本文档依[隐私政策](/mail/privacy-policy/)第 10 节，说明本服务个人资料之生命周期、各类资料之处理矩阵，以及运营者依《个人资料保护法》第 20-1 条（非公务机关应办理安全维护事项，防止个人资料被窃取、窜改、毁损、灭失或泄漏）及《个人资料保护法施行细则》第 12 条所建立之安全维护措施。本文档同时作为接受主管机关依《个人资料保护法》第 22 条实施检查及当事人查阅之基础文档。

| --- | --- | --- | --- | --- |
| 帐号凭证 | 电子邮件地址、用户名、密码哈希值与盐、TOTP 密钥（AES-GCM 加密）、备用码哈希值、Passkey 公钥 | 注册、验证、两步验证、凭证恢复 | Cloudflare D1；密码 PBKDF2（100,000 次迭代加盐）、TOTP 静态加密 | 保存至帐号终止；实体删除时即刻清除 |
| 网络与设备资料 | 注册 IP、最近登录 IP、操作系统、浏览器 User-Agent、设备类型 | 安全审计、异常登录识别、限流 | Cloudflare D1；限管理员审计访问 | 保存至帐号实体删除 |
| 会话状态 | JWT 令牌、RBAC 角色识别、选定信箱 | 边缘网关授权、请求路由 | Cloudflare KV；最长有效期 30 日 | 登出即撤销；30 日未活动自然过期 |

| 附件 | 原始文件名、MIME 类型、文件大小、二进制内容 | 附件传输、内嵌显示、安全下载 | Cloudflare R2／S3 兼容存储；下载采防御性标头 | 随所属邮件之生命周期；实体删除时一并清除 |

## 3. 安全维护措施（对应施行细则第 12 条）

《个人资料保护法施行细则》第 12 条列举「适当安全维护措施」得包括之事项。运营者依该条建立下列措施，全部十一项均已涵盖：

| 施行细则第 12 条事项 | 本服务之落实 |
| --- | --- |
| 一、配置管理人员及相当资源 | 实例运营者指定管理员，依 RBAC 多级角色划分权限 |
| 二、界定个人资料之范围 | 本文档第 2 节之处理矩阵，明确界定各类资料 |
| 三、个人资料之风险评估及管理机制 | 三种邮件模式之加密选择、失败锁定、限流与配额机制；开源代码公开受社群检视 |
| 四、事故之预防、通报及应变机制 | 见本文档第 4 节 |
| 五、收集、处理及利用之内部管理程序 | [隐私政策](/mail/privacy-policy/)第 5 节之处理活动对应表 |
| 六、资料安全管理及人员管理 | 密码学哈希路由（防越权访问）、默认拒绝（fail-closed）之权限检查、非白名单参数于网关剥离 |
| 七、认知倡导及教育训练 | 自行部署运营者应自行办理；本站文档可作为训练素材 |
| 八、设备安全管理 | Cloudflare 边缘设施承担实体与虚拟设备安全（SOC 2 Type II、ISO/IEC 27001）；密钥以环境变量注入，不入代码库 |
| 九、资料安全稽核机制 | 安全日志（登录 IP、设备、失败记录）留存并限审计访问；会话得即时撤销 |
| 十、使用记录、轨迹资料及证据保存 | 登录与安全日志保存至帐号实体删除；滥用事件之证据依[可接受使用政策](/mail/acceptable-use/)保存 |
| 十一、安全维护之整体持续改善 | 开源项目持续演进；重大安全修复随版本发布并公告 |

技术措施要点：全站 HTTPS/TLS；HTML 邮件经 DOMPurify 于隔离之 Shadow DOM 净化后呈现（阻断脚本、内嵌事件与外部导入）；附件下载强制 `Content-Disposition: attachment` 与 `X-Content-Type-Options: nosniff`；对 Webhook 与外部存储端点实施 SSRF 防护（阻断私有网段与云端 metadata 地址）；邮件 ID 以 HMAC 混淆路由，防止越权枚举。

:::caution[加密之范围与限制]
本服务「全部／隐私／加密」三种邮件模式之加密，系服务器端静态加密：密钥由实例服务器之环境变量与用户识别衍生。此机制防护数据库文件遭窃取或快照泄漏之风险，并非端对端加密；掌握服务器与密钥之运营者在技术上具备解密能力。需要运营者亦无法读取之保密强度者，应自行以 GPG 等端对端加密工具先加密邮件正文再行发送。
:::

## 4. 事件应变与通知

运营者知悉个人资料被窃取、窜改、毁损、灭失或泄漏时，采取下列措施：

1. 即时阻断侵害来源（撤销会话、封锁来源、轮替密钥）；
2. 评估影响范围并留存记录（《施行细则》第 12 条第十款之轨迹资料与证据保存）；
3. 依《个人资料保护法》第 20-1 条第二项授权订定之安全维护办法及主管机关之规定，通知受影响之当事人并向主管机关通报；通知内容包括侵害事实、可能之危害、已采取之应变措施及当事人得采取之自保措施；
4. 就事件原因检讨并补强对应之安全措施（《施行细则》第 12 条第十一款之持续改善）。

## 5. 受检之配合

依《个人资料保护法》第 1-1 条，本法之主管机关为个人资料保护委员会。依同法第 22 条，主管机关认非公务机关有违反本法之虞，或为检视其落实本法情形而认有必要时，得通知陈述意见、要求提供必要之文书、资料、物品，或自行或会同中央目的事业主管机关、直辖市及县（市）政府派员携带执行职务证明文件进入检查。本服务运营者接受主管机关之检查与稽核，无正当理由不得规避、妨碍或拒绝；本文档与[隐私政策](/mail/privacy-policy/)即作为受检之基础文档。

依《个人资料保护法》第 25 条，主管机关就违法情事，除裁处罚款外，并得为禁止收集处理利用、命令删除个人资料档案、没入或令销毁违法收集之个人资料、公布违法情形之处分；运营者将依处分内容配合办理。

自行部署之运营者，应就其实例独立履行本节所列全部义务，并自行面对其所在地主管机关之稽核；本文档可作为其建立安全维护计划之范本。
