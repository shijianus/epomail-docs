## 1. 部署拓扑

| 组件 | 实现 |
| --- | --- |
| 运算 | Cloudflare Workers（V8 Isolate 沙箱）处理请求；服务器可在处理时取得明文，源码不能保证请求结束即销毁沙箱或擦除全部明文 |
| 入站 | Cloudflare Email Routing 接收邮件，postal-mime 解析正文、标头与附件 |
| 出站 | 三通道依序解析：Cloudflare Email Workers 绑定、Resend API、Mailjet；站内互发直接写库 |
| 结构化存储 | Cloudflare D1：支持用户库与邮件库分离，也可回落单库；用户库承载帐号、角色与设置，邮件库承载邮件、星标与附件元数据；线上实际绑定须另行核验 |
| 键值存储 | Workers KV：会话令牌、登录风控计数、TOTP 中间态、用户资料与对象存储兜底 |
| 边缘推论 | Workers AI（验证码提取等，默认 llama-3.1-8b-instruct） |
| 定时任务 | 仓库配置为每日 UTC 16:00（台湾时间次日 00:00）清空验证计数、重置发信计数、清理垃圾与未绑定 OAuth 身份、刷新分析缓存；每 5 分钟处理通知与对象删除队列。代码另有 30 分钟分支，但该配置未注册它 |
| 人机验证 | Cloudflare Turnstile（HTTP API 校验，注册与新增信箱） |

## 3. 数据加密体系

- **三模式静态加密**：全部模式不加密邮件字段；隐私模式按垃圾、回收站及无主状态选择加密；加密模式对选定字段加密。字段范围为 `subject/content/text/code`，并非全部资料；见[数据处理与安全维护](/mail/data-security/)；
- **邮件加密**：AES-256-GCM 使用随机 12 字节初始化向量，HKDF-SHA256 按用户派生密钥；来源依序为 `email_enc_key`、`totp_enc_key`、`jwt_secret`，全部缺失则报错，不回落内建默认密钥；
- **凭证保护**：新密码默认以 PBKDF2-HMAC-SHA256 210,000 次迭代及随机盐哈希，迭代数可配置，旧哈希在登录时升级；已启用 TOTP 密钥以 AES-256-GCM 加密，恢复码同时保存 SHA-256 哈希与加密原码副本，通行密钥保存公钥及凭证资料。临时认证资料与其他凭据的保存例外见[数据处理与安全维护](/mail/data-security/)；
- **边界**：以上为服务器端静态加密，非端对端加密；附件不在加密范围内。

## 4. 附件存储链

附件二进制依序解析存储：用户自备 S3 → 运营者配置的 S3 → Cloudflare R2 → 缺省 KV。元数据存于 D1；下载使用签名链接与防御性标头。物理删除邮件时先清除附件索引并登记对象删除队列，再检查剩余引用；失败重试达到 10 次后停止，不能保证全部对象同步删除。外部副本见[第三方处理者清单](/mail/sub-processors/)。

## 5. 会话与角色权限

JWT（HS256）默认有效期为 30 天；KV 保存会话允许列表及去除部分敏感字段的用户快照。代码在加入新会话前判断数量大于 10，通常可保留 11 个，并非严格 10 个上限；KV 期限可因活动续写或部分操作缩短。登出移除当前会话，注销删除该账户会话记录；权限采用 RBAC，播种六个标准角色：

| 角色 | 每日发信 | 存储配额 | 附件 | 附加能力 |
| --- | --- | --- | --- | --- |
| 参观者 | 禁止 | 0 | 否 | 只读沙箱 |
| 普通用户 | 5 封 | 5 MB | 否 | 基础收发 |
| 普通用户 LV.0 | 8 封 | 10 MB | 否 | 博客等级联动升级 |
| 普通用户 LV.1 | 10 封 | 25 MB | 是 | 基础收发与附件 |
| 管理员 | 100 封 | 500 MB | 是 | 用户管理、全邮件管理（受邮件模式约束） |
| 站长 | 不限 | 1024 MB | 是 | 全部权限 |

受保护路由核验 JWT、KV 会话及相应角色权限；部分公开端点另有验证流程。注销删除常规会话记录，不等于同步清除全部授权、资料或第三方副本。

## 6. 邮件生命周期

| 环节 | 行为 |
| --- | --- |
| 删除 | 普通删除标记 `is_del=1`；每日任务按 `email.create_time` 超过 7 天清理垃圾桶，不是移入后再保留 7 天；显式彻底删除或配额条件可直接触发物理删除 |
| 垃圾隔离 | `spamRetentionDays` 默认 7 天，按邮件创建时间转入垃圾桶；随后同轮可能满足垃圾桶物理删除条件 |
| 配额清理 | 用户执行删除时，现有容量用量严格超过配额 90%，所选邮件直接物理删除；没有达到 90% 即后台自动清仓的任务 |
| 官方邮件 | 读取邮件列表时，按 `welcomeExpireDays`（默认 7 天）及创建时间将指定官方发件地址的过期邮件标删；后续物理清理另由垃圾桶任务处理 |
| 级联删除 | 普通邮件彻底删除与垃圾桶清理会清理附件索引和星标，并登记对象删除重试；不同管理员批量路径的覆盖范围不完全相同 |
| 帐号注销 | 仅标记用户资料列为已删除并移除会话；信箱、邮件及个人资料不会一并标删，没有注销后 90 天自动物理删除任务，见[隐私政策](/mail/privacy-policy/) |

## 7. 应用安全设计

- **防越权路由**：邮件 URL 一律使用 HMAC-SHA256 签名的 20 位随机 Hash，绑定用户与租户，不暴露自增 ID，杜绝枚举与 BOLA／IDOR；
- **XSS 三重防御**：DOMPurify 白名单消毒、body style 注入过滤、附件输出 MIME 白名单加严格 CSP 与 `nosniff`；
- **SSRF 阻断**：出站请求经公共地址校验，回环、RFC 1918 与云元数据地址一律拒绝；
- **登录防护**：失败计数以输入的登录标识为键，达到 5 次拒绝登录，每次失败写入 12 小时 TTL；不是所有别名共享的原子账户锁。另有 Turnstile 与 TOTP／Passkey 验证；
- **官方邮件完整性**：官方发信身份锁定、不可变快照投递与文档防篡改校验，见[防篡改与官方规范](/mail/tamper-proof/)。

## 8. 可观测与质量保障

- 仓库启用 Cloudflare observability；应用另在 D1／KV 保存身份操作、举报、裁决及登录环境资料。多数审计记录无自动到期任务；平台日志实际保留期须核验，见[隐私政策](/mail/privacy-policy/)；
- 自动化测试、审计与巡检脚本逾百个：Playwright 全真栈浏览器回归、公网端到端断言、全仓静态扫描与六语言 i18n 三件套（详见[专案介绍](/mail/project/)第 7 节）。
