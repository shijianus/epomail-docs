## 目标与默认范围
对文档站七语及产品现行六语 UI 做一次本地化修正和上线前审计。按现有 README 与代码边界，产品 UI 保持简体中文、繁体中文（台湾）、English、Français、Español、Nederlands；Deutsch 继续作为文档站对照语言，不在本轮擅自扩成完整德语 UI。文档语言与 UI 语言采用显式映射，避免语言切换、帮助入口或隐私/条款链接指向不存在的 locale 页面。

“可上线”按验收结论处理，不把本地文档构建通过等同生产可上线；在应用可靠性、最终稳定测试版本或运营者/供应商生产事实仍有阻断时，会如实给出阻断项，不部署、不提交或推送。

## 实施步骤
1. **建立安全基线并确认文件归属**：分别记录文档与应用仓库当前工作树状态；保留所有既存和并发修改，只对确认的本地化目标做窄范围修改。应用仓库仍有并行 outbox/邮件管道变更时，不覆盖或代替其作者处理；把需要先冻结的文件列为测试条件。
2. **修复六语 locale 一致性**：新增或整理一个轻量 locale 注册表，统一规范语言别名、Vue I18n 消息、Element Plus locale、Day.js locale、`Intl` locale tag 和文档目录映射。检查启动时浏览器语言识别、用户设置回读和语言切换；默认映射为 `zh → root`、`zh-Hant → zh-tw`，其余现有语种映射到相应文档 locale。移除分散的重复判断，不改变六语产品范围。
3. **修复可见翻译与日期格式问题**：以英文资源为键结构基线，对 `fr`、`es`、`nl` 和两种中文资源检查缺键、多余键和英语夹杂；修复影响登录/注册、导航、设置、错误和数据/隐私告知的可见字符串，并确保占位符与富文本变量不变。审计相对日期、详情日期、注册/授权/安全时间戳和设置页日期，使用当前 UI locale 与用户时区格式化，保留 API/存储时间格式不变；修复确定的硬编码区域标记及相对时间英文残留。
4. **复核法律文档地区适配**：逐语复核台湾正式版声明、译本地位、地区法律不得排除强制权利的告知和本地数据事实；以官方一手来源核实个资法施行状态，只有核验到可引用的正式公告才更新生效日期或主管机关措辞，否则保留明确的不确定性，不套用技能缓存或旧稿作为法源。七语同步同一技术事实与版本日期。
5. **增加可重复的本地化检查**：添加静态 locale/翻译键完整性门禁和针对映射、别名、文档 URL、日期/区域格式的测试；避免以 Vue I18n 默认回退到简中掩盖缺译。测试还应验证 `zh-TW`、`zh-HK`、`zh-Hant` 等系统语言别名最终选择正确的受支持语言。
6. **最终审计与视觉/流程验收**：在应用源文件连续稳定且无并行测试时，串行运行本地化测试、登录 UI 构建、出站/入站/认证回归与合成数据 fullstack；文档侧运行七语结构、法律引用核对、无警告构建、锚点、内链、镜像及 5.25 清单检查。用本地 GUI 对六种实际 UI 语言抽查登录/注册、语言设置、数据/隐私设置及帮助链接，覆盖桌面和窄屏。测试仅使用隔离资源与合成数据，不读取生产凭证、数据库或真实邮件。
7. **交付判定**：补充本地化审计报告，记录修复范围、语言映射、测试版本与结果、视觉验收范围和未完成条件。只有最终固定版本的所有强制检查通过且出站事务/全量回归/生产运营资料问题关闭，才可标为 release-ready；否则交付已完成的本地化改动并明确“仍不可上线”及具体阻断。此计划不包含生产部署、commit 或 push。
