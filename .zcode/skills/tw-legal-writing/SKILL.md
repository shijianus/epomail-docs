# 台湾法域法律文档写作规范（EpomailDocs）

## 0. 单一事实源（写作前必读）

1. **法条引用白名单**：`doc/legal-reference.md` 是全站唯一法条引用依据。**只允许引用该清单已核验之条号**；清单未收录的法规一律不带条号引用（只可提法规名称）。原始条文缓存于 `tmp_laws/`（已 gitignore），复现命令：
   ```bash
   python scripts/extract-tw-articles.py tmp_laws doc/_law-raw.md
   python scripts/verify-laws.py
   ```
2. **技术事实**（加密语义、保存期限、第三方清单、保留/删除行为）以 epomail 仓库源码为准，禁止臆造。
3. 法规时效锚点：個資法修正案於民國 114 年 11 月 11 日公布，行政院定自**民國 115 年 8 月 10 日（2026-08-10）施行**。现行文本即修正后版本：主管机关为**個人資料保護委員會**（§1-1）；非公务机关安全维护义务为 **§20-1**（旧 §27 已删除，全站严禁再引用）；施行细则 §12 十一项安全维护措施清单是 data-security 文档的框架。

## 1. 台湾法定写作格式

- 条文引用层级：`第 19 條第一項第二款`（繁中）。英文 `Article 19, Paragraph 1, Subparagraph 2`（全拼，全文统一，不得混用 `Art. 19(1)(2)` 缩写）。简中与繁中同构。
- 立法机关用语：蒐集／處理／利用／當事人／主管機關／非公務機關／特定目的／國際傳輸／罰鍰（简中对应：收集／处理／利用／当事人／主管机关／非公务机关／特定目的／国际传输／罚款）。
- 引述法条要点时使用数据库原文关键句，不得改写为口语；转述时保持「要件—效果」结构。
- 繁體中文（臺灣）版为**正式版本**，其余语言为对照版本；每份文档开头须载明此效力条款。

## 2. Google 政策页范式（policies.google.com 对齐）

- **按主题分文档**，不写单一大文件：总览（角色与效力顺序）→ 隐私政策（告知与法源）→ 服务条款（契约）→ 可接受使用政策（行为边界）→ 数据安全 → 第三方清单 → 用语定义。跨文档用链接互相引用，不重复长文。
- 开头一段直接说明「本文件是什么、依什么而写、不同意怎么办」；不加营销语。
- 可枚举事实用表格（法定告知六款、处理矩阵、执行阶梯、第三方清单）。
- 每节保持单一主题；段落短；表格内不写散文。
- 每篇配一张开头示意图：扁平几何风格、承担真实信息结构（不作装饰），图内微标签用英文跨语言复用，语义由各语言图注承载。

## 3. 去 AI 味公文规则（红线）

1. 列表项**不得**一律加粗引导词；仅在同类并列超过 4 项且需要扫读锚点时使用。
2. 每节结尾**不得**追加总结句（「總之／綜上，本節…」一律删除）。
3. 禁用破折号链（「——」每篇至多 2 处）、禁用「不僅…更是…」「值得一提的是」「總而言之」。
4. 句首不得连续段落都以「本服務／營運者」开头；用定义词但变换句式。
5. 数字与事实直接陈述，不加评价性副词（「極大地」「全面地」「強大地」）。
6. 疑似营销语气一律改为要件式陈述：先行为、后法效。
7. 同一信息只在一处详述，他处链接引用，不整段复读。

## 4. 6 语言同步与核验

- 结构 1:1：标题、表格行列、提示框、图片、图注逐一对应；改任一语言必须同步其余五种（zh 简中为默认、zh-tw 为正式版、en/fr/es/nl 对照）。
- 版本号与生效日期全站统一（每篇文档头部 `生效日期｜版本` 行）。
- 提交前核验：
  ```bash
  pnpm build                     # 零报错
  node scripts/validate-anchors.cjs   # 全站锚点 0 断链
  python scripts/verify-laws.py       # 法条引用与核验底稿一致
  ```
- 图片引用一律 `/images/mail/*.svg` 站点绝对路径；SVG 支持浅色 + `prefers-color-scheme` 暗色双主题。
